Bounded A1 hypothesis and proposed one-file delta

Hypothesis: if the desired actor phase differs while PENDING is set, the overlay should preserve the old PRES_ACTOR_PHASE and return before beginning another BACK transaction. The next normal Attract dispatch can recompute the phase and admit it after PENDING clears. This avoids advancing the phase cache before admission. It neither clears PENDING nor waits in a loop, and it does not guarantee a visible repair or replay every intermediate phase.

The only proposed production file is the fresh candidate's src/perimeter_reset_helper.s. Insert direct-page `tst PENDING` and short `bne pao_done` on the phase-change path, before `sta PRES_ACTOR_PHASE` and before `jsr PRES_MAIN_FB_PREPARE`. Use the existing same-helper PENDING admission style. Keep the actor copy and finish/capture path unchanged. No change has been applied yet.

The helper allocation is $06B2-$07FF inclusive (334 bytes; exclusive end $0800). The current image occupies [$06B2,$07FD), 331 bytes; it leaves three bytes at $07FD-$07FF. The proposed TST and BNE cost four bytes. Recover exactly one byte by changing `lbsr presentation_attract_phase` at $0786 to `bsr presentation_attract_phase`. Current bytes are 17 00 5B and target $07E4. After both edits, the callee moves to $07E7 and the BSR return address is $0788, giving projected signed displacement +95 ($5F), within the 6809 BSR range -128..+127. Projected BSR bytes are 8D 5F. The guard at $078C is projected as 0D 91 26 53: direct TST of PENDING=$91, then BNE from $0790 to pao_done at $07E3. The phase store moves to $0790 and the prepare JSR to $0792. Net growth is three bytes; projected helper size is exactly 334/334 and its exclusive end is $0800. The listing and compiled bytes must confirm every address and displacement; these are not yet built facts.

BSR and LBSR are both relative subroutine calls and both push a return address for RTS. A compiled postcheck must decode the actual BSR target and return path, not assume the target stayed at $07E4. The BNE destination must decode to pao_done. The helper has zero spare bytes after the proposed change. Any source drift, different instruction width, changed target, branch out of range, or size other than 334 stops the step. Do not widen the allocation, relocate unrelated code, or edit the full presentation runtime, which is already 1,280/1,280 bytes.
