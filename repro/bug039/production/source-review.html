BUG-039 independent source review — 2026-09-16

Parent review of retained candidate fb3f8bd and subsequent corrections. Source correctness is not runtime visual or timing acceptance.

Lifecycle

New-game init clears entry state and initializes LIVES=3. Only live_begin arms WAIT_STAGE. WAIT_STAGE retains RF_STAGE and suppresses actor closure until that stage image renders; render clears RF_STAGE, and mainloop waits for FB_RENDER_PENDING to clear at IRQ publication before a second dispatch. That dispatch sets LIVES=2 once and starts the south-facing actor at $8994. WALKOUT advances PLAYER_FB by $0140 exactly 12 times on PLAYER_TICK_PENDING, reaching $9894. The state changes to OFFSCREEN before composition at that pointer, so no new row-192 framebuffer access occurs.

OFFSCREEN checks both player-valid ledgers, then renders restoration of the selected owner's old footprint. It does not clear the other owner early. Only after both owners report invalid does init_player seed $89EC and cell (12,22). Movement-only MAZE_ENTRY subtracts $0140 and decrements cell Y every four scheduled steps; 16 steps reach (12,18). The final transition to inactive still returns through the entry-only render/audio branch, so ordinary simulation and input begin on the following tick. Death state is never reused.

Composition and clipping

BACK preparation hydrates validity, old pointer, visible-row extent and save-under pointer from the same owner. Restoration writes exactly that old extent, invalidates working history, and precedes background/lives projection. Entry staging initializes only bounded stage RAM, captures visible destination rows into both clean save-under and the stage, decodes the full sparse sprite into the 128-byte stage, and commits only visible rows. The sparse resolver temporarily borrows PAR5, but all stage data and visible-row count remain always mapped; sparse_decode_done restores page $34 before save-under metadata is accessed.

player_visible_rows derives the row from PLAYER_FB using $8400 as row 160; the remainder is the byte column and is not mistaken for another row. WALKOUT rows 168 through 176 have extent 16; rows 178,180,182,184,186,188,190 have extents 14,12,10,8,6,4,2. Row 192 is hidden. The rightmost marker is HUD tile column 37, row 21, yielding byte column 148 and pointer $8994. Each visible row is eight bytes and ends at column 155, within the 160-byte scanline. At row 190 the second row ends before $9800. Maze entry starts fully visible at row 169, byte column 76, and receives a fresh full-size underlay for each owner.

Full player/death/popup saves record extent 16. Hidden history captures validity and extent zero; the old extent may remain in working scratch but is never published as valid. Both persistent owners independently replay RF_LIVES from current LIVES=2, eliminating the old third marker before new capture. No stale HUD/lower-edge underlay is reused at the maze entrance.

Input, counts, adjacent ownership

Active entry branches before gate completion, pickup, enemy, collision, bonus, perimeter, RNG and stage simulation. Ordinary read_joystick is bypassed, and presentation normal_start now ignores held start while entry is active. Existing credit handling remains unchanged. Reset cold-boots normal initialization; live initialization clears and re-arms, demo initialization clears without arming, and next_stage writes neither LIVES nor entry state. Existing death replacement decrements reserves 2 to 1 to 0, then enters game over on the third death. Existing extra-life increment/display cap is unchanged.

$00A0 is entry state and $00A1 is row extent. RING_BASE is a word at $009E-$009F and PLAYER_BG_PTR starts $00A2. Source-wide equate/reference review found no prior overlap, and the Vbord IRQ writes neither new byte. IRQ preserves foreground registers through the hardware interrupt frame. Foreground row counters alias existing renderer scratch only within the nonreentrant render transaction.

Fitting design and exclusions

Move the unchanged eight 16-byte sprite colour tables into the same always-mapped asset page. This uses the existing 128-byte asset margin without new copying or mapping. PERSISTENT_FB=1 closure already restores every old footprint and calls the entry compositor only for WALKOUT/MAZE_ENTRY; the old delta/strip compositor and its two-row helper are compatibility-only code and can be omitted from that build while retaining their source and fixed $080C ABI. No authored frame, walkout step, clipping rule, life, input rule, audio instruction or loader boundary is removed.

Remaining acceptance gaps: natural cold credit/start visual sequence, held-input/reset observation, natural death/replacement, stage/award checks, live artifact identity and publication timing. No runtime harness was added or repaired for this review.
