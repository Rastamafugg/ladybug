Known evidence and source distinction
R2 captured Options A=6 at byte-qualified presentation PC $1A78 before start_screen updates PRES_SCREEN. At final stop, PRES_MODE/PRES_SCREEN were $05/$06, and the 0300 helper dump exactly matched the 938-byte instruction payload. This proves helper content, not phase owner or call timing. User separately confirmed visible Options/collectible flicker persisted until the window closed; no separate input-unresponsive/freeze confirmation exists.

The immutable presentation map labels OPTIONS=6, HIGH_SCORE=3, MODE_CREDIT=5, PRES_MODE=$00A5, PRES_SCREEN=$00A6, DEMO_RUNTIME_TICK=$0300 and INSTRUCTION_RUNTIME_TICK=$0300. The identical $0300 aliases make the current helper bytes insufficient to identify the invoked role.

Compiled source/listing yields a short discriminating path:
- `presentation_runtime.s:512-520` installs the instruction helper only for the instructions screen or screen 0; Options screen 6 skips that install.
- `presentation_runtime.s:551-567` handles menu input at `load_tick`; `1AD7 BD B0 89` calls MENU_TICK=$B089, a distinct entry from $0300.
- `presentation_runtime.s:623-658` contains the complete-profile `load_done` dispatch. The pinned listing is `1B65 F6 00 A6` (read screen), `1B68 C1 03` (compare HIGH_SCORE=3), `1B6A 25 03` (branch only if screen<3), and `1B6C BD 03 00` (Options screen 6 falls through to JSR $0300). The call's return PC is $1B6F.
- `presentation_runtime.s:707-721` later publishes the screen mode. R2 observed mode 5/screen 6. The compiled dispatcher compares mode 5 at $19F6 and branches to `credit_tick`; map/listing place `credit_tick` at $1CB1 with `1CB1 7E 03 00` (JMP $0300). This is a second possible $0300 route, after load publication. The load_done JSR is the shortest earlier marker; do not chase a later route in the same phase.

Proposed single-phase capture
Start the 45-second clock at the one owned emulator launch. Before interpreting PCs, retain the existing full resident-bank and full $1900..$1DF6 presentation binding against the capsule. With native inputs, stop first at the existing selected-screen entry $1A78 with A=6; after that stop, arm one temporary breakpoint at $0300 and continue naturally. At the first $0300 stop, stop the case before executing the target instruction. Read PC/A/S, stack bytes at S, PRES_MODE/PRES_SCREEN, PAR5, all 938 bytes at $0300, and the full 1271-byte presentation module. The already pinned capsule/ROM source and stage facts identify authored and packaged helper candidates; compare the live helper with instruction, demo, and high-score payloads. The full live module plus the stack return identifies whether the callsite is the $1B6C JSR; do not infer it from a symbol name alone.

Primary discriminating marker: PC=$0300, PRES_MODE=1 (load), PRES_SCREEN=6, stack return PC=$1B6F, and live 0300 bytes equal the instruction payload. That would establish a natural Options load_done call to DEMO_RUNTIME_TICK while the instruction payload occupies the shared entry. It would materially support a wrong-phase-owner hypothesis, but would not alone prove that this call caused the visual flicker. A live helper matching the packaged demo payload is the negative identity outcome for that hypothesis. A target stop with a different caller, state, or unrecognized helper is unexpected: retain raw evidence and stop. The $1CB1 credit_tick JMP is documented as a later alternative, not an added breakpoint or second route in this proposal.

Limits, timeout, and stop rule
One cold process, one Options route, native user input only; entire phase <=45 s including launch/attach/input/read/cleanup, each stop/continue <=10 s, <=12 stop/continue observations, existing 8 s cleanup reserve. Success marker is the first qualified natural $0300 entry and caller identity above, not pixel acceptance or a freeze gate. No target by deadline, an unexpected caller, any byte mismatch, or a tool/cleanup failure means incomplete/unbound evidence; preserve the first raw boundary and stop without retry or another continue. Do not infer absence of dispatch from a missed marker. Stop immediately after the first $0300 snapshot; do not execute the helper or pursue the later credit_tick route.
