Finding
The build was a complete keyboard/adaptive profile; source qualification passed, then source-reference generation stopped with `external call targets lack project-authored/imported labels: keybinding-runtime:PRES_MAIN_JOY_AXIS`. This is a source-versus-assembled-profile classification defect, not evidence of a missing keyboard symbol or runtime product failure. The build stopped before post-build acceptance; runtime probes were zero.

Evidence and mechanism
- `src/keybinding_runtime.s:194,198` has two `jsr PRES_MAIN_JOY_AXIS` calls inside `ifne INPUT_JOYSTICK` (default 0 at lines 25-26); its contract comment at line 18 says keyboard builds have no joystick callback reference.
- `scripts/build.sh:708-756` emits `PRES_MAIN_JOY_AXIS` into `build/ladybug_presentation_symbols.inc` only when `INPUT_JOYSTICK` is true, by mapping main-map `joy_read_axis` to that alias. The failed keyboard artifact's generated include has `PRES_MAIN_SHARED_MASK` but no `PRES_MAIN_JOY_AXIS`. `src/main.s:2772+` similarly guards `joy_read_axis` with `ifne INPUT_JOYSTICK`.
- `source_parser.read_source_tree()` reads source/include text, not assembler conditional execution, so the conditional calls are present in the lexical source for either profile. `normalize.py:283-284` already filters call edges against listing-backed emitted spans in ownership-audit mode; the keyboard listing shows no emitted address for the two calls.
- `normalize.py:286-290` treats `external_symbols` as allowed call targets. At lines 412-420 it then validates every configured external unconditionally against all authored/imported source labels, independent of the listing-backed active call set. `scripts/source_reference.json` has both `PRES_MAIN_SHARED_MASK` and `PRES_MAIN_JOY_AXIS` in the keybinding-runtime `external_symbols` list. This unconditional check causes the reported keyboard failure.
- The generated alias is profile-specific; it exists for joystick builds and is omitted for keyboard builds. A source-only conditional line is not an assembled call. `wiki/internal/implementation/source-guide.html` defines source-only relative to a particular assembled module and says a complete-build receipt records the actual profile/assembler arguments; this supports the listing-backed distinction.

Smallest semantically sound proposal
Add one explicit `conditional_external_symbols` entry for `PRES_MAIN_JOY_AXIS` under `keybinding-runtime`, leaving `PRES_MAIN_SHARED_MASK` in the existing unconditional `external_symbols` list. Keep the conditional target in the module's recognized external-target set for classifying source call edges. In `normalize.py`, require each conditional target to occur in that module's unfiltered authored call set (reject stale/unused exemption declarations), then apply the existing authored/imported-label check whenever a filtered, listing-active call references it. If active, a missing generated/imported alias must fail with the existing unknown-target error. If inactive, no label is required. When there is no receipt/listing-backed active-span evidence, fail closed by treating the source call as active (or reject conditional metadata in that mode); do not infer inactivity from absent/stale build artifacts. Preserve all unconditional external checks unchanged.

This uses the existing source parse plus current listing spans, rather than inventing a second parser for assembler `ifne` expressions. It distinguishes source-level presence from assembled-profile activity without weakening the unknown-target guard for any emitted call. It does not claim that any gameplay or runtime acceptance has passed.

Alternatives rejected
- Remove `PRES_MAIN_JOY_AXIS` from external metadata: a joystick build's active callback would cease to be classified as an imported call target and would be treated as an internal required label/routine. This loses the intended interface declaration.
- Add an unconditional source alias or fabricated label: this would claim the keyboard profile imports an alias that its generated include does not emit.
- Ignore every configured external absent from source labels, or validate only externals that happen to be called without explicit conditional metadata: both broaden the exemption and weaken detection of stale or misspelled unconditional imports.
- Implement general assembler-conditional evaluation: materially broader parser semantics than this one profile-specific external requires.
