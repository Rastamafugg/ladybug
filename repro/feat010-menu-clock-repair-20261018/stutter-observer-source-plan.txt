Source-qualified trace markers
- Trace CPU rows are postinstruction state (`pc| bytes mnemonic operand cc=... a=... b=... dp=... x=... y=... u=... s=... dt=...`). Native vector rows use `pc|` plus fixed-width bytes/name and `dt`, without CPU registers (`mc6809_trace.c` vector formatter around line 977). `dt` is updated on vector and CPU trace events, so parse both and discard the first event delta, regardless of row type. It is guest event time, not wall time. Any unparsed timing-looking line invalidates the timeline.
- Receipt listing `ladybug-perimeter-reset-helper.lst`: `$07E7 DCB0 LDD PRES_TIMER` is the timer consumed by phase calculation; `$07F3 8403 ANDA #3` leaves the computed logical phase in post-A; `$0790 97D3 STA PRES_ACTOR_PHASE` writes phase only on a change. The helper normalizes `t` by 6; expected phase is `((t-6)>>3)&3`, subphase `(t-6)&7`. Keep logical phase 1 and 3 separate although their mapped glyph is identical. The `$07F3` observation is the computed phase target, not the persisted actor phase or displayed pixels; missing `$0790` stores cannot by themselves establish a skip.
- Receipt listing `ladybug-presentation-runtime.lst`: `$1C50 DCB0` reads the preincrement timer and `$1C55 DDB0` stores its increment. `$1C50` is not the phase-consumed sample; use `$07E7` for phase correlation.
- Receipt-bound logo-clock listing for `candidate/src/shared_text_stage.inc`: `$ACBD DE02 LDU FRAMES` exposes the post-U independent frame counter value. Receipt listing `ladybug-enemy-runtime.lst`: `$0EAD B7FF9D STA GIME_VOFF1` marks entry to the IRQ publish path; `$0EB0 968F LDA FB_FRONT_ID` and `$0EB2 D690 LDB FB_BACK_ID` expose the actual loaded IDs in post-A/post-B. Validate their execution order and count only a relative publication ordinal at `$0EAD`. `INC FB_COMMIT_SEQ` post-registers do not reveal the memory result. `FB_MISSED_COMMIT` can increase while no ready back image exists and is not alone a failure.

Identity and coverage blockers
- A receipt/listing opcode match proves authored bytes only. A runtime interpretation requires an independently reviewed authored -> staged -> live mapped-address byte comparison plus CPU mapping/bank identity. The exact acquisition procedure is unresolved; the parser's `runtime_bytes_and_mapping_proved` input is a required externally reviewed assertion, not something this preparation implements. Do not interpret symbols or classify product behavior until that blocker is resolved.
- The ROM receipt does not by itself prove copied helper bytes at `$07xx` are mapped at the observed time. Do not infer mapping from PC alone. No monitor reactivation, private monitor extension, or simultaneous `-monitor` and `-gdb` process is authorized.
- This parser observes independent timer, phase, FRAMES, guest event-delta, and relative IRQ-publication timelines. The `FRAMES` read and FRONT/BACK reads are actual trace register values; the publication ordinal is path execution only. It does not observe committed pixel contents, frontend presentation, or host display pacing. Missing raw timer/phase samples are missing coverage, not phase skips. A phase anomaly requires the traced phase result to disagree with the timer oracle. Replay diagnosis remains unsupported without independently captured displayed pixels; host FPS is unsupported.
- `PRES_ACTOR_PHASE` phase 3 and phase 1 are logically distinct but render the same glyph. A trace-only conclusion cannot label their identical pixels stale or fresh. No pixel capture API/source proof is asserted here.
