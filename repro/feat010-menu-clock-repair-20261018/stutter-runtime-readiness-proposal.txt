FEAT-010 runtime identity and trace readiness — proposal only

Disposition
Runtime diagnosis is not Ready. Proposed order: one no-input, same-process GDB identity preflight (<=60 seconds), followed by one bounded native trace in that same XRoar process (<=60 seconds). No runtime action is authorized here. The existing observer and its offline qualification remain unchanged; PASS means parser fixtures only.

Phase 1: same-process identity preflight, <=60 seconds total
Use the existing GDB-MCP XRoar round trip with the receipt ROM, CPU 6809/adaptive profile, and `-gdb -gdb-ip 127.0.0.1 -gdb-port 65520`; do not enable `-monitor`. XRoar's GDB accept sends SIGINT on connection, but launch-to-connect can miss early boot. On the one connection issue `target remote 127.0.0.1:65520`; record the connection SIGINT PC and DP, then query only `p/x $pc`, `p/x $dp`, `p/x $x`, `p/x $y`, `p/x $u` (do not use `info registers`, which the project GDB rejects). Arm temporary `tbreak *0xC002`; it must stop exactly at the bootstrap checkpoint and its bytes must match the receipt ROM. Record DP at C002 without an oracle because bootentry inherits it. A late/missed PC, unsupported breakpoint, or timeout is SETUP_REJECTED. This is a runtime stop/read after launch, not a prelaunch identity claim.

Use listing relocation: authored loader_start $C056 is copied to $0300; copy_enemy_runtime $C0A6 runs at $0350; descriptor setup $C12A at $03D4; hot copy loop $C139 at $03E3; copy_sparse_done $C180 at $042A. Require DP=$02 at loader checkpoints $0350,$0375,$03D4,$042A; require DP=$00 only at B080/runtime. Record, but do not judge, DP at C002. Do not break in the hot $03E3 loop. The planned sequence is:
1. At $0350 before enemy copy, require X=$C800,Y=$0800 and bank 3 selected by the executed loader path. Read source $C800-$D800 (4096 bytes), plus AUX bank-3 spans $F495-$FE00, $C000-$C010, and $C012-$C800. At $0375 after the loop compare $0800-$1800 to expected enemy bytes.
2. Arm temporary `tbreak *0x03D4 if $u==0xC802 && $y==0x06B2 && $x==0x014E`; require the helper descriptor and bank 0. This is once per segment, before the $03E3 inner loop; allow one unrelated descriptor candidate as a bounded ignored stop. Delete the temporary bootstrap breakpoint after C002 and the helper breakpoint after its match. Read source $C802-$C950 plus bank-0 spans $C950-$CC12 and $CC92-$D191, and the 96-byte descriptor table at $0200. At $042A with Y=$0800 compare $06B2-$0800 to helper bytes. At each mapped-byte observation read `x/8xb 0xFFA0`; compare PAR low six bits, including PAR5 at $FFA5, to the expected page. PAR reads are supported CPU memory reads; do not write them.
3. At the first natural presentation `load_done` call to $B080, code executes `LDA #$23; STA PAR5; JSR $B080` before hydration and MODE_ATTRACT. Stop at this first B080 before any later AC40 entry or the $1C62 trace trigger. Require PRES_MODE=LOAD, PRES_SCREEN=ATTRACT, timer 0, PAR5=$23. Compare live page-23 code $AC40-$B84D, staged AUX bytes $A422-$B84D, and low destinations $06B2-$0800 (phase helper), $0800-$1800 (IRQ/enemy module), and $1900-$1DFF (presentation module) against receipt-derived expected bytes. The page-23 table is four raw segments: bank 3 $F495->$A422/$096B; bank 3 $C000->$AD8D/$0010; bank 3 $C012->$AD9D/$07EE; bank 0 $C950->$B58B/$02C2. The final AUX copy precedes the final presentation copy. Source spans are read at the selected-bank checkpoints; B080 checks all final destinations before interpretation. Record PARs and confirm the copied bytes include phase helper $07E7, presentation tick $1C58, IRQ publish $0EAD, and logo FRAMES code $ACBD. Trace opcode bytes at executed marker PCs must also match the proved live spans.

Maximum phase-1 stops are eight: initial connection SIGINT, the six named checkpoint returns (C002, enemy pre/post, helper pre/post, first B080), and one ignored descriptor-condition stop. Cap at 32 live read requests and 32768 total bytes, including code, PAR, and descriptor reads. Budget 52 seconds for observation and 8 seconds for cleanup within the 60-second phase. These are projected bounds, not measured qualification. If GDB-MCP cannot apply the descriptor guard, any required point is missed, or a cap/deadline is reached, report SETUP_REJECTED and stop without retry or expansion. Bank identity uses the selected descriptor, executed bank-select path, and matching source bytes; PAR mapping is read back from $FFA0-$FFA7. No MMU/GIME/guest writes or monitor reactivation are allowed.

Phase 2: bounded native trace, <=60 seconds total, only after phase 1 passes
Keep the same PID and natural guest history. At B080 remove all GDB breakpoints, require that no trace has started, then issue GDB `detach`; source gdb.c closes the connection and resumes the guest. Configure existing XRoar options before launch as `-trace-timing -trap pc=0x1C62 -trap-timeout 2 -trap-trace-n 32768`. The one-entry candidate is the first cold attract clear of HOLD_FINAL at $1C62 (opcode $0FD4), reached from the $1C58 check when HOLD_FINAL=$81 and PENDING=0; clearing it makes subsequent no-input ticks bypass this PC. Source proof of a unique entry through the two-second guest-time horizon is a readiness prerequisite, not an observed result. Do not claim `-trap-range 1` or `1-1` alone prevents rearming. Reject a second activation, trace output before detach, early timeout, or cap before complete coverage. No XRoar fix is proposed.

The frozen observer requires at least 33 timer samples starting at t>=6, but startup hydration calls the phase helper at t=0 before the first attract tick. A pure bounded preamble-window adapter is therefore required: discard only the prefix before t>=6, preserve/sum every dt including vector rows, and retain paired raw records. Its fixture/card plus the one-entry/two-second horizon must be approved and qualified separately; no adapter or qualification is implemented here. Budget 52 seconds for tracing and 8 seconds for cleanup/retention. The trace cap remains 32768 CPU instructions; it is a projection, not a statically proven full-cycle fit.

Success requires at least 33 consecutive $07E7 timer observations spanning 32 advances from t>=6, ordered $07F3 phase results, bracketing $ACBD FRAMES reads, and $0EAD->$0EB0->$0EB2 publication records. Cap/deadline before complete coverage is INCOMPLETE_COVERAGE, never pass and never proof that guest code is slow. Discard the first trace-event dt; subsequent CPU and vector dt values measure guest event time. Trace flushes per instruction, so trace wall duration/FPS cannot establish frontend pacing.

Oracle and limits
- A computed phase disagreeing with the timer oracle is PHASE_ANOMALY; omitted timers are missing coverage. Keep phases 1 and 3 distinct despite identical glyph pixels. FRAMES and relative IRQ publication ordinals are independent guest counters; FRONT/BACK are actual loaded register values, not inferred from INC. FB_MISSED_COMMIT can increase on idle no-ready-back work.
- The probe can classify guest timer/phase/event-time/publication behavior only if required coverage completes. It has no committed/presented pixel channel, so stale-frame replay versus a valid phase-1/phase-3 alias and frontend pacing remain UNSUPPORTED. No screen-capture method is claimed.
- Maximum history is one no-input pass. A natural menu-event pass is a later separately reviewed stage, only if no-input completes. Preserve RNG/input; do not force guest state. Stop after two rejected probes, two tool timeouts, or material scope expansion. No production, wiki, XRoar, or observer implementation is included.
