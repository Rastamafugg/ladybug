Source proof
------------
In the current read_joystick:rj_request, after the INITIAL_ENTRY_STATE
barrier, the approved sequence is LDB PLAYER_MANUAL; ORB PLAYER_DIR;
BEQ rj_done. LDB/ORB/BEQ leave A unchanged and use B/CC as scratch. The OR
result is zero only for manual=0 and active direction North=0, so the automatic
North request is suppressed. Once pt_at_center stops the automatic entrant at
(12,18), PLAYER_DIR and PLAYER_WANT become DIR_NONE; the next actual read passes
the guard. A North request with manual=0 and DIR_NONE is admitted and sets the
manual latch. An already-manual North request is also admitted.

The PLAYER_MANUAL writer audit found init_player clearing the latch, physical
rj_request setting it only after an admitted direction, and autonomous demo
route code setting it at its handoff cell. Demo route code owns that path and
does not add another physical read_joystick path. Name preparation sets
PLAYER_DIR/PLAYER_WANT to DIR_NONE and name_tick calls PRES_MAIN_READ_JOY;
scripts/build.sh maps that symbol to read_joystick. Name preparation does not
write PLAYER_MANUAL. The manual0/DIR_NONE admission case is covered by the
compiled truth case; any natural predecessor state remains a runtime fact.

The existing movement model verified the fixed North edges (12,22)->(12,21),
(12,21)->(12,20), (12,20)->(12,19), (12,19)->(12,18), then default Up
(12,18)->(12,17), plus held Down (12,18)->(12,19). Every target gate_owner is
zero and the gate-state array remained unchanged. No path search was performed.
Entity collision safety is dynamic and remains a runtime preflight requirement.
Adaptive input samples before its batch (adaptive_active.s:22-30). The
nonadaptive main path runs player_tick (~main.s:814), then reaches
main_render/render_frame/read_joystick (~main.s:854-860), after the current
tick/render and before the next scheduled tick. In either order, the first real
sample that observes PLAYER_DIR=DIR_NONE admits input.

Variant 0 encodes the guard as D6 18 DA 06 27 0A at offset 4, branching to
rj_done at $C014. Its downstream stores match every control. Variant 1 omits
the guard. Variant 2 uses a manual-only condition that rejects manual0 name
input. Variant 3 reverses the branch and rejects already-manual North while
admitting automatic North. Full binary bytes and hashes are retained in
qualification.json; .bin and .lst outputs are in guard-qualification/.

The fixture verifies assembler encoding and static truth cases only. It is not
a 6809 interpreter or CPU execution harness. It does not establish that the
candidate build places the guard at the qualified runtime address.
