BUG-117 stage-entry control repair — read-only design review
2026-10-15

Verdict: recommend a six-byte `rj_request` guard that returns when `PLAYER_MANUAL | PLAYER_DIR` is zero. Keep the existing `INITIAL_ENTRY_STATE` guard first, preserve A, and leave the current direction stores untouched for every other state. This is a High-risk repair because the reproduced failure crosses retained presentation and scheduled gameplay input ownership while the framebuffer position is persistent. The frozen baseline reproduces the defect. Both runs entered at cell (12,22), framebuffer $89EC, step 0. Neutral input produced the authored north step to $88AC/step 1. Held Down left the player at $89EC/step 0 and had already set `PLAYER_MANUAL=1`, `PLAYER_WANT=2`, `JOY_DIR=2`. The source supports the compact gate. `init_player` sets cell (12,22), north direction 0, step 0, manual 0, and $89EC. The automatic player path advances north by $140 per scheduled two-pixel step. At center cell (12,18), `pt_at_center` clears direction and buffered request to $FF. Because resident joystick sampling follows the player call, a read at the arrival pose can still see north in `PLAYER_DIR`; the next center call clears it without another position step, and the following joystick sample admits held input. This gives a bounded one-center-tick release at an unchanged target pose. The approved brief should state that behavior and require no further translation before control resumes. Fixed rendering samples joystick after player_tick; adaptive rendering samples before its bounded simulation batch, so the first input read after the center branch may be the next adaptive work call. The state gate remains closed until that center branch has cleared direction.

The six-byte sequence is source-projected as direct-page `ldb PLAYER_MANUAL` (2), `orb PLAYER_DIR` (2), `beq rj_done` (2). It preserves A and leaves raw axis sampling intact. It suppresses input during the MODE_LEVEL preview because this gate has no mode predicate; the adaptive input owner calls `read_joystick` while presentation remains retained. A ten-byte MODE_NORMAL-specific alternative was rejected because it would admit held input in MODE_LEVEL preview.

The broader 22-byte screen/manual/cell predicate was rejected for capacity. Parent-provided BUG-120 Ready-fit free-resident values are 110/74/42 bytes for keyboard-adaptive, joystick-adaptive, and keyboard-nonadaptive profiles. The six-byte projection leaves 104/68/36, so the narrow profile retains 36 bytes, four above the 32-byte minimum. This remains a projection, not an assembler result; every shipped profile needs a map check after repair approval. The 22-byte predicate would leave only 20 bytes in the narrow profile and miss minimum reserve by 12.

The guard does not trap other input paths under current source ownership. A manual directional request sets `PLAYER_MANUAL=1`; the only normal clear is `init_player`, which re-establishes the automatic north state. Name-entry setup sets `PLAYER_DIR=DIR_NONE` before its joystick read, so the first directional request passes and latches manual ownership; subsequent north requests pass. Demo mode owns its separate route and main skips resident joystick reads; its route sets manual ownership at alignment. Menu events use `PRES_EVENT`/`MENU_SCAN`, separate from the resident directional publication guarded here. The existing life-entry marker/audio barrier remains ahead of the new test and is unchanged.
