Each stage is wrapped in a uniquely named native GDB user-defined command. Start and completion printf markers are inside that command body; command errors are intended to abort before completion. Returning to a GDB prompt never establishes success. Missing, duplicate, reversed or late markers fail. Raw output is fsynced before parsing. Native syntax and framing compatibility on the installed GDB remain unexercised.

PC responses must contain one exact numeric result equal to $C0E3. Breakpoint removal requires the exact C-locale response “No breakpoints or watchpoints.” Unexpected output fails.
