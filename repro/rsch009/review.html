RSCH-009 evidence review

Verdict: partial evidence is usable to stop the runtime diagnosis at the identity gate. It does not prove the claimed runtime identity, boot-loop cause, or either BUG-036 cause. The ticket remains incomplete and blocked pending a revised plan and budget.

Review boundary

This review covers frozen commit d8270e2, the retained files under repro/rsch009/runtime/, the current build map/layout artifacts referenced by that evidence, and the authored runtime source. No emulator session, build, source, production, tooling, or shared-wiki changes were made. Only this report is owned by the reviewer.

Identity and address findings

The report states name_joy_ready=0379 and then assumes a low-RAM destination of $0B79 by adding $0800. The current map identifies name_joy_ready as absolute assembled address $0379 in ladybug-highscore-runtime.bin. The authored source places this runtime in an org $0300 region. The build script and retained sparse layout identify the high-score runtime stage as $A880 and its delivered destination as $0300. Therefore $0B79 is not established by the map or loader layout; the +$0800 transformation is rejected. Parent correction: $0379 already includes ORG $0300. Its binary-file offset is $0079, so copying the binary to $0300 preserves runtime address $0379. The original reviewer proposal $0679 also double-counted the origin and is rejected. Live equality remains required.

The attempted read at $0B79 occurred before helper publication and is correctly excluded as identity evidence. However, authored/build/staged/live equality was not proven at the actual destination either. No live-byte comparison at the breakpoint address, no destination copy comparison, and no loader mapping proof are retained. The identity gate therefore correctly fails, but the report must call the address an unsupported assumption rather than a derived destination.

Final-PC interpretation

The retained final bytes and PC are an observation only: PC=$C0E4 and bytes beginning tst <$91; bne $c0e3; lda <$03; cmpa #$00; beq $c0e3. The report labels this a “boot credit/start wait loop.” That semantic claim is unproven. The runtime diagnosis invariant requires current authored, staged, and live bytes to match before interpreting a live PC; the report explicitly records that this was not done, and the backtrace is unsymbolized. A symbolic current-source label or mnemonic pattern cannot identify the live routine without that byte identity.

Source review also does not support the stronger statement that the main loop generally waits on FB_PENDING. The resident main loop gates on FB_RENDER_PENDING; FB_PENDING is read by name-entry/timer code for framebuffer publication sequencing. Even if $C0E3 later matches a current mainloop address, the observed branch must not be called a credit wait without a proven live artifact and a source-level control-flow match. The safe finding is: execution did not reach the proposed breakpoint within the timed observation, and the last captured instruction sequence is compatible with an unclassified early boot/control boundary.

Timing and accounting corrections

The report says “experiment count: 0 completed” while an identity experiment was attempted and timed out. Retain both fields explicitly: attempted=1, completed=0, observation-tool timeouts=1. Zero completed experiments does not mean zero experiments were attempted.

The ticket defines the 60-second deadline for the whole phase, including setup and tool waits. The retained report establishes a 60-second GDB wait, then separately acknowledges setup/inspection time, but supplies no total phase elapsed time or clean phase boundary. Compliance with the whole-phase 60-second limit is therefore unproven. Record the measured end-to-end phase duration on any rerun; do not describe the timed GDB interval alone as the phase duration.

Build evidence

The retained build log demonstrates substantial generated-artifact and capacity output, but the operator report does not retain a clean build exit status. “The wrapper returned after its 30-second command wait” and “no build process remained” are not an exit code. Treat the build as artifact-observed and exit-status-unverified. This is sufficient to retain the partial artifacts for review, not sufficient to claim the required clean build command passed.

Acceptance disposition

Identity/first publication: failed, because the live destination and bytes were not proven. Sprite movement, idle/timer publication: unverified. Collision boundary/open corridor/perimeter: unverified. No causal finding is confirmed, no parent replay was performed, and the absence of later probes is appropriate after the failed identity gate. The operator’s stop classification is valid after correcting the unsupported address and final-PC semantics above.

Required correction for a future approved run: derive the runtime address from the current map and documented destination $0300; compare authored binary, staged payload, loader destination, and live bytes before symbol interpretation; report attempted versus completed experiments; capture total phase wall time including setup; and retain the actual build exit status. Further runtime diagnosis remains blocked pending the parent’s revised plan and budget.
