FEAT-010 bounded recovery proposal
Date: 2026-10-15
Status: read-only proposal; no source edit, assembly, build, runtime, Git, or cleanup performed.

Decision basis
Attempt 06 measured a 1,303-byte complete/keyboard/adaptive presentation module, ending at $1E17 from $1900 against the $1E00 limit (1,280 bytes): 23 bytes over. The measured module is build/ladybug-presentation-runtime.bin in the retained fit copy. Proposed recovery is exactly 32 explicit direct-page operands in the same complete-profile presentation source block. In that listing each listed operand is extended and each target is $00xx; replacing it with the direct form removes one byte. Projection: 1,303 - 32 = 1,271 bytes, end $1DF7, 9 bytes below the cap. This is projected, not measured; only an assembler/build can confirm the emitted result after rebase.

DP and equivalence proof
The selected complete-profile equates resolve to PRES_SCREEN=$00A6, PRES_CELL=$00AA, PRES_CELL+1=$00AB, PRES_X=$00AC, PRES_Y=$00AD, PRES_DST=$00AE, PRES_TIMER=$00B0, PRES_TIMER+1=$00B1, PRES_RUN=$00BB, PRES_VALUE=$00BC, PRES_ROWS=$00C6, PRES_PHASE=$00CA, and PRES_HOLD_STATE=$00D4. The isolated build uses HIGHSCORE_TEST_PROFILE=0; its alternate test-profile PRES_RUN/PRES_VALUE at $00EA/$00EB are not in this allowlist.

Assembler source sets `setdp $00`. Runtime DP is not globally zero during boot: gmc_bootstrap sets DP=$02, then main entry executes `clra; tfr a,dp` before presentation callers (`jsr $1900`). Parent's source-wide scan found no other active runtime DP writers/restores in the presentation caller closure. The generated include closure from scripts/build_presentation.py (`ladybug_presentation.inc`, `ladybug_presentation_symbols.inc`, `ladybug_presentation_resident.inc`, and `ladybug_presentation_timer_records.inc`) supplies constants, external symbol equates, and data tables; it does not write DP or redefine the selected internal page-$00 state equates. On these callers, `<symbol` therefore encodes the same absolute $00xx byte address using DP=$00. Each change retains the operation and register/condition-code behavior; the LDY extended-to-direct conversion retains its 0x10 opcode prefix. No call, branch, callback, stack operation, owner, state transition, or MMU operation changes. Reassembly must still verify emitted size and branch diagnostics.

Rebase and scope
The fit source is a retained candidate, not current root source. Current integrated source is commit 759b8e6 (`main.s` includes the approved six-byte automatic-entry guard; `shared_text_stage.inc` includes the shared-stage word tail and two one-byte savings). FEAT-010's approved patch also touches `shared_text_stage.inc`; reconcile that hunk against the current revision. Do not count those root changes as presentation-module savings. Apply this allowlist by routine/operand context to current `src/presentation_runtime.s`; do not apply stale line numbers or modify the alternate profile block.

Five short-form branch changes identified in the listing save at most five bytes and do not independently cover the 23-byte miss. No branch shortening or logic/state factoring is included. Parent reports the current-root build is blocked by the authored High Score TMX missing `Coin Positions`; do not weaken or bypass that validator. This audit did not run a build.
