Cause and smallest proposed repair

highscore_logo_tick is an existing routine in src/shared_text_stage.inc. It advances the attract/high-score logo phase, increments PRES_TIMER outside attract, respects the BACK-pending state and owner-local phase cache, then redraws the twelve authored logo tiles through the existing page-$23 callbacks. The highscore-helper module's declared primary source is src/demo_runtime.s. The policy checker accepts a source-contract mirror only in that primary source, so a comment in shared_text_stage.inc would not satisfy the mirror check. src/demo_runtime.s has an existing blank line 64 after the symbol includes and before the PAR5 definitions; replacing that blank line with the mirror preserves all following source line numbers.

Proposed file 1: scripts/source_reference.json. Add one routine contract under highscore-helper.routines, using the already-existing presentation profile, no reasons, and the generated-routines anchor semantic ID routines.html#routine-highscore-helper-highscore-logo-tick. Exact purpose:

Advance the shared logo phase and replay twelve phase-changing tiles when the current BACK owner needs an update.

Also add one presentation-runtime.basic_blocks entry for menu_load_event, with routine:null and purpose "Internal load_tick fallthrough that services a fresh local menu event during complete-profile loading." The label is an internal fallthrough point within load_tick, not a callable routine or public API. Do not create a load_tick routine contract solely to own it and do not classify it as a routine boundary.

Proposed file 2: src/demo_runtime.s. Replace only blank line 64 with this exact primary-source mirror:

No executable source change is proposed. Do not edit src/shared_text_stage.inc, src/presentation_runtime.s, verifier/normalizer code, tests, build scripts, receipts, generated artifacts, or canonical wiki pages.
