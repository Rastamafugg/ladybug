Assembly tips · addressing

Indexed addressing and tables release

Use base registers and explicit strides to traverse data without rebuilding each address.

Choose an addressing form for the data shape

Indexed addressing combines a base register with an offset or an update. Use a fixed displacement when a field is at a known offset, auto-increment when consuming a stream, and a scaled index when selecting a fixed-size table record. LEA instructions update a pointer without loading a value from the destination.

  • ,X+ advances an 8-bit cursor by one after the access.
  • ,X++ advances a 16-bit cursor by two.
  • offset,X addresses a field relative to a record base without losing that base.
  • LEAY table,PCR forms a position-relative pointer to nearby code or immutable data.

The LEAX, LEAY, and LDA pages list indexed forms and their encoding costs.

Walk sequential data with auto-increment

; Y points at a mask row; X points at its framebuffer output.
        lda     ,y+
        sta     HUD_BYTE
        ; expand the mask byte through the selected colour table
        ldd     ,y++
        std     ,x++

A post-increment load or store combines a memory access with pointer movement. It is useful for packed streams and fixed-width data. Keep track of the element width: byte operations advance one byte and word operations advance two. If a value must be reread, retain a second base or use a fixed offset rather than undoing the cursor by guesswork.

Ladybug's shared mask and fast-blit routines use ,Y+ and ,Y++ while consuming generated mask or graphic data. The same code uses LEAY D,Y to reach a glyph whose offset is computed from its compact mask index.

Select fixed-size records

For records with a constant stride, multiply the logical index by the record size, then add the result to the table base. Keep the record length and field offsets beside the table definition so producers and consumers use the same layout. Check the index before forming the address; pointer arithmetic does not enforce table bounds. 

; Ladybug dynamic descriptors use two bytes per entry.
dynamic_dispatch
        clra
        lslb                    ; B becomes the low byte of index * 2
        rola                    ; carry supplies the high byte of D
        leax    dynamic_descriptors,pcr
        leax    d,x
        ldb     1,x             ; read the descriptor type

This is the descriptor-address calculation in src/shared_text_runtime.inc. The caller supplies a valid descriptor index; table extent and index limits are part of that interface.

PC-relative pointers and CoCo 3 mapping

PC-relative addressing is useful for data assembled near its code, such as local tables. It does not make a banked target permanently visible. On the CoCo 3, a pointer into a mapped page is valid only while the relevant PAR exposes that page at the pointer's CPU address. A routine that changes mappings must define which pointers remain valid and restore or hand off the mapping before returning. See the CoCo 3 memory map.
