Assembly tips

Direct-page conventions

Using the 6809's DP register and direct-mode addressing to save bytes and cycles on hot variables.

Why direct page matters

The 6809's DP register holds the upper byte of every direct-mode effective address. When the assembler emits direct mode (an 8-bit operand byte), the CPU concatenates DP with that byte to form the 16-bit address. The result:

  • Two bytes per access (opcode + low byte) instead of three (opcode + 16-bit address) for extended mode.
  • Four clock cycles for a direct-mode load instead of five for extended.

For a 256-byte region you access often, the savings compound across every load and store. On the 1.78 MHz CoCo 3 with a tight per-frame budget, this is the cheapest performance lever the architecture offers.

Setting DP at boot

Set DP once early in your boot sequence and leave it alone for the life of the program: 

        lda   #$02         * upper byte of $0200
        tfr   a,dp         * DP = $02; direct page covers $0200-$02FF

Some assemblers (including lwasm) require a directive so they know to emit direct-mode encodings for matching addresses: 

        setdp $02          * lwasm: tell the assembler DP = $02

Forcing direct mode

The < prefix forces direct-mode encoding even when the assembler would otherwise pick another form: 

        lda   <score      * direct: 2 bytes, 4 cycles
        lda   score        * may emit extended (3 bytes, 5 cycles)
        sta   <$05        * direct: store A at DP:$05

Conversely, > forces extended mode if you need it for a label that could live in the direct page.

What to put in the direct page

DP space is precious (256 bytes total). Reserve it for:

  • Per-frame counters and flags read by the main loop.
  • IRQ handler scratch — the interrupt path should never pay extended-mode prices.
  • Hot pointers to game state that get dereferenced every frame.
  • Sprite-blit temporaries on the fast path.

Keep cold data (one-time init, debug counters, anything touched at boot-time only) in extended-mode memory and save DP for the things that run 60 times a second.

Pitfalls

  • Changing DP mid-program invalidates every prior direct-mode encoding. Don't. Set DP once and treat it as constant.
  • The assembler doesn't enforce DP. If you setdp $02 but never tfr a,dp at runtime, your direct-mode operands will resolve against whatever DP the BASIC ROM or cartridge handshake left behind.
  • Interrupts inherit DP. If your main code runs with one DP and an IRQ handler assumes another, the handler's direct-mode operands will resolve to the wrong page. On a single-DP project this is a non-issue; if you ever need per-context DP, save/restore in the IRQ prologue.

Reference: Tepolt, Assembly Language Programming for the Color Computer ch. 4 (Addressing Modes); Motorola MC6809E HMOS 8-Bit Microprocessor data sheet §3.
