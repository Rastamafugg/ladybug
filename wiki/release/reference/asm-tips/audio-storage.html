Assembly tips · audio data

Audio Data Storage release

Keep cue data, executable service code, boot transport, and live audio state in their correct phases.

Separate source cues from the runtime module

Ladybug's GMC cues are compact command streams for the SN76489 sound generator, not recorded waveform samples. The audio runtime assembly includes its cue descriptors and data from assets/arcade/audio/gmc_sound_data.inc. The resulting audio-runtime module contains both executable service code and the cue data it addresses.

The build then treats the compiled module as a boot-transport stream. It compresses the module for cartridge storage, stages the packed bytes in physical page $24, and expands the module into its runtime allocation in page $3D. At runtime the service maps its page through PAR5 and restores the caller's game-state mapping before returning.

Use generated descriptors for relocated payloads

The sparse-sprite packer emits a descriptor table for boot streams and derives the audio stream's index and byte offset from the final stream list. The bootstrap verifies that audio is the unique final descriptor before using that generated identity. Keep the descriptor producer and the boot consumer in sync; do not copy an ordinal or address from an older manifest into assembly.

; Source path, not a literal runtime address:
assets/arcade/audio/gmc_sound_data.inc
        ↓ assembled with src/audio_runtime.s
ladybug-audio-runtime.bin
        ↓ compressed as boot transport
page $24 staging
        ↓ boot expansion
audio runtime and cue data in page $3D

The stage page is temporary storage for a lifecycle phase. It is not the address the steady-state mixer should retain. Check the current profile and generated layout when documenting an address or module size.

Match storage to lifetime

Executable audio code, cue bytes, active voice records, and output shadows have different lifetimes even when they share one mapped page. Ladybug's first 28-byte voice slot keeps the active cue fields in its first 17 bytes and reuses the remaining 11 bytes for retained SN76489 output shadows. Resetting the slot must preserve those shadows or explicitly reinitialize them.

Direct-page event-queue fields are accessed without changing the current banked audio mapping. Code and cue pointers into page $3D are only valid while PAR5 selects that page. Record which values are persistent between ticks and which scratch values may be reused by the sequential decoder and mixer.

Profile is part of the layout

The complete build selects adaptive rendering by default, while the build can explicitly override that setting. ADAPTIVE_RENDERING conditionally includes audio-service code and changes the assembled runtime. A size, symbol, or offset claim therefore needs its profile and generated module identity. Source lengths alone do not establish the final packed allocation.
