Audio Event and Output Processing release

An event is only audible after admission, voice selection, mixing, and register output.

Follow the event to the hardware write

Keep audio service stages visible in the routine structure. Ladybug polls the current gameplay or presentation owner, places semantic events in a bounded queue, admits cues into music or effect slots, advances command streams, mixes the active voices, and writes changed register state to the GMC SN76489 interface. A slot's priority does not by itself prove that the mixer selected it.

; Ordered stages from the non-adaptive audio_tick path
        lbsr    audio_process_queue
        jsr     audio_music_dispatch
        lbsr    audio_advance_all
        lbsr    audio_credit_service
        jsr     audio_mix
        jsr     audio_mix_write

This sequence separates event policy from device output. The queue can reject an event, admission can replace a lower-priority voice, and the mixer can choose another source. Verify the stage that owns the behavior being changed.

Service time and event time are different

A cue stream contains commands and waits. Advancing a wait is logical audio time; it is not the same operation as emitting the next PSG register values. In adaptive builds, the audio API separates elapsed-note service, semantic admission, audible publication, and rebasing after static work or a phase change. The ordinary tick path handles its stages in one foreground service call.

Follow the build's ADAPTIVE_RENDERING selection before describing which path a user will run. The complete profile defaults to the adaptive build setting, and scripts/build.sh supports an explicit override. Do not describe one compiled path as unconditional behavior.

Use shadows to avoid needless output

The mixer keeps logical channel periods, attenuation, and noise state before encoding SN76489 latch/data bytes. It retains 11 bytes of output shadow so unchanged continuation, attenuation, and noise values can be skipped. Tone latches are deliberately selected before a possible continuation write. This combines stateful device programming with fewer redundant data writes while preserving register selection.

Keep register encoding at the output boundary. Storing already-latched device bytes throughout every event queue makes priorities and mixed voices harder to reason about and couples producers to the physical chip's write format.

Verify the right evidence

  • Queue acceptance proves an event was recorded, not that a voice was selected.
  • Stream completion proves the decoder reached its end, not that a sound reached the device.
  • Mixer state and matching PSG shadows prove software output state, not physical-hardware listening.
  • Profile, service phase, and the measured audio worklist belong with any timing or cadence claim.

Audio cue storage and module placement are covered by audio data storage. The CoCo 3's DAC, cartridge SND selector, and PB1 paths are documented separately in the sound hardware reference; Ladybug's GMC chip output should not be confused with the internal DAC.
