Assembly tips · CoCo 3 memory

MMU-Aware Pointer Lifetimes release

A 16-bit pointer names a CPU window; the current PAR mapping selects the physical page behind it.

A pointer does not carry a physical page

The 6809 addresses a 16-bit virtual space. With the CoCo 3 MMU enabled, each 8 KiB virtual page is translated by its Page Address Register (PAR). For example, an address in $A000-$BFFF accesses whichever physical page PAR5 currently selects. If PAR5 changes, the same address can refer to different bytes.

Treat a pointer into a remappable window as a value with an owner and a lifetime. Its lifetime ends when the mapping changes, when a callee changes that mapping without restoring it, or when control returns to a caller whose contract requires another page.

Save, map, consume, restore

This schematic pattern assumes the routine and stack execute in windows that the PAR5 change does not remap. The consumer must finish using its pointer and return with PAR5 still selecting the source page.

; GIME_PAR5 is the executive PAR5 register at $FFA5.
; SOURCE_PAGE is selected only for this bounded call.
        lda     GIME_PAR5
        pshs    a
        lda     #SOURCE_PAGE
        sta     GIME_PAR5
        ldu     #$A000
        jsr     consume_stream
        puls    a
        sta     GIME_PAR5

If code itself executes from $A000-$BFFF, changing PAR5 can replace the instructions that must run next. Put the mapping operation in a stable window or arrange a deliberate handoff. Also define what nested helpers and interrupts may do to the same PAR.

Resolve relocatable data instead of retaining raw addresses

Ladybug's sparse actor index stores a physical page plus a CPU address for each frame. The resolver maps the indexed payload page and returns a pointer into the mapped window; the decoder consumes the stream before the caller restores the game-state page. The frame record keeps an ordinal, not a pointer that would become stale when PAR5 is reused.

Apply the same rule to cold assets, banked routines, and temporary aliases. Keep the source page, CPU window, mapping owner, and restoration point together in the routine contract. A pointer into the current mapping is not a persistent handle.

Review the full call boundary

  • Identify which PAR makes the pointer valid and which routine owns writes to that PAR.
  • Check that instruction fetch, stack access, and direct-page scratch remain mapped across the switch.
  • Require callees either to preserve the mapping or to return a documented page and pointer pair.
  • Restore the caller's mapping before reusing its saved pointers or updating state through that window.
  • Validate page reads as six-bit physical page values when observing GIME state; upper readback bits are not part of the page number.

For register definitions and the virtual/physical address model, see the GIME MMU reference and the CoCo 3 memory map. For indexed stream selection, see asset packing and sparse streams.
