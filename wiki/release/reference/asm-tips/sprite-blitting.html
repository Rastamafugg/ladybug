Assembly tips · native pixels

Packed Pixel and Sprite Blitting release

Make pixel format, transparency, row stride, and restoration explicit.

Address the destination in bytes

In Ladybug's 320 by 192, 16-color mode, each pixel uses four bits and each byte holds two neighboring pixels. A framebuffer row is 160 bytes. The high and low nibble therefore name different pixels; a partial write must preserve the nibble that the sprite leaves transparent.

Indexed actor sources begin as packed two-bit pixels. The host builder applies each frame's palette map, expands the pixels to native four-bit bytes, and then emits sparse commands. At runtime, the indexed player path resolves that sparse stream and the framebuffer blitter consumes its native pixels; the raw two-bit source and runtime command stream are separate formats. Name both ends of every conversion in the data contract.

Use direct copies for opaque runs

When both destination nibbles are covered, the decoder can store a byte directly and advance X. Transparent gaps can be skipped by a destination delta. These commands reduce work for sparse frames, but the command parser and index lookup also cost cycles; compare complete actor worklists before specializing a decoder.

Mask only the pixels that must survive

A partial command carries a mask and replacement byte. The mask preserves destination nibbles for transparent source pixels; the replacement supplies the visible pixel. This fragment is the runtime path used by the sparse framebuffer decoder.

; Source pattern from sparse_blit_fb in src/enemy_runtime.s
        lda     ,u+       ; destination-preserve mask
        anda    ,x
        ora     ,u+       ; replacement pixel byte
        sta     ,x+

Opaque and partial runs have different costs and inputs. Do not use an opaque copy when one nibble is transparent, and do not read-modify-write fully opaque bytes without a reason.

Restore the right underlay

Moving actors need a clean background before their new pixels are drawn. Ladybug saves each player's 16 by 16 footprint as 128 bytes and retains enemy save-under records per framebuffer owner. When actor footprints overlap, restore the affected closure before capturing new clean pixels; restoring only one actor can preserve another actor's old pixels as background.

Keep all reads and writes inside the declared clipped extent. A sprite that is partly off-screen needs a matching source offset, destination offset, and visible-row count. Do not assume that advancing a pointer by one row is the same as advancing one contiguous sprite row when the source and framebuffer strides differ.

See asset packing and sparse streams for frame indexes and framebuffer publication for owner-local save-under state.
