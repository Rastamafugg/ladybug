Screen and Graphic Data Generation release

Move parsing, transforms, deduplication, and address calculation to the host build.

Compile authored screens into runtime-ready data

Ladybug's screen builder reads authored Tiled maps, validates the map and layer contracts, applies supported transforms and palette mappings, packs native tiles, and emits compact tables for 6809 consumers. Presentation generation builds on that compiler to produce shared cold assets, map streams, descriptors, and overlays. Runtime code uses those prepared bytes instead of parsing XML, resolving editor tile IDs, or repeating host-side image transforms during play.

This shifts deterministic work to the development machine. It also makes the generated output an explicit interface: assembly consumes stable labels and records, while the builder owns the conversion rules and validation.

Use final generated identities

Tile deduplication, palette corrections, profile options, and overlay packing can change a tile's final atlas index or a stream's offset. A hand-copied index from an earlier build can cross a dispatch boundary and point into unrelated data. Generate the consumer constant from the final descriptor or manifest and have the build reject values outside the intended range.

Keep editor coordinates, logical map IDs, packed atlas IDs, and framebuffer addresses as distinct types in comments and routine contracts. Convert at the boundary where the next representation is selected. Do not let a Tiled global ID leak into a native descriptor lookup unless that is the defined table key.

Validate before omitting or compressing data

  • Check map dimensions, tile dimensions, required layers, and complete screen coverage before flattening the map.
  • Recognize metadata layers by their validated contract; visibility alone does not make a layer disposable.
  • Deduplicate packed tile bytes only after color and transform conversion, so equality means identical runtime pixels.
  • Emit offsets, lengths, hashes, and page-boundary checks beside the generated payload they describe.
  • Retain authored assets and source manifests as the reviewable authority; generated output is reproducible build data.

The gameplay screen compiler validates a 40 by 24 map of 8 by 8 cells. The presentation builder also emits profile-specific content. Record the profile when describing an output layout or byte count.

Keep generation distinct from rendering

A successful compiler run establishes that the builder accepted the authoring inputs and produced bytes. It does not prove the runtime selected the correct descriptor, mapped the correct page, wrote the intended framebuffer, or published those pixels. Use sprite blitting and framebuffer publication for those consumer-side contracts.

For native display modes and palette registers, use the GIME reference. Keep hardware register facts there and keep project compiler conventions here.
