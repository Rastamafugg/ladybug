XRoar -monitor port — Phase 1 requirements internal

Custom JSON-RPC "monitor" server inside XRoar, replacing the gdb stub for our tooling. Eliminates the four documented gdb-stub limitations from the 2026-05-16 lessons-learned entries.

Supersedes the deferred design sketch in backlog/mcp-xroar-server.

Architecture

 Claude Code / agent ──MCP (real spec)──▶ Ladybug web backend (web/backend/instance.py)
                                            │
                                            ├──monitor JSON-RPC──▶ XRoar instance A
                                            ├──monitor JSON-RPC──▶ XRoar instance B
                                            └──monitor JSON-RPC──▶ XRoar instance C

The XRoar side speaks a project-private JSON-RPC "monitor protocol". The web backend owns the session registry and brokers commands; it is the component that speaks real-spec MCP outward. XRoar is not MCP-aware. The name -monitor (not -mcp) reflects this.

Activation

  • Flag: -monitor [host:]port — enable monitor server. Default endpoint 127.0.0.1:17654. Loopback-only by default.
  • Flag: -monitor-halt-on-start — pause CPU before first instruction until a client connects.

Transport & framing

  • TCP listener, line-delimited JSON-RPC 2.0 (one JSON object per \n).
  • No auth in v1; loopback is the trust boundary.

Concurrency with -gdb

Both stubs may be enabled simultaneously. Combination is allowed but unsupported.

Address-space model

  • "cpu" (default) — addr ∈ $0000–$FFFF resolved through the currently-active PAR set. Matches gdb behavior.
  • "physical" — phys_addr ∈ $00000–$7FFFF (19-bit), bypassing PARs. Required to inspect pages not currently mapped, and to write RAM-under-ROM regions.

Run-state contract for state-mutating commands

  • State reads — permitted while CPU is running.
  • State writes — require CPU halted. If running, return target_running.

Write semantics by address space

  • CPU-space write to a ROM-backed address: return read_only_region.
  • Physical-space write: always writes the byte directly into XRoar's RAM array at the 19-bit physical address. Bypasses bus decode. See lessons-learned §XRoar cart-window write decode.

Failure modes

  • Malformed JSON → JSON-RPC -32700; do not drop connection.
  • Unknown method → -32601.
  • Invalid params → -32602.
  • Memory reads capped at 64 KB.
  • Write to ROM-backed CPU address → read_only_region.

Explicitly out of scope (v1)

  • Replay / time-travel / reverse-stepping
  • Audio buffer capture
  • Analog joystick value injection
  • Authentication / TLS
  • Real Anthropic MCP-spec compliance inside XRoar
  • Persistent BP conditions / scripting
  • Hot-reload of the monitor stub

M1 carry-forwards

Tracked from QA review 2026-05-17. None block M2.

  • goodbye notification on XRoar shutdown — DONE in M5. Triggered via clean exit; new quit JSON-RPC method makes this externally triggerable.
  • Concurrent multi-client support — DONE in M6a. Accept thread spawns detached worker per client; event broadcasts use trylock.
  • -gdb + -monitor simultaneous activation: when both are enabled, coco3.c gives gdb precedence in the run loop; monitor's pause/run then silently no-op. Defer until a real need surfaces.
  • coco3.c delta vs plan estimate: plan said "Two lines". Actual is ~31 lines (run-loop gate architecturally required for pause/run).

M6a carry-forwards

  • Multi-client architecture in place via accept-thread + worker-per-client.
  • Event push avoids stalling the emu thread via pthread_mutex_trylock.
  • hsync event kind reserved but not wired (15.7 kHz tick rate would dominate trylock loop).
  • inject_text end-to-end depends on a CRC-matched BASIC ROM (auto_kbd installs its character-injection breakpoints via CRC list).
  • Watchpoints share bp_session with breakpoints; WP fires surface as reason="breakpoint" with bp_id=0.
  • signal_fs chained delegate is single-instance.
  • Deferred to M6b: screen_capture, snapshot_save/snapshot_load.

M5 carry-forwards

  • New method quit beyond plan's MUST table — only way to make XRoar run its atexit chain.
  • monitor_interface_free self-thread skip via pthread_equal.

M4 carry-forwards

  • coco3.c monitor branch now substantial (~25 lines).
  • Step batches are atomic w.r.t. UI events.
  • bp_id resolution on SIGTRAP — first-match wins for duplicate-addr BPs.

M3 carry-forwards

  • Plan errata — physical-space RAM indexing. M3 implements bank = phys / bank_nelems, off = phys % bank_nelems.
  • New accessor tcc1014_get_monitor_view: 19 lines to tcc1014.h, 17 lines to tcc1014.c.

M2 carry-forwards

  • read_only_region error still not implemented after M3. Deferred to M5+ or web-backend integration.
  • No size cap on register envelopes.
  • Run-state contract — read concurrency is a soft guarantee.

Open follow-ups (not blockers for Phase 2)

  • MAME comparison test of the cart-ROM-to-RAM copy — see backlog/mame-cart-ram-comparison.
  • Real-hardware verification of the RAM-under-ROM write contract — deferred to Phase 10 hardware bring-up.
