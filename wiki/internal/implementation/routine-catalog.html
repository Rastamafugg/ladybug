Implementation · routine contracts

Routine Catalog internal

Canonical purpose and interface contracts for every exported, called, fixed-entry, hardware-touching, shared-state-mutating, or otherwise non-trivial routine in the current release topology.

Controlled vocabulary

Routine contract, authoritative state, render intent, and publication use the glossary definitions throughout this catalog.

How to read a contract

Each routine contract is the combination of its unique purpose below and one named interface profile. The profile supplies inputs, outputs, conservative clobbers, memory reads, memory writes, side effects, and invariants. A narrower source-local header overrides the conservative register set but may not widen memory ownership or weaken an invariant. Generated module pages add current callers, callees, source lines, addresses, and emitted bytes; they do not own semantic meaning.

In each routine table, label is the authored global symbol and stable link target, purpose is that routine's owned operation, profile selects the complete interface contract, and coverage reason states why fail-closed documentation requires the routine.

Interface profiles

Root and hardware gateway

Inputs: Entry-specific machine state and the shared direct-page protocol named by the routine purpose.

Outputs: Control transfers or status values defined by the routine purpose.

Clobbers: A, B, D, X, Y, U, and condition codes unless the caller-facing entry contract states otherwise.

Reads: Always-mapped direct-page protocol state plus the module-owned state required by the selected operation.

Writes: Module-owned state and mapped hardware registers required to establish or dispatch the operation.

Side effects: May change mapping, interrupt, rendering, or lifecycle ownership as stated by the routine purpose.

Invariants: The stack remains balanced and every temporary PAR mapping is restored or deliberately handed off before return.

Authoritative state mutation

Inputs: Current authoritative gameplay or presentation state; register arguments are named by the routine label and immediate caller.

Outputs: Updated authoritative state and condition codes used by the immediate caller.

Clobbers: A, B, D, X, Y, U, and condition codes unless a narrower source-local header is present.

Reads: Owned direct-page and page-$34 state needed for the operation.

Writes: Only the owned state fields and render intents required by the operation.

Side effects: May enqueue rendering work but does not publish FRONT.

Invariants: Authoritative state changes precede their render intents; framebuffer publication remains IRQ-owned.

BACK and staging rendering

Inputs: Current render intent, selected actor or tile state, and a valid BACK or staging destination.

Outputs: Updated destination pixels and any owner-local history required by later restoration.

Clobbers: A, B, D, X, Y, U, and condition codes unless a narrower source-local header is present.

Reads: Authoritative gameplay state, immutable art streams, and current owner-local background metadata.

Writes: BACK or staging pixels, render scratch, and owner-local save-under or damage metadata.

Side effects: Changes a non-visible composition surface or its metadata.

Invariants: The routine never selects the visible FRONT surface; temporary PAR5 mappings expire or restore before return.

Persistent framebuffer protocol

Inputs: ACTIVE/PENDING state, BACK identity, owner metadata, and the current worklist.

Outputs: A prepared, captured, finished, or published framebuffer transaction as named by the routine.

Clobbers: A, B, D, X, Y, U, and condition codes unless the fixed entry contract narrows them.

Reads: Always-mapped framebuffer protocol bytes and owner-local metadata.

Writes: Framebuffer protocol bytes, BACK pixels, owner-local metadata, and GIME display offset only at IRQ publication.

Side effects: Advances one bounded phase of the persistent A/B transaction.

Invariants: Foreground code may arm PENDING but only Vbord IRQ publishes FRONT; mapping-sensitive pointers do not outlive PAR changes.

Movement and collision

Inputs: Current actor coordinates, direction, maze topology, gate state, and collision state.

Outputs: A legality result, selected direction, contact result, or updated actor state.

Clobbers: A, B, D, X, Y, U, and condition codes unless a narrower source-local header is present.

Reads: Authoritative actor records, maze and gate tables, and movement scratch.

Writes: Owned actor state, collision flags, and render intents required by the movement result.

Side effects: May change authoritative gameplay state and queue later composition.

Invariants: Movement remains on legal semantic cells and does not write framebuffer pixels directly.

Bounded copy, cache, and address transformation

Inputs: Source and destination identities, bounded count or stream metadata, and any required mapped page.

Outputs: Copied, decoded, merged, cached, or addressed data plus caller-visible pointer progress.

Clobbers: A, B, D, X, Y, U, and condition codes unless a narrower source-local header is present.

Reads: The declared source stream, table, framebuffer rows, or metadata record.

Writes: Only the declared bounded destination record, cache, row range, or scratch fields.

Side effects: May temporarily map PAR5 while moving or decoding data.

Invariants: Counts and destination bounds are honored; temporary mappings are restored before returning.

Presentation interval

Inputs: Presentation state, interval timer, input edges, current map, and the selected auxiliary profile.

Outputs: Updated presentation state and the dispatcher retain/release status when applicable.

Clobbers: A, B, D, X, Y, U, and condition codes unless a narrower source-local header is present.

Reads: Presentation direct-page state, cold payloads, authored map streams, and input state.

Writes: Presentation state, mapped BACK pixels, and presentation-owned persistent metadata.

Side effects: May retain the foreground interval or produce a complete presentation surface.

Invariants: Gameplay mutation begins only after the dispatcher releases the interval; FRONT publication remains IRQ-owned.

PIA input sampling

Inputs: PIA input state, prior sampled state, and axis or key selection.

Outputs: Normalized input state, edge bits, or axis sample.

Clobbers: A, B, D, X, Y, U, and condition codes unless a narrower source-local header is present.

Reads: PIA registers and prior input samples.

Writes: Owned input state and temporary PIA scan selection.

Side effects: Temporarily drives keyboard or joystick scan hardware.

Invariants: PIA control and drive state are restored to the runtime convention before return.

Bootstrap and delivery

Inputs: The declared cartridge bank, staged payload, destination identity, and bootstrap mapping state.

Outputs: Installed runtime bytes or a non-returning transfer to the next boot phase.

Clobbers: All CPU registers and condition codes.

Reads: Cartridge-staged payloads, generated size symbols, and bootstrap tables.

Writes: Declared RAM destinations, PAR registers, boot scratch, and decompressed surfaces.

Side effects: Changes MMU mappings and copies or synthesizes executable/data payloads.

Invariants: Authored, staged, and destination byte identities remain distinct and every transfer obeys its generated size bound.
