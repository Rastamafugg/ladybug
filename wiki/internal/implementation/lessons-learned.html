Lessons Learned internal

Observed-fact findings — hardware quirks, register gotchas, patterns to avoid, and explicit decisions to skip otherwise-tempting precedents. Append-only.

Presentation cold data and game-state aliases require an explicit PAR5 handoff

Filed 2026-08-11. BUG-010 mapped presentation cold page $3A while loading the title, then called framebuffer preparation before restoring game-state page $34. Preparation wrote ENEMY_OLD_FB at virtual $A890, corrupting six bytes of cold atlas tile 68. The damaged tile appeared twice on the instructions screen and produced deterministic transition artifacts even though the boot-loaded cold payload initially matched its authored hash.

Rule: before calling any renderer or ownership routine that accesses page-34 state, explicitly restore PAR5 to $34. Verify immutable payload identity both immediately after loading and after every cross-module handoff; boot-time identity alone does not prove runtime immutability.

Citation: BUG-010, src/presentation_runtime.s, src/perimeter_reset_helper.s, and scripts/verify_bug010_visible_runtime.py.

Framebuffer oracles must scale tile rows by tile height

Filed 2026-08-11. BUG-010's static oracle placed each 8-pixel TMX row only one 160-byte scanline below the previous row instead of eight scanlines, while runtime rendering correctly advanced 1,280 bytes. Actor-only crops could still pass, but the composed title hash described rows 0–1 instead of the authored rows 7–18.

Rule: derive framebuffer destinations as tile_row * tile_height * scanline_stride + tile_column * packed_tile_width. Retain a natural physical-frame comparison in addition to generated hashes so the oracle cannot validate its own coordinate defect.

Citation: BUG-010, scripts/build_presentation.py, and the four-phase physical-frame evidence.

Copied modules must import current resident symbols

Filed 2026-08-11. The presentation module retained a literal BLIT_TILE equ $D6C1 while the current resident map placed blit_tile at $D6BF. The build already generated a presentation symbol include for other resident calls, so exporting blit_tile removed the stale-revision dependency.

Rule: copied absolute modules must consume build-generated symbols for every resident call target. Static verification must compare each imported address with the current map; older absolute addresses are not valid evidence for current main.

Citation: BUG-010, scripts/build.sh, and src/presentation_runtime.s.

BUG-010 hold publication requires a transient owner state

Filed 2026-08-10. Restoring the presentation module to the locked $1900-$1DFF boundary required moving the attract actor loop into the existing helper allocation. The helper now copies the complete visible framebuffer to $28-$2B in thirty bounded chunks, publishes it only through transient owner ID 2 at Voffset $A0, and hydrates both persistent A/B owners before normal publication resumes.

Rule: compatibility storage is not a persistent framebuffer owner. Keep its state in always-mapped direct-page bytes, preserve the last complete hold surface across pre-emption, and prohibit intermediate A/B publication while hidden owners are hydrated. Final-pending cancellation must share the pending publication path so an input edge cannot leave a stale commit armed.

Citation: BUG-010, src/perimeter_reset_helper.s, src/presentation_runtime.s, and src/enemy_runtime.s.

Edge-triggered input must retain the sampled cold baseline

Filed 2026-08-10. BUG-009 called the presentation keyboard scanner before cold-state initialization. That scan correctly stored the idle CoCo keyboard rows as $7F,$7F,$7F, where PA7 is the joystick comparator rather than a keyboard row, and the cold path ignored its arbitrary pre-initialization event result. The cold path then replaced those samples with $FF,$FF,$FF; the next unchanged scan interpreted the PA7 difference as a new active-low edge on every selected credit drive, produced event mask $07, and replaced the pending attract load with high score before first publication.

Rule: initialize an edge detector from the first real hardware sample and suppress that sample's event, then retain the sampled baseline. Do not substitute an assumed all-high idle byte when input ports contain non-keyboard or platform-dependent bits. Verify no-input, held-through-initialization, release, and new-press sequences.

Citation: BUG-009, src/presentation_runtime.s presentation_flow_tick/scan_keys, the CoCo 3 input reference, and the 2026-08-10 bounded XRoar/GDB capture at checkpoint 8183005.

FEAT-002 diagnosis requires live-byte and visible-path proof

Filed 2026-08-09. The FEAT-002 recovery initially appeared to implicate GIME or PAR setup, but live-byte comparison showed bank-0 bootstrap bytes at the supposed resident handoff. Selected cartridge ROM prevented same-destination writes from populating resident RAM; staging resident and asset bytes in boot-only physical pages before all-RAM publication corrected the delivery defect. A separate boot-synthesis defect read bank-0 bootstrap bytes instead of authored bank-1 screen assets until bank 1 was retained during synthesis.

Rule: before interpreting a live symbol or hardware access, compare authored/source, staged, and final destination bytes. Treat undocumented hardware failure as a last-stage hypothesis requiring discriminating software/tool/emulator results plus independent or authoritative support. A runtime marker also proves only code reachability; first visible screen, decoded content, input ownership, and natural sequence require separate evidence.

Applies to: GMC bootstrap and handoff diagnosis, MMU/PAR investigations, presentation startup, bounded XRoar/GDB probes, and QA closure.

Citation: FEAT-002, PERF-004, RSCH-002, src/gmc_bootstrap.s, and the 2026-08-09 recovery evidence.

Indexed sparse-stream resolvers must preserve caller-owned destinations

Filed 2026-08-09. BUG-008 passed a framebuffer or stage destination in X, then sparse_enemy_stream and sparse_player_stream reused X to address a three-byte stream-index record. The decoder therefore received an index offset instead of the destination. On first live-stage publication, enemy-stage decode began at $0000, corrupted direct-page state and the return path, and recursively entered frame_render_impl. The repair calculates the indexed U address before payload-page selection, preserving X without a wrapper or second decoder; the bank-3 module fell from 4,089 to 4,081 bytes.

BUG-010 extension 2026-08-10: the presentation actor resolver selected the index page, read the stream page byte, remapped PAR5, and only then read the two-byte address through the same virtual pointer. It therefore decoded unrelated bytes and expanded phase-changing title intervals to 104,963–179,918 cycles. Loading U before the remap, with no instruction-size or allocation change, reduced the complete natural interval and all 69 phase changes to at most 15,017 cycles.

Rule: a resolver inserted between destination setup and decode must preserve the destination register and every multi-byte index field before changing the bank that owns the index window. Runtime verification must assert authored/staged/live module identity, decoder return/publication, and a natural cycle distribution; proving only that decoder entry was reached is insufficient.

Citation: BUG-008, BUG-010, src/enemy_runtime.s sparse_enemy_stream/sparse_player_stream, src/presentation_runtime.s draw_actor_overlay, and the bounded XRoar traces.

Presentation actor overlays require the existing save-under contract

Filed 2026-08-08. A transparent sparse actor blit does not remove pixels from its previous framebuffer footprint. FEAT-002 instruction traversal left trails until each movement restored the prior 16×16 rectangle through the resident save_player/restore_player routines and the already-owned PLAYER_BG_PTR buffer. The presentation module now selects $A300, clears PLAYER_BG_VALID on screen load, and orders restore, save, then draw within the 1280-byte module.

Rule: every presentation actor that moves over static pixels must reuse an owned save-under buffer or a verified static redraw path; transparent drawing alone is not restoration.

Arcade presentation coordinates require retained capture and transform evidence

Filed 2026-08-08. Projected actor positions are not arcade evidence. FEAT-002 retains the MAME contact capture hash, frame number, thumbnail extraction rule, established counter-clockwise rotation, CoCo centering offset, and final framebuffer destinations in assets/arcade/attract_actor_reference.json. scripts/verify_presentation_flow.py rejects a changed capture hash or source constants that do not match the recorded transform.

Rule: preserve the source capture and deterministic coordinate transform with the code; a comment or visual estimate is insufficient.

Copied raw modules must have executable bytes at the loader destination

FEAT-002 assembled a low-RAM module with emitted metadata before the code's absolute $1900 origin. The raw binary concatenated that metadata before the code, so the loader copied data to the call target and XRoar decoded it as instructions. The static map symbol alone did not prove raw-image entry alignment.

Rule: require the first copied byte at every relocated entry to be an executable opcode, and keep compile-time metadata out of the raw prefix unless the entry stub explicitly skips it.

Presentation sentinels must validate an exact value in uncleared RAM

FEAT-002 used a nonzero-only presentation magic test. Cold RAM contained a nonzero byte, so initialization was skipped and the presentation mode became an unrelated opcode byte. An exact magic comparison now distinguishes initialized state from arbitrary RAM contents.

Rule: use an exact multi-state initialization marker whenever a copied module owns RAM that is not cleared by the platform boot path.

Gameplay re-entry must restore persistent framebuffer ownership

The presentation demo reused init_game_state, which clears FB_INIT_STATE. Without rerunning framebuffer ownership initialization, the persistent compositor intentionally skipped restore, damage queue, and damage projection, leaving the runtime probe unable to cover those paths.

Rule: any presentation-to-gameplay re-entry that resets logical state must rehydrate all persistent renderer ownership ledgers before the next frame.

Cold-screen atlases can consume the source budget before the page budget

FEAT-002's six 40×24 maps fit within four physical 8 KiB destination pages, but coordinate-dependent palette transforms produced 254 shared native tiles and a 13,888-byte payload. The current GMC source layout retains only 76 bytes after the copied presentation module. Source-capacity, destination-page, module-size, and stack-margin checks must remain separate; a destination fit is not evidence of source headroom.

Presentation pre-emption must retain a controlled gameplay probe

Adding a boot attract loop changes the first observable runtime path. Existing gameplay compositor proofs that assume immediate gameplay can fail without proving a presentation-to-gameplay transition. Runtime verification must either force the transition with an input/replay control or use a bounded probe long enough to reach normal gameplay; a loader-only pass is insufficient.

Queued gate projection must precede or follow entity redraw as one transaction

Filed 2026-08-07. A queued gate final can be projected into BACK before the current epoch's collectible colour redraw. If the current epoch has RF_ENTITIES but no current gate intent, erase_entity_footprints restores static maze tiles over the already projected dynamic gate. A forced nearby-entity case changed 19 bytes in the gate union on both framebuffer owners.

Rule: treat queued gate projection and entity underlay/redraw as one ordered transaction; the authoritative gate union must be the last dynamic layer in any combined replay.

Citation: BUG-005, framebuffer_project_gate_only, frame_render_background, and erase_entity_footprints.

Respawn invalidation requires republishing the replacement actor

Filed 2026-08-07. Clearing both FBM_PLAYER_VALID bytes prevents stale save-under restoration, but dt_finish_blank requests RF_PLAYER for only one transaction. The steady-state actor closure does not draw an alive player solely when the selected owner's validity is clear, so the next owner can publish without the replacement Ladybug.

Rule: after respawn, require a valid replacement player record on every framebuffer owner before clearing the redraw obligation.

Citation: BUG-006, dt_finish_blank, framebuffer_prepare_back, and actor_closure_draw.

Gate legality must validate both current and target ownership paths

Filed 2026-08-06. Enemy navigation used a static fast path whenever the current cell lacked the dynamic gate bit. Ordinary cells immediately before a gate-owned target could therefore enter the target without consulting GATE_STATE. The independent 128,640-case oracle reproduced 3,200 legacy mismatches across all gates and four states.

Rule: before accepting a static exit, inspect the target's gate-owner record and route gate-owned targets through the dynamic state oracle. Keep the fast path only for ordinary target cells.

Applies to: enemy junction choice, future actor navigation, and any optimized current-cell collision path.

Citation: BUG-002, src/enemy_runtime.s enemy_direction_legal, and scripts/verify_bug002_enemy_gate_collision.py.

Stage-load entity rendering requires the same underlay restore as replay

Filed 2026-08-06. The initial stage compositor draws the authored maze before drawing randomized entities. Because it skipped the entity-footprint restore used by incremental RF_ENTITIES redraws, the authored flower remained visible under a collectible until the first colour-cycle redraw. BUG-003 now restores those footprints before gate and entity publication.

Rule: every stage or full-background path must clear object footprints from the authoritative maze state before drawing entity pixels. Static skull art remains white and is verified separately in Done BUG-004; the shared redraw may visit the record, but palette selection must not read BONUS_COLOR.

Persistent-intent offsets must be named and mutation-tested

A gate-only replay optimization copied a 16-byte render-intent record but loaded offset 13 as the primary gate style. The actual layout places the primary and secondary styles at offsets 14 and 15; offset 13 is unused direct-page byte $008C. Zero-initialized performance fixtures concealed the invalid read. Style 1 restored the wrong pair of diagonal dot cells in one framebuffer, while random nonzero values indexed beyond the two-style offset table. A controlled $00/$FF comparison produced an out-of-framebuffer write at CPU stack address $1FE7.

Rule: define persistent-record offsets once, assert every producer and consumer against that layout, force every enumerated field value in natural replay, and mutate reserved bytes to prove they are inert. Pixel convergence alone is insufficient when an invalid field can redirect a compositor outside its declared write region.

Correction: offset $008C is the live RENDER_ZONE_Y field, not an unused reserved byte. The required mutation test must preserve and vary that field only through valid zone-refresh scenarios; gate-style replay must read offsets 14 and 15 exclusively.

Citation: BUG-001, src/main.s framebuffer_project_gate_only, and the 2026-08-06 all-gate/style XRoar diagnostics at revision deea3c9.

Cartridge source capacity and runtime destination capacity are independent gates

Counting only the remaining bytes in banks 2 and 3 understated available cartridge source storage and could reject cycle-improving precomputed data even though bank 0 was mostly empty. Bank 0 offsets $0800-$3DFF now form a manifest-owned overflow pool used after the primary source intervals.

Rule: accept per-bank source spill when the complete CPU-readable four-bank allocation fits, but retain independent checks for the loader boundary, destination RAM, MMU ownership, resident/assets/enemy-module windows, direct page, stack, ABI, timing, and behavior. Arbitrary absolute code is not relocatable merely because source ROM space exists.

Citation: scripts/build_sparse_sprites.py, scripts/verify_gmc_overflow.py, src/gmc_bootstrap.s, and TOOL-001.

Force rare fallbacks and natural replay in acceptance traces

A short movement distribution stopped reaching the discontinuity fallback, and isolated owner forcing measured nest animation below 25,000 cycles while missing the natural alternate-owner replay interval at 28,222. Explicit stale owner metadata now forces exactly four full captures on each owner, and three-interval animation traces prove current publication followed by queued replay.

Rule: required rare paths must fail verification when absent. For persistent A/B rendering, profile the natural current-to-replay sequence in addition to independently forcing each owner.

Citation: scripts/capture_performance_baseline.py, scripts/verify_performance_baseline.py, and build/performance-baseline.json.

Bounded scenery damage needs bounded actor recapture

A gate transition previously set one global dirty byte, forcing all four roaming actors through full 128-byte background captures even when their destinations did not intersect the gate. A four-bit overlap mask reduced the complete gate owners from 37,968/39,292 to 32,868/36,894 cycles while retaining the all-actor fallback for unrelated damage.

Rule: represent bounded mutable-scenery overlap per actor. Full-capture only intersecting current destinations after old actors are restored and scenery is projected; retain conservative global invalidation for unbounded or mixed damage.

Citation: src/main.s mark_gate_enemy_overlap, src/enemy_runtime.s roam_update_background, and build/gate-performance.json.

Pre-expand sparse presentations when packed decode dominates the frame

Packed popup and death expansion consumed about 9,000 cycles per presentation. Full native frames were fast but required 1,792 bytes for death alone; build-time sparse streams reused the existing decoder, removed the packed colour lookup and merge loop, and fit with 939 expansion bytes still free. Exhaustive A/B capture reduced popup from 34,763 to at most 25,185 cycles and isolated death presentation from 43,575 to at most 24,524 cycles.

Rule: compare native, packed, and sparse sizes against complete-interval cycle attribution. Keep build-time pre-expansion when it reuses a proven decoder and every required variant remains explicitly verified.

Citation: scripts/verify_presentation_sparse.py, scripts/verify_presentation_profiles.py, and build/performance-presentation.json.

Optimize circular restore by separating row and column phase

The generic vertical-ring restore recomputed a physical row address and byte wrap for every logical row, costing 4,840 cycles per enemy at a nonzero row phase. Selecting one of eight fixed column copiers once and executing at most two contiguous row segments reduced the controlling discontinuity frame from 45,034 to the mid-30K range. Four-byte PULU D,Y transfers further reduce phase-zero restore, vertical capture, and player save-under copies.

Rule: when both axes are circular, dispatch the small fixed axis once and segment only the wrapping axis. Do not repeat address multiplication and wrap decisions inside every row.

Citation: src/enemy_runtime.s roam_copy_bg_to_fb/roam_capture_ring_row and src/main.s save_player/restore_player.

Reject optimizations whose guards exceed their measured reuse

A reserved player-metadata byte could identify an owner-local presentation, but the measured player frame changes at the active cadence, so the overlap and damage guards added 280–283 cycles without removing a restore. Removing per-byte sparse masks saved 2,915 payload bytes, but splitting mixed-nibble runs added enough commands to increase horizontal and vertical maxima by 111 and 345 cycles.

Rule: measure reuse frequency and command fragmentation before retaining cache metadata or denser encodings. Capacity improvement alone is not a hot-path improvement.

Citation: Task 2 experimental current-revision XRoar captures and build/performance-baseline.json.

A passing horizontal sample is not renderer distribution acceptance

A hydrated horizontal sample measured 27,531/28,067 cycles, but a current-revision distribution found a 30,284-cycle horizontal junction frame, 30,603/30,629-cycle vertical frames, and 36,333/45,034-cycle discontinuity frames. The earlier sample was correct for its phase but did not cover the controlling paths.

Rule: require complete A/B distributions across horizontal and vertical motion, ring phases, arrivals, turns, and full-capture fallbacks. Record the source commit and relevant generator hashes with every acceptance result.

Citation: scripts/capture_performance_baseline.py, scripts/verify_performance_baseline.py, and build/performance-baseline.json.

Persistent damage replay can multiply transient renderer cost

A gate diagonal is a persistent background mutation. The first BACK owner draws it and queues coverage for the alternate owner. On the following frame, that owner must replay the diagonal before drawing the current final gate, producing two full gate compositions in one transaction. The measured event work is 66,027 cycles on the first owner and 140,296 cycles on the second.

Rule: budget a transient background effect across both framebuffer owners. A renderer that is acceptable once may still fail when damage projection and the next logical phase coincide. Prefer compact retained gate state or bounded footprint primitives that can project the final state directly.

Resolution 2026-07-27: when the current epoch draws the same gate’s authoritative final state, discard that BACK owner’s queued diagonal before projection. The final compositor restores the complete affected union, so replaying the transient first has no visible value. Redraw only static entities whose 16×16 footprints intersect the gate-plus-neighbour union; a global entity pass multiplied the bounded gate mutation by every collectible on the stage.

Transition-delta resolution 2026-07-27: all 168 gate, parity, style, and neighbour cases collapse to six canonical gate-relative byte-patch streams. Generate opaque destination runs from the authoritative cell compositions, retain dynamic dot restoration outside the stream, and map the shared player/gate payload page only after resolving gate state. This replaces contextual tile restoration and transparent gate blending without making the persistent framebuffer depend on an undocumented prior image.

Citation: controlled gate traces in build/remaining-gate-owner-a.trace/build/remaining-gate-owner-b.trace and wiki/internal/platform/timing.html.

Respawn must invalidate every framebuffer owner's actor history

Changing the player position at the end of the death sequence left both persistent framebuffer ledgers marked with valid save-under history from the prior life. Alternating owners could therefore restore stale player rectangles during the replacement life.

Rule: when an actor teleports or is recreated, clear its global validity and every buffer-local validity record before the new position is drawn.

Citation: src/main.s dt_finish_blank and the A/B player metadata at FB_META_A/FB_META_B.

Stage rebuilds must reapply session-persistent HUD state

The static stage image replaced persistent SPECIAL/EXTRA highlights with Grey source tiles even though their logical bits survived the transition.

Rule: after drawing the static HUD, redraw every session-persistent field from its logical state. Treat authored HUD tiles as the unlit baseline.

Citation: src/enemy_runtime.s fri_stage_background and src/main.s draw_word_progress_hud.

Stage rebuilds must reapply runtime gate state

The static TMX image and the generated runtime gate overlays were separate representations. A stage rebuild exposed incorrectly oriented authored gate sections until the player rotated those gates.

Rule: after drawing a static stage image, redraw every gate from GATE_STATE. Treat the static map as gate background, not authoritative dynamic state.

Citation: src/enemy_runtime.s fri_stage_background and src/main.s draw_all_gates.

Keep sparse control data always mapped; scope payload mappings to one decode

The original three-byte sparse index lived at the start of each PAR5 payload and required mapping the index page before mapping the selected stream page. Mirroring the 384-byte enemy and 48-byte player indexes into free PAR0 low RAM removes that first mapping and its direct-page page scratch.

Rule: mirror small, read-only dispatch metadata into an always-mapped page when its payload must be banked. Restore the banked window at the decoder terminator, not through a second wrapper call. Do not retain the payload mapping across callers that access state owned by the displaced page.

Citation: src/gmc_bootstrap.s, src/enemy_runtime.s, and the bounded GMC trace entering both decoders while actor state remains on PAR5 page $34.

Segment circular captures at the physical wrap

A horizontal exposed-column capture previously recomputed base + row*8 for every logical row. Physical ring rows are contiguous, so one initial phase calculation yields a tail segment followed by an optional head segment.

Rule: compute the physical start once, walk the contiguous stride, subtract the ring size at the wrap, and finish the second segment. Retain the generic indexed path only for operations that update a complete row.

Citation: src/enemy_runtime.s rub_horizontal_fb and the verifier model covering sixteen row phases by eight column slots.

Select buffer-local history; do not exchange its contents

A persistent framebuffer owner previously obtained its player save-under by exchanging all 128 bytes between fixed A-side working storage and B-side storage before rendering, then exchanging them again afterward. The affected transaction executed 256 swap-loop iterations and spent 7,168 cycles on byte movement alone.

Rule: when each owner already has fixed storage, select that storage through an always-mapped pointer for the transaction. Clone initial state once, but keep steady-state history stationary and move only ownership metadata.

Applies to: ping-pong save-under buffers, per-buffer damage ledgers, animation history, and other fixed owner-local state.

Citation: src/main.s/src/enemy_runtime.s PLAYER_BG_PTR, alternating A/B/A GDB proof, and the 2026-07-26 interpreter-adjacent trace attribution.

Use existing sentinel sign bits and share fixed-copy tails

The sparse row parser compared every start byte with $FF even though valid starts are only $00-$07. Its short opaque lengths also re-entered a generic byte loop despite being suffixes of existing fixed length-four and length-five copy bodies.

Rule: when the valid data range is nonnegative and the sentinel is negative, branch directly on N after the load. Label fixed-copy suffixes so shorter measured lengths reuse the same ordered instruction tails instead of duplicating code.

Applies to: compact interpreters with a constrained code bank, a validated token range, and repeated fixed-length payload prefixes or suffixes.

Citation: src/enemy_runtime.s sparse_blit_fb/sparse_blit_stage, the independent 128-enemy/16-player sparse proof, and the 2026-07-26 row/command profile.

Keep short sparse-command counts in B and specialize only measured common lengths

The framebuffer decoder spent most of its 13,656-cycle four-enemy path repeatedly storing and decrementing a direct-page command count. Opaque lengths five, six, and four were the repeated lengths with enough bytes to benefit from word copies after dispatch cost.

Rule: retain each command count in B across its byte loop and use ordered LDD/STD copies only for measured profitable opaque lengths. Keep the generic loop for all other lengths and masked partial commands.

Applies to: compact command streams whose hot count can remain register-owned and whose length histogram justifies a bounded specialization.

Citation: src/enemy_runtime.s sparse_blit_fb/sparse_blit_stage, scripts/verify_enemy_runtime.py, and the 2026-07-26 optimized sparse-decoder profile.

Dispatch circular row-zero restores once per actor, not once per byte

A generic circular decoder recomputed physical row addresses and dynamically split the wrapped column range for every one of 16 rows. Four horizontal enemy restores consumed 20,003 cycles even though horizontal movement never changes the packed row phase.

Rule: when row phase is zero, dispatch the eight column phases once to fixed four-word row loops; synthesize an odd wrapped word with separate A/B loads. Retain the generic decoder for nonzero row phases so vertical movement preserves the same ring format.

Applies to: fixed-size circular save-under buffers where one dimension remains unrotated across the common movement path.

Citation: src/enemy_runtime.s roam_copy_bg_to_fb, the eight-phase ring model, and the 2026-07-26 four-enemy fast-restore profile.

GMC payload capacity excludes the forced-RAM and I/O tail of every bank

Filed 2026-07-23.

A preliminary sparse-stream packing counted all 16 KiB of each GMC bank. The CPU can read cartridge data only at $C000-$FDFF, so bank offsets $3E00-$3FFF map to forced RAM and dedicated I/O rather than cartridge bytes.

Rule: constrain every loader source interval to bank offsets below $3E00. Validate both file offsets and their CPU addresses; nominal ROM-file capacity is not runtime-readable capacity.

Applies to: sparse sprite payloads, cold presentation screens, and every future GMC bank-to-RAM copy.

Citation: scripts/build_sparse_sprites.py, cartridge layout, and the phase-1 sparse loader proof.

Persistent framebuffer swaps require per-buffer history

Filed 2026-07-23.

Changing the GIME display base removes dirty-region publication, but the old front buffer becomes an older world snapshot as soon as it becomes the next back buffer. A shared save-under buffer or one-shot dirty flag cannot restore that snapshot correctly.

Rule: each physical framebuffer owns actor positions, frame keys, clean save-under data, and pending background damage. Logic mutates authoritative state without drawing; the back renderer restores its own history, projects current damage, saves clean destinations, draws final layers, and only then requests a Vbord commit.

Applies to: persistent double buffering, moving actor overlap, gate transients, nest animation, pickups, deaths, and stage rebuilds.

Citation: persistent ping-pong framebuffer design, fresh four-enemy trace, and GIME vertical-offset/Vbord references.

IRQ-visible state must not live behind a temporary MMU mapping

Filed 2026-07-23.

A ping-pong renderer may map PAR5 from game-state page $34 to a sparse-sprite page while Vbord remains enabled. An IRQ that reads handshake fields through PAR5 would then observe sprite bytes instead of ownership state.

Rule: place framebuffer ownership, readiness, sequence counters, and IRQ diagnostics in always-mapped physical page $38. Keep the IRQ independent of PAR5, and treat every temporary PAR5 mapping as scoped and non-nestable.

Applies to: framebuffer commits, sparse sprite decoding, loader windows, and future interruptible MMU windows.

Citation: src/main.s IRQ/MMU layout and the pre-implementation review of persistent ping-pong buffering.

Missed publication must freeze the logical render epoch

Filed 2026-07-23.

If Vbord arrives before a back image is ready, the old front remains visible. Advancing gameplay from the free-running Vbord counter would skip transient gate, popup, release, or death states while the unfinished image still represents the prior epoch.

Rule: advance simulation once per committed render transaction. On a missed Vbord, finish and publish the same frozen epoch; do not catch up timers or retarget the buffer.

Applies to: persistent double buffering, animation cadence, movement staggering, and overload recovery.

Citation: the pre-implementation review of persistent ping-pong buffering.

Expand immutable sprites at the hot-cache boundary

Filed 2026-07-23.

The packed enemy atlas and resident player frames conserve storage, but expanding the same selected frame inside every framebuffer or compact-stage draw repeats palette lookup and nibble unpacking in the hottest rendering paths.

Rule: keep cold immutable sprites packed, expand a selected frame once when its type/direction/animation or face/animation cache key changes, and let repeated hot draws consume native destination-format pixels. Account for larger caches against stack margin before changing their stride.

Citation: src/enemy_runtime.s enemy_sprite_cache, player_frame_cache_impl, blit_enemy_fb, and blit_enemy_stage; live 128-byte cache comparisons against the generated enemy and player frames.

Dirty flags must identify compositor ownership

Filed 2026-07-23.

A single enemy-dirty flag caused every roaming movement frame to rebuild and publish the unchanged 16-by-32 nest, including its packed-sprite blit. Movement and nest animation share the hidden framebuffer transaction but do not share the same dirty region.

Rule: represent nest/animation dirtiness independently from roaming movement. Run the shared restore/save/draw/publish transaction when either changes, but invoke each retained compositor only when its owned pixels changed.

Citation: src/enemy_runtime.s ENEMY_NEST_DIRTY, ENEMY_MOVE, and et_compose; live GDB-MCP probes with $60=0/$61=1 and $60=1.

Cache final bounded layers after scoped sparse expansion

Filed 2026-07-31.

A dormant animation frame did not require active-actor closure, but restoring its background and decoding the sparse sprite still left the complete interval near the movement ceiling. Four final 128-byte dormant rectangles fit in free game-state RAM, while the sparse source temporarily owns PAR5 and therefore cannot decode directly into that storage.

Rule: expand through an always-mapped stage, restore PAR5, then copy the completed native frame into owner-neutral page-34 cache storage. Carry animation-only damage separately through A/B replay and do not invalidate unrelated roaming save-under strips. Keep the complete compositor as the structural fallback.

Citation: src/enemy_runtime.s build_enemy_nest_cache and compose_enemy_animation, scripts/verify_nest_animation.py, and the 24,951/24,958-cycle complete A/B traces.

Snapshot reward state before applying a pickup's progression

Filed 2026-07-23.

Blue-heart scoring used the old multiplier correctly, but the delayed popup read the live multiplier after the same pickup advanced it. The displayed reward therefore contradicted the awarded score. The angel path had analogous delayed-state defects: its quarter counter did not wrap and its framebuffer pointer could cross the top boundary while fixed-duration animation continued.

Rule: snapshot reward modifiers before mutating pickup progression, reduce repeating phase indices to their documented period, and separate animation timing from render visibility at framebuffer boundaries.

Citation: src/main.s PICKUP_MULTIPLIER and death_tick; user CoCo playtest 2026-07-23.

DoD anti-patterns we will NOT copy

Filed 2026-05-08 alongside ingest of the DoD cartridge source. See sources/dod-source and coding-conventions for what we are adopting.

Tape (cassette) I/O

DoD carries a substantial cassette save/load layer in COMMON.ASM:24-96 (GETBUF, PIATAP, SAVE, LOAD) plus the entire PZTAPE.ASM module. Skip entirely. We are cartridge-only with no persistence in v1 (decision locked 2026-05-07; see log entry and platform/cartridge).

CoCo 1/2 SAM and legacy PIA initialisation

DoD's ONCE.ASM:31-49 writes a hard-coded SAM/PIA configuration aimed at CoCo 1/2 hardware. The CoCo 3's GIME (ACVC) supersedes the SAM and the PIA layout is largely the same but with extensions (CoCo 3 GIME reference, CoCo 3 input reference). Do not adapt this routine line-for-line. Re-derive boot init from the GIME register catalog and our cartridge boot strategy (platform/cartridge).

3D vector-graphics macros

VCTLST.ASM and the SVORG / SVECT / SVEND macros in missing-macros.asm implement DoD's first-person dungeon-vector renderer. Lady Bug is tile-based 2D — none of this applies.

24-bit fixed-point shift chains

HUPDAT.ASM:29-67 does multi-byte LSL/ROL chains for heartbeat-rate scaling. Elegant but specific to DoD's analogue-feeling timing. Unless we add fade effects or analogue-feeling animations, integer counters are simpler and faster.

BASIC ROM trampolines

Various DoD spots dispatch into BASIC ROM (BLKIN/BLKOUT, SWI2 to BASIC). We've already locked all-RAM mode post-boot (platform/cartridge, 2026-05-07 boot decision), so anything that re-enters BASIC ROM after init is unavailable to us by design. Don't borrow patterns that assume it's there.

SWI / IRQ vector collision — RESOLVED

Filed 2026-05-08 at the Phase 1 review gate, deferred from coding-conventions §4.

LDD ,Y++ clobbers B — never use B as a loop counter alongside it

Filed 2026-05-08.

In the Phase 2.4 blit_tile routine the obvious shape was ldb #8 outside the loop, decb/bne at the end. Inside the body, ldd ,y++ reads tile data into D — and D is A:B, so every ldd ,y++ overwrites the loop counter with whatever low byte was just loaded. For a solid-$33 tile the counter resets to $33 every iteration, decrements to $32, and the loop never terminates (or terminates non-deterministically based on tile content). The bug was invisible to static reading and produced confusing partial-render symptoms that varied by tile data.

Fix used in blit_tile: compute leau 32,y before the loop (sentinel = end of tile data), pshs u, then cmpy ,s / blo btrow for loop control. Y is the natural cursor and Y vs ,s is unaffected by ldd. Costs 2 stack bytes, returns them with leas 2,s.

Why: the 6809 D register is the concatenation A|B; any 16-bit load through D destroys both halves.

Applies to: any tight blit/copy loop that uses ldd ,y++ or ldd ,x++ for the data and B for iteration counting. Use a stack/memory sentinel or use Y/X comparison instead.

Citation: src/main.s blit_tile; debugged in the 2026-05-08 session.

Former cart-shadow self-copy did not populate RAM

Filed 2026-05-15. Four-pass gdb-mcp investigation in backlog/cart-ram-corruption settled this empirically.

The boot model from memory-map — "self-copy $C000-$FEFF to shadow RAM, flip TY=1, run from RAM" — does not describe how XRoar 1.10 actually runs our cart. Cold-start probes show cartridge bytes directly while TY=0. After TY=1, the mostly matching bytes come from the RAM shadow that the CoCo 3 reset ROM had already copied and patched. The self-copy's std ,x writes for x in $C000-$FDFE go to cart_rom_write (a no-op on a read-only rombank_d8) and skip the RAM-write path because the GIME decode returns RAS=0 for that range pre-SAM_ALLRAM. We have been depending on the reset-created shadow after the mode switch, not on Ladybug's copy. The Phase 2.1 "wrote a marker, flipped TY, read it back" verification is consistent with this — it cannot distinguish "Ladybug populated shadow RAM" from "the reset ROM had already put a matching byte there".

$FE00-$FEFF is the exception: MC3=1 forces RAS=1 in the inner decode, so reads and writes hit bank-0 RAM symmetrically. The IRQ jump-table slots ARE RAM-backed.

Why: XRoar's coco3.c read_byte / write_byte use a S=1 (CTS), RAS=0 path for the cart window under our boot state; the if (RAS) RAM-overlay block is skipped on reads and writes. cart_rom_write → rombank_d8 is read-only. So nothing the boot does to $C000-$FDFF while TY=0 reaches internal RAM. TY=0 reads come from the cartridge; TY=1 reads come from RAM.

Applies to:

  • Don't put self-modifying code at $C000-$FDFF — it will silently fail on XRoar.
  • Don't expect runtime-mutable data tables in that range under emulation.
  • The obsolete $C0DC fill was removed. The old $C0D9-$C0DB mismatch came from the BASIC-patched all-RAM shadow; the active TY=0 boot reads cartridge bytes directly.
  • The CoCo and CoCo 3 manuals describe TY=0 as selecting ROM or the cartridge rather than internal RAM. That supports XRoar's no-write-under-ROM behavior; physical CoCo 3 and CoCoSDC verification remains deferred to Phase 10.
  • Trust empirical gdb-mcp probes over XRoar source review for GIME questions; the source has a known decode gap we couldn't fully resolve (see memory-map §Open items).

The gdb channel itself is sound: the 16-byte palette at $FFB0..$FFBF reads back byte-for-byte, and the PARs at $FFA0..$FFA7 return the GIME reset state 38 39 3A 3B 3C 3D 3E 3F (linear-64K mapping; PARs are R/W).

Why: real GIME registers in the $FF90/$FF98..$FF9E block are write-only; XRoar's stub does not maintain a shadow on the host side, so reads pass through to whatever the emulator returns for inaccessible bus addresses (here, a fixed $1B). Same as on real hardware — there is no readback path in silicon either.

Applies to: WS-A of the emulator-monitor-tester initiative — the decision gate between strategy options 1/2/3 for GIME-state visibility. Option 1 (DirectReadStrategy) is not viable on XRoar. Decision: WS-A adopts Option 2 (ProgramStateStrategy) — the tester ROM exports tester_mode_idx + tester_mode_table symbols and the backend reads program state via those symbols. Option 3 (software shadow block) remains available for future generalization but is not needed for the tester.

Citation: probe script web/scripts/probe_gime_readback.py; writes performed at src/diag_minimal.s:39-93; strategy table in emulator-monitor-tester §WS-A.

XRoar gdb stub is hostile to mid-run inspection

Filed 2026-05-16.

Three observed behaviors that constrain how we write gdb-driven probes against an XRoar instance:

  1. -exec-interrupt is not honored while the target is free-running. The MI command sits without reply, eventually timing out at gdb's wait. Bug or stub limitation — unclear. Workaround: use a halt-on-*stopped mechanism (breakpoint) rather than asynchronous interruption.

The probes under web/scripts/ are written around these constraints — they sample state on the attach-halt and accept reduced coverage of mid-run behavior. Cart-window write decode — root cause of the cart-shadow no-op

Filed 2026-05-16. Refines the earlier 2026-05-15 Cart-shadow self-copy is a no-op under XRoar 1.10 entry by naming the precise cause from source review.

Traced through docs/reference/xroar/src/ for a CPU-space write at $C100 with TY=0 (cart attached) under our boot state:

  1. tcc1014/tcc1014.c:711-739 — GIME address decode: bank = 0x38 | (A>>13) = 0x3E. Line 729 branch !TY && bank >= 0x3c is taken, setting S=1 (CTS, cart). RAS stays at its line 712 init value of 0 — line 736 (the else branch that sets RAS=1) is not reached.
  2. coco3.c:1170-1240 — write_byte dispatches on S. With S=1 it calls cart->write (cart.c:955-959), which for a ROM-type cart routes to rombank_d8 (rombank.h:102-107) — a no-op on a read-only bank.
  3. Line 1227 in coco3.c is if (mcc3->GIME->RAS) { ram_write }. RAS=0 → RAM-overlay write skipped. No write reaches RAM.

$FE00–$FEFF writes work only when MC3=1; that path at tcc1014.c:720-723 fires before the TY/cart logic and forces RAS=1, sidestepping suppression. Outside that 256-byte window there is no other code path that writes RAM while the cart S-line is selected.

The author's comment at coco3.c:1242-1253 acknowledges the bus simplification: "Of course, I do none of that here … Good enough?"

Why: XRoar implements ROM/CTS selection via the S signal and the MC3 override for $FE00-$FEFF. Under TY=0, selecting CTS leaves RAS inactive, so a write is presented to the cartridge and not to internal RAM. This agrees with the CoCo 1/2 manual's description of TY=0 address decoding and the cartridge data bus: a cartridge RAM or PIA may accept the write, while a ROM cartridge ignores it. The CoCo 3 manual likewise describes physical pages $3C-$3F as ROM, not RAM, in ROM/RAM mode. Hardware verification is still deferred.

Verdict: Intentional simplification in XRoar, not a bug, and not faithful to real CoCo 3 silicon — which accepts writes into DRAM regardless of TY (the SAM/GIME's ROM redirect is read-only; writes always reach physical RAM).

Applies to:

  • Confirms the XRoar monitor protocol's physical-space write API as the correct primitive: it bypasses XRoar's bus decode and writes the emulator's RAM array at the 19-bit physical address. That lets the monitor honor hardware semantics even where XRoar diverges.
  • CPU-space writes to ROM-backed addresses should return read_only_region (predictable, matches what XRoar will do regardless).
  • Real-hardware behavior of the same path is unverified — Phase 10. A MAME comparison test (backlog/mame-cart-ram-comparison) is filed to cross-check before then.

Citation: XRoar 1.10 source — tcc1014.c:711-739, coco3.c:1170-1253, cart.c:955-959, rombank.h:102-107. Investigation logged 2026-05-16 during XRoar monitor Phase 1 requirements work.

Nested Unix repo on Windows: disable core.autocrlf before WSL build

Filed 2026-05-17 during Phase 3 M1 XRoar bring-up.

The nested XRoar checkout under docs/reference/xroar/ was cloned on Windows with the global default core.autocrlf=true, which rewrites LF→CRLF in the working tree. The first WSL build attempt died immediately: 

$ ./autogen.sh
bash: ./autogen.sh: /bin/sh^M: bad interpreter: No such file or directory

autogen.sh, configure, libtool helpers, and many other shell scripts in autotools projects are sourced as /bin/sh under WSL — CRLF line endings make the kernel try to load /bin/sh\r as the interpreter, which doesn't exist.

Fix (per nested repo):

git config core.autocrlf false
git rm --cached -rq .
git reset --hard HEAD

This is local to the nested repo, so the parent Ladybug repo's autocrlf behavior is unchanged. After the reset, file autogen.sh reports POSIX shell script, ASCII text executable (no CRLF) and the build proceeds.

Why: Windows-native git tooling treats LF/CRLF as a presentation concern, but Linux interpreters treat \r as part of the path. WSL bridges both worlds, so any nested repo whose build runs under WSL must keep LF endings on disk.

Applies to: any shell script executed through WSL. The Ladybug repository now enforces *.sh text eol=lf in .gitattributes; nested third-party repositories still require their own attributes or core.autocrlf=false.

Citation: XRoar bring-up under WSL, log.html 2026-05-17 entry.

XRoar monitor stub serializes requests per connection — never long-poll on a shared socket

Filed 2026-06-11.

The monitor protocol's per-client worker (handle_connection in monitor.c) is a strict read_line → dispatch → reply loop. A pending wait_for_stop(timeout_ms) long-poll therefore blocks every subsequent request on that connection for up to the full timeout — including the pause that would have satisfied the poll, which sits unread in the socket buffer while the poll runs out its clock. The web backend's halt watcher long-polled with timeout_ms=30000 on the same connection the UI commands use, so breakpoint clicks during free-run stalled ~30–60 s and then "caught up" all at once. Verified by web/scripts/probe_monitor_serialization.py: a get_run_state sent 0.3 s after a wait_for_stop(8000) was answered 7.7 s late, and a pause was starved behind its own poll.

Two corollaries. First, async event push (send_event_to_subscribers) uses pthread_mutex_trylock on the client's write mutex and silently drops the event if the worker is mid-reply (dropped_events++), so bp events are best-effort and cannot be the sole halt detector. Second, the fix: the session's halt watcher now polls get_run_state (which replies immediately) every 250 ms; bp events remain the low-latency path and the poll is the drop-proof fallback.

Why: worker-per-client (M6a) parallelizes across clients, not within one connection; JSON-RPC 2.0 framing permits pipelining but the server replies strictly in order, and the Python session layer wrongly assumed out-of-order service.

Applies to: web/backend/monitor_session.py (halt watcher, _call concurrency comments), any future monitor client; also any new long-poll-style protocol method.

Citation: docs/reference/xroar/src/monitor.c (handle_connection, send_event_to_subscribers); web/scripts/probe_monitor_serialization.py; log.html 2026-06-11 entry.
