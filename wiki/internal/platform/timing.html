Timing — frame budget internal

Project-specific decisions on clock rate and interrupt source, plus the Phase 1 frame-budget partition.

Reference content (clock options, IRQ sources, 6809 IRQ/FIRQ timing) is in release/reference/coco3/timing.

Clock rate — locked at 1.78 MHz

Ladybug will run fast — we don't enter BASIC ROM I/O. Decision rationale: doubling the budget halves the cost of every cycle-counting decision and brings Lady Bug's 60-Hz arcade frame within easy reach.

Interrupt source — locked: ACVC Vbord

Decision: Ladybug's main game tick = ACVC Vbord IRQ. That gives us a clean 60 Hz frame interrupt; everything else (animation, AI, input poll, sound dispatch) runs from the same handler. A few µs of jitter to account for: an FIRQ for serial / cartridge can preempt the main IRQ; that's intentional and matches the IRQ < FIRQ < NMI priority order.

Frame partition (first-pass)

A forced four-record XRoar -trace snapshot measured 26,404 executed instructions on a normal enemy movement frame. A frame where movement coincided with additional animation work reached 31,389. These are instruction counts, not cycle estimates; because every 6809 instruction costs more than one cycle, both conclusively exceed the 29,666-cycle 60 Hz budget.

The behavior-preserving attack order is: remove the duplicate old- background restore, skip nest composition when only roaming pixels changed, pre-expand low-RAM cached frames to native 4bpp, and replace per-row shadow-window mapping with page-segment copies. Rectangle coalescing is deferred until the lower-risk changes are measured.

First optimization completed 2026-07-23: roam_prepare_shadow previously ran two adjacent loops that restored the same valid old roaming backgrounds with no intervening framebuffer mutation. It now performs one restore pass, removing 38 bytes from the bank-3 module and one 128-byte background copy per established roaming enemy. The four-enemy estimate is approximately 712 instructions saved. The guarded build, GMC trace proof, enemy-runtime contracts, and a live m6809 GDB-MCP attach passed; a fresh frame trace remains required before replacing the original measured totals.

Second optimization completed 2026-07-23: direct-page byte $60 now means nest/animation dirtiness only, while $61 independently requests roaming movement. Movement-only frames still restore, save, draw, and publish roaming unions but branch over compose_enemy_zone. Animation, release, vegetable, skull, death-reset, and retained-background changes still compose the nest. A live GDB-MCP probe stopped after the bypass with $60=0/$61=1, then stopped inside nest composition on an animation frame with $60=1. This targets approximately 3,297 instructions on applicable frames and costs six bank-3 bytes; fresh frame tracing remains the measurement gate.

Third optimization completed 2026-07-23: the bank-2 atlas remains packed at 64 bytes per frame, but each of five low-RAM cache slots expands through sprite_attr0_pairs to a native 128-byte 4bpp frame only when its type/direction/animation key changes. Enemy framebuffer and nest draws now consume the native cache directly; player, vegetable, score, and other packed paths are unchanged. The cache grows from 320 to 640 bytes and leaves a 1,402-byte stack gap. A live slot-4 dump matched an independent expansion of bank-2 frame 3 across all 128 bytes, and XRoar was observed executing the native nest blitter. The bank-3 module is 2,751 bytes. A forced four-enemy frame trace is still required to quantify the hot-path reduction.

Player-cache extension completed 2026-07-23: the selected 64-byte packed player frame now expands into a single 128-byte native cache only when PLAYER_FACE*4+PLAYER_ANIM changes. The 30 Hz off-screen player compositor uses the native compact-stage blitter, and resident gate/respawn/popup redraws obtain the same cache through the seventh bank-3 ABI entry. The remaining stack gap is 1,273 bytes. A live cache dump matched generated player frame 3 across all 128 bytes while XRoar executed the native hot compositor. Resident use is 8,071 bytes and bank-3 use is 2,801 bytes. Re-profiling remains required for measured savings.
