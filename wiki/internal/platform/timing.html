Timing — frame budget internal

Project-specific decisions on clock rate and interrupt source, plus the Phase 1 frame-budget partition.

Reference content (clock options, IRQ sources, 6809 IRQ/FIRQ timing) is in release/reference/coco3/timing.

Clock rate — locked at 1.78 MHz

Ladybug will run fast — we don't enter BASIC ROM I/O. Decision rationale: doubling the budget halves the cost of every cycle-counting decision and brings Lady Bug's 60-Hz arcade frame within easy reach.

Interrupt source — locked: ACVC Vbord

Decision: Ladybug's main game tick = ACVC Vbord IRQ. That gives us a clean 60 Hz frame interrupt; everything else (animation, AI, input poll, sound dispatch) runs from the same handler. A few µs of jitter to account for: an FIRQ for serial / cartridge can preempt the main IRQ; that's intentional and matches the IRQ < FIRQ < NMI priority order.

Frame partition (first-pass)

29 666 cycles per frame at 1.78 MHz × 60 Hz. Will be revisited by coding-architect:

Next renderer optimization analysis — 2026-07-23

The remaining shadow path is dominated by its per-byte loop rather than mapper setup. Across four 144-byte imports and four publications, the six byte-loop instructions account for 33,408 of 39,640 cycles. The roaming unions are constrained to either 8 bytes by 18 rows or 9 bytes by 16 rows. Add roaming-only word-copy kernels that transfer four LDD/STD pairs per row plus the ninth byte when required. Test once per row for the rare physical-page crossing and retain the existing byte splitter for that row. Keep the generic rectangle copier unchanged for gate and player regions. Static modeling of the captured frame reduces this path to approximately 15,700 cycles, saving about 24,000 cycles or 60%.

The native framebuffer blitter processed 512 cached bytes: 224 were fully transparent, 224 were fully opaque, and 64 contained one transparent nibble. Its current mask-building loop costs 24,064 of the routine's 25,580 cycles. After the word-copy change, specialize this loop with a B-register byte counter, skip zero bytes, store fully opaque bytes directly, and use a destination mask only for the 64 partial bytes. The captured distribution predicts approximately 9,800 additional cycles saved without changing cache layout or using more RAM.

The recommended order is word-copy roaming transfers, re-profile, then sparse native blitting. The two modeled changes together reduce the measured frame from 81,370 to approximately 47,600 cycles. This fits the 59,332-cycle aggregate envelope of the existing 30 Hz movement cadence but not one 29,666-cycle Vbord interval. Meeting a strict single-Vbord limit requires a later ownership change such as persistent ping-pong framebuffers with per-buffer save-under state; that is a renderer protocol refactor, not a local kernel optimization.

The viable incremental change is layout-only: place sbf_partial before sbf_row, branch over it once at decoder entry, and let every completed partial command fall through into the row parser. This removes 80 return branches at a cost of four entry branches, for a projected net saving of 228 enemy cycles. It exchanges one two-byte branch for another and is therefore code-size neutral at 4,048/4,096 bank-3 bytes. The projected enemy path is 12,079 cycles and the complete A-owner frame is approximately 34,939 cycles, still 5,273 over the strict gate.

Length-one or length-two dispatch is rejected: the comparison cost paid by all 80 commands cancels the avoided loop control. Mask- orientation commands are also rejected. Across all 128 frames, 452 of 2,688 partial commands mix $F0 and $0F masks; splitting them creates 524 extra command runs. In the measured frames it creates 14 extra runs, and their approximately 25-cycle command-parser cost consumes the four-cycle-per-byte immediate-mask opportunity. A partial-only change therefore cannot close the frame budget; the broader row/command interpreter costs 5,756 enemy cycles and is the next architectural target.

The viable interpreter redesign is a destination-delta stream. Keep the existing length/type byte and payload bodies, but replace each row start with the unsigned framebuffer delta from the prior command end. Register X becomes the advancing destination cursor, so a normal command uses LDB ,U+, sentinel test, ABX, then the unchanged type/length load. Delta $FF escapes to a 16-bit framebuffer delta plus an 8-bit compact-stage delta; a zero framebuffer delta ends the frame without the stage byte. Normal cross-row deltas are 152-167, so the stage decoder obtains its equivalent by subtracting 152; the explicit stage byte handles skipped rows. Only two long escapes occur in frames 5/1/1/13. The static model removes 1,576 enemy cycles and 404 player cycles from the captured frame. Across all generated actors it also removes 1,647 payload bytes, increasing readable GMC spare space from 1,018 to approximately 2,665 bytes. The design retains the current index, partial encoding, and both framebuffer/stage destinations.

Two adjacent paths have higher aggregate payoff. The captured owner physically exchanges the 128-byte A/B player save-under twice: 256 loop iterations consume 7,168 cycles, excluding call/setup overhead. Selecting PLAYER_BG or PLAYER_BG_B through an always-mapped direct-page pointer removes that copy while preserving buffer-local ownership. The horizontal circular-strip loop consumes 4,800 cycles across four enemies because every row recomputes base + row*8. Computing the physical column once and copying the tail/head row segments linearly models the loop at roughly 1,664 cycles, saving about 3,100 cycles on the captured phase-zero path. Vertical movement keeps the existing generic row capture.

Owner-selected player save-under implemented 2026-07-26: direct-page pointer $00A2 selects $A300 or $AB00 during BACK preparation. Resident player save/restore and bank-3 player composition now use the selected pointer, and frame completion leaves both owner-local buffers stationary. This removes the measured 7,168 swap-loop cycles plus call/setup overhead from the affected owner. Destination delta, segmented capture, and mirrored index implemented 2026-07-26: exact generated payloads are now 22,683 enemy bytes and 2,294 player bytes, 1,649 bytes below the row-framed form and leaving 2,667 readable GMC bytes spare. The framebuffer decoder advances X directly; the stage decoder translates shared adjacent-row deltas and consumes explicit stage deltas only for long escapes. Enemy/player indexes are mirrored into always-mapped $0500/$0680, removing index-page mapping and three direct page scratch bytes. Decoder termination performs the single restore to game-state page $34. Holding a sparse page across actor draws is not valid because frame selection and actor orchestration access page $34 between calls.

Horizontal circular capture now computes ring + row_phase*8 + column_slot once, copies 16-row_phase rows linearly, wraps by 128 bytes, then copies the remaining row_phase rows. Vertical capture is unchanged. The independent model covers all sixteen row phases and eight column slots. The prior static cycle estimates require a fresh complete-frame profile before strict-budget acceptance.

Destination-delta streams, segmented horizontal capture, and always-mapped index resolution are implemented. Cross-actor payload-page batching remains invalid without first relocating or staging the page-$34 actor state used between draws. Duplicate-frame multi-draw and partial-mask stream splitting remain situational or negative.

Strict-60-Hz architecture designed 2026-07-23: the persistent ping-pong framebuffer removes normal shadow import/publication by rendering directly into the non-scanned physical framebuffer and selecting it with one $FF9D write at bottom-border Vbord. Per-buffer actor history and damage ledgers keep the older snapshot convergent. Precompiled sparse enemy/player streams and strip-updated circular save-under state provide the additional reduction required beyond the 39,640-cycle copy removal. The modeled steady four-enemy range is 24,500-27,500 cycles; implementation must prove every steady path below 29,666 cycles. In the accepted overload protocol, raw Vbord continues counting but simulation advances once per committed image. A missed Vbord freezes the current logical/render epoch until it commits instead of skipping transient states or catching up timers.
