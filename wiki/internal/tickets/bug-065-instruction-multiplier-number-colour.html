BUG-065 — Match instruction multiplier digits to the blue X Proposed

2026-10-01 · P2 · Standard · Proposed · RSCH-014 Step A

Approval brief

Objective and motivation

Color the multiplier numerals 2, 3 and 5 blue wherever the instruction screen shows them beside the blue X glyph.

Evidence, reproduction and cause

Two source paths currently disagree. In the left template multiplier legend, presentation_pen_map makes the X blue while other glyphs on the y=7 row fall back to grey. In parse_instruction_contract, generated multiplier composites map the X to BLUE but the following numeric tile to WHITE. The static instruction frame is in instructions-static.png; current author/map hash is recorded in snapshot.json.

Scope

In: the template X2/X3/X5 multiplier legend and generated runtime multiplier replacements in both point rows. Out: 10/100 point-award digits, ordinary point values, heart colors, trigger order and multiplier scoring.

Design and prototype

Use the existing BLUE pen index for each multiplier digit, matching its adjacent X. Restrict the map override to the semantic multiplier legend row and the generated multiplier digit tiles; do not recolor an entire instruction row or all numeric characters.

Scenarios and edge cases

  • Template X2, X3 and X5 use the same exact blue pen for X and numeral; unrelated legend text is unchanged.
  • Generated X2/X3/X5 heart-row overlays use the same blue pen for X and numeral on every publication; point-award numbers keep their authored colors.
  • Static compiler comparison reports only the approved multiplier pixels changed; both authored multiplier destinations and the current movement/color schedule remain unchanged.
  • Existing instruction verifier, current complete build/capacity guards and natural instruction capture pass after FEAT-005/layer integration.
