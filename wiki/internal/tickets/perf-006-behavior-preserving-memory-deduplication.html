Approval brief

Objective and motivation

Increase boot/cartridge and resident-code headroom by removing confirmed emitted-code duplication while preserving exact current application behavior. The resident window has four bytes spare, so bounded deduplication creates room for later correctness work without pulling PERF-005 forward or modifying known bugs.

Evidence and baseline

The certified DOC-002 source/artifact baseline is revision fac594fea1af6f33eb8bd60ed5d71c4f72eee16c; the assigned runtime baseline is its documentation-only descendant 038ef92. The inspected release artifacts report resident 8188/8192 bytes, assets 7144/7680, enemy runtime 4095/4096, presentation module 1276/1280, and perimeter helper 331/334. These are single artifact observations. Exact binary inspection confirms a 70-byte span duplicated at resident addresses $C454 and $C4B8, a 46-byte preparation span duplicated at $C952, $D489, and $D4B7, five identical 32-byte unrolled copy bodies in the boot loader, and a redundant tfr d,x / tfr x,d pair in the sparse-segment loader. Net savings remain projections until final maps are compared.

Scope

In: remove the redundant reverse transfer in src/gmc_bootstrap.s; share the identical HUD rendering tail used by draw_hud_digit and draw_recolored_map_tile; and share the identical tile preparation used by draw_perimeter_box, draw_cell_tile, and draw_cell_overlay. Out: enemy phase-copier changes, PERF-003 work, data compression, generated asset changes, runtime ownership/protocol changes, visible output changes, bug fixes, diagnostic/test-source removal, profile removal, and broad source-constant cleanup.

Scenarios and distinct risks

  • Loader transfer: clean GMC boot proves unchanged bank selection, staged bytes, all-RAM publication, final live bytes, entry address, and PAR5 restoration.
  • HUD helper: score/high-score digits, stage/vegetable digits, SPECIAL/EXTRA letters, and multiplier tiles prove exact source selection, destination addressing, and recolouring.
  • Tile helper: ordinary maze-cell restoration, transparent gate overlay, and perimeter recolouring prove exact tile ID, TEST coordinate, destination pointer, and source pointer behavior.
  • Natural integration: one boot-to-attract-to-gameplay sequence proves added calls preserve stack balance and the presentation/gameplay handoff.
  • Timing: no current accepted worklist maximum may be crossed in exchange for bytes.

Selected design and rejected alternatives

Use local shared implementation paths inside the existing modules. Preserve all register inputs, direct-page scratch, MMU/PAR ownership, destination calculations, and pixel loops. The HUD entries tail-merge only after each caller establishes its unique source identity. The tile callers use one documented local helper plus a 24-entry row-address table that offsets nearly all call/return overhead. The loader retains its unrolled copy bodies and changes only the redundant transfer. Macros are rejected because they retain emitted duplication. A generic renderer or new module is rejected because it broadens ownership. Enemy phase-copier consolidation is excluded because it belongs to PERF-003 and has different timing risk.

Acceptance criteria

  • The redundant loader transfer is removed and the assembled loader shrinks by at least two bytes.
  • The two resident transformations save at least 90 combined resident bytes; the audit projects approximately 107 bytes before final assembly.
  • Resident, asset, enemy, presentation, helper, loader-overflow, stack, direct-page, and GMC guards pass from a clean release build.
  • Authored, cartridge-staged, and live destination bytes pass existing GMC identity checks.
  • Named HUD, maze-cell, gate-overlay, perimeter, and natural integration results are pixel-identical to baseline or their independent oracle.
  • No existing timing target regresses past its accepted maximum; measured call overhead and headroom are recorded.
  • No behavior, bug status, runtime owner, ABI entry, generated format, or file outside the assignment allowlist changes.
