Approval brief

Objective and motivation

Update the RSCH-005 source-proof logic so its unchanged isolated timing command remains a valid regression after BUG-024 repairs the RSCH-004 loop. The current command correctly measures boundary/LDQ/STQ/pair/byte-equivalent controls, but exits nonzero because its historical proof requires ldb #Q_ROWS, DECB, and LDQ-before-DECB in the repaired-away loop.

Baseline and observed failure

Current RSCH-005 evidence retains medians 2/8/8/16/38/38, three identical samples, and zero timeouts. The command reports cause_confirmed=false only because the old source proof is false after BUG-024; the isolated control checks remain passing. BUG-024 evidence is ed1e647bfc0c8b269b1affff09c0efdabf46f4051ad21bce79b906274c4666b7.

Scope

In: update scripts/benchmark_6309_ldq_stq_timing.py to recognize either the retained pre-repair source proof or the BUG-024 direct-memory counter proof; rerun the unchanged RSCH-005 command; synchronize RSCH-005, BUG-024, the ticket index, tooling page, and log. Out: instruction timing changes, new probes, XRoar source, production assembly, ROM policy, native mode, hardware qualification, and changes to historical evidence.

Acceptance criteria

  • The runner reports the repaired loop proof as valid: direct-memory RESULT_Q_STATUS initialization, DEC RESULT_Q_STATUS, and BNE q_hot_row, with no DECB in the hot window.
  • The unchanged RSCH-005 command exits zero with three identical samples, zero timeouts, all control checks passing, and medians 2/8/8/16/38/38.
  • The historical B/DECB diagnosis and original RSCH-004 11119-cycle evidence remain retained and explicitly labeled historical.
  • No production source, release ROM, XRoar source, timing method, or separate-build behavior changes.
  • Python compilation, focused source assertions, balanced HTML, and local-link validation pass.

Risks and exclusions

The main risk is weakening the proof so an unrelated loop passes. The repair proof must require the exact direct-memory counter and branch sequence in the RSCH-004 hot window. This ticket does not authorize a new benchmark harness or another timing experiment.
