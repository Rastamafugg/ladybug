Confirmed source defect

The generated timer record is a four-byte pair: destination address followed by a 16-bit pointer to raw green tile bytes. scripts/build_presentation.py:2044-2053 appends framebuffer_destination(cell) and name_entry_timer_tiles_offset + green_index * TILE_BYTES. A historical generated include example has 92 records (368 bytes), with first record 20 50 2C 90 (destination $2050, raw tile pointer $2C90); generated outputs were not rebuilt for this investigation.

The active complete shared-text helper is selected by src/demo_runtime.s:2-8 and includes src/shared_text_stage.inc when HIGHSCORE_PHASE_HELPER is set. In src/shared_text_stage.inc:148-161, the consumer loads the destination into Y, then executes LDB 3,X, and calls PRES_MODULE_DRAW_TILE. The active complete dispatcher in src/shared_text_runtime.inc:30-42 interprets B below 174 as a graphic ID and computes B*32 before calling the shared cold pointer; the resident-side tile path has the same ID contract at src/presentation_runtime.s:2289-2323. Therefore the pointer low byte is incorrectly treated as a graphic ID. This is a confirmed source-level cause for unrelated art in timer squares; runtime reproduction remains unclaimed.

There is a second, independent defect in the page-$23 helper copy at src/shared_text_stage.inc:154-161 and src/shared_text_ranking.inc:154-161: after the record load, LDD #highscore_after_tile overwrites both A and B, and the following LDD #PRES_MAIN_PAGE23_RESUME overwrites them again. The final tile argument at the draw jump is LOW(PRES_MAIN_PAGE23_RESUME), regardless of the record contents. src/demo_runtime.s:156-170 duplicates this sequence. This explains deterministic unrelated tile selection even if the record encoding were otherwise accepted; do not describe the earlier LDB 3,X value as correct.

Remapping and stale-ID assessment

Tile remapping is not the primary defect. scripts/build_presentation.py:1930-1953 remaps timer base IDs, then deliberately clears timer_green_tile_ids after the green variants have been deduplicated into timer_green_tiles. The later table emission at 2044-2053 stores raw green-surface pointers, not IDs. The current source therefore has a producer/consumer format mismatch before any stale-ID or atlas remap question can arise. The timer base IDs are not consumed by the timer record path.

Rejected explanation: a simple stale generated timer include is insufficient. The authored generator and all three current timer consumers agree on the four-byte pointer-shaped record only accidentally; the consumer explicitly treats byte 3 as an atlas ID. Rejected explanation: green palette generation alone. replace_packed_colour(... WHITE, GREEN) at scripts/build_presentation.py:1780-1786 produces a valid native green surface, but that surface is never selected by the draw consumer when it receives the pointer byte as an ID.

Repair direction and smallest future runtime check

Repair direction: choose one ABI and enforce it at generation and consumption. The smallest coherent direction is for the timer consumer to use the record's 16-bit source pointer as Y (with destination preserved separately) and call a raw native-tile blitter, or alternatively emit/remap a one-byte atlas ID and keep the existing graphic-ID ABI. The helper continuation address must be installed without clobbering the tile argument. Parent review must select the direction before implementation.

Smallest future runtime check: during the enter-high-score phase, within a 60-second probe deadline, force the first timer record on both framebuffer owners, stop immediately before the draw call, and verify that the record's cold-payload offset maps to the generated first green-tile bytes and that the destination is $2050. Then execute one draw and compare the destination's 32 bytes against a software native blit of that same source. A timeout means the probe boundary or callback path was not reached, not that the timer is slow. Residual uncertainty: this source report cannot establish live mappings, callback register preservation in the loaded artifact, or framebuffer publication behavior.

Conclusion

The unrelated timer art has a confirmed source defect: raw green-tile pointers are passed through an atlas-tile-ID ABI, and the helper callback setup then overwrites B again. Stale-ID remapping and framebuffer-owner history remain secondary runtime checks after the ABI is repaired.
