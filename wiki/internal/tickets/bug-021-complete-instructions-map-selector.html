Preserve the requested presentation map ID across the complete-profile instruction-runtime installation.

Approval brief

Objective and motivation

Make the LADYBUG_PROFILE=complete presentation path load the authored instructions map instead of reading a stream pointer from outside the map-offset table. The current failure prevents the combined profile from reaching a valid instructions screen.

Evidence and baseline

Current complete artifact revision is the uncommitted main checkout build with ROM SHA-256 de0339c501cc49d059074987becd3bdc60a46467fe49fdcae3b410b8ea50cccc. The staged page-$23 actor/runtime bundle matches its authored concatenation byte-for-byte. In src/presentation_runtime.s:279-290, start_screen stores the requested ID in PRES_SCREEN, then the complete-only instruction path calls install_instruction_runtime. That routine restores PAR5 by loading $34 into A; the following tfr a,b therefore selects offset $68 rather than map ID 1. The valid map_stream_offsets table is at $1DAC-$1DB7, so the indexed read is outside the table. This is a confirmed source-level cause; no hardware defect is implicated.

Reproduction

  1. Build with LADYBUG_PROFILE=complete bash scripts/build.sh build.
  2. Run the combined image through the attract-to-instructions transition.
  3. Observe garbage or a stalled/crashed instructions display.
  4. Inspect start_screen after the instruction install call; A contains restored PAR5=$34, not the requested map ID.

Observed versus expected

Observed: the complete-profile instruction install clobbers the map selector before map_stream_offsets is indexed. The staged runtime identity is correct, so the failure occurs after delivery at the presentation handoff.

Expected: requesting map ID 1 preserves that selector, sets PRES_IN to PRESENTATION_MAP_STREAM_1, loads the authored instructions screen, and reaches instructions_tick with the installed runtime present at $0300.

Scope

In: the accumulator/register-preservation correction in src/presentation_runtime.s, complete-profile instruction transition verification, regenerated complete artifacts, and synchronized ticket/wiki evidence. Out: demo behavior, release/development profile semantics, framebuffer protocol, loader packing, MMU layout, authored map data, and unrelated visual changes.

Scenarios and edge cases

  • Complete profile requests attract map ID 0 and still selects stream 0.
  • Complete profile requests instructions map ID 1 after installing the instruction runtime and selects stream 1.
  • Level-start map ID 2 and later demo-runtime installation remain unchanged.
  • Release and development builds retain their existing auxiliary ownership and map behavior.
  • Authored, staged, and live instruction-runtime bytes remain identical before interpreting rendering results.

Options and recommendation

Recommended: preserve or reload the requested map selector across install_instruction_runtime before indexing map_stream_offsets. This is the smallest compatible correction and does not alter memory ownership or the runtime ABI.

Rejected: changing the map table or padding data around the out-of-range index, because that masks register corruption and can affect unrelated map IDs.

Discriminating test

Force start_screen with A equal to 1 in the complete image, verify the instruction runtime destination bytes, then verify PRES_IN equals the generated stream-1 address and that the next load phase reaches instructions_tick. A live-byte mismatch or missing transition fails the test.

Acceptance criteria

  • Complete-profile instructions transition reaches instructions_tick without garbage output.
  • PRES_IN selects stream 1 after runtime installation.
  • Installed instruction-runtime bytes match the authored/staged runtime.
  • Complete presentation and sparse proofs pass, and the combined build remains within all existing limits.
  • Release and development builds and their existing focused checks pass unchanged.
  • Completion evidence records the ROM hash, source/staged/live identities, transition marker, capacity, and residual risk.
