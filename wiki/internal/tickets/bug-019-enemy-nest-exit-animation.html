BUG-019 — Enemy nest exit lacks continuous underlap animation Proposed

Animate the released enemy from beneath the dormant nest actor through the existing north exit lane.

Identity and ordering

  • Status: Proposed; explicit approval required.
  • Created / updated: 2026-08-14 / 2026-08-14.
  • Priority / order: P1 / 12.73.
  • Owner: unassigned.
  • Parent: FEAT-002.
  • Dependencies: integrated BUG-014 release timing; coordinate BUG-018 colour oracle.

Approval brief

Objective and motivation

At the first valid timer release, show one enemy beginning beneath the dormant dummy enemy, then walking continuously north and out of the nest. This supplies the missing visible release choreography without changing eligibility or AI.

Reproduction and observed versus expected

  1. Run the integrated demo or credited level one.
  2. Wait through all 92 timer advances to the first valid release.
  3. Observe the nest and north release lane on each committed frame.

Observed: release creates the active record at cell (12,12), direction north. The compact nest compositor draws active actors before the dormant actor, which establishes the required underlap, but computes vertical displacement as phase scanlines while movement changes the framebuffer address by two scanlines per phase. The actor therefore advances 1, 1, 1, then 5 scanlines across a cell boundary instead of four uniform two-scanline steps. Persistent actor rendering takes over near the nest boundary and can alter overlap order. Expected: four continuous two-scanline steps per cell, with the dormant actor remaining above the released actor for every overlapping pixel until the released actor clears the nest.

Golden path

  1. Timer expiry activates exactly one enemy at the existing release cell.
  2. The active sprite is initially under the dormant dummy.
  3. Each committed movement phase advances it north by two scanlines.
  4. The dormant actor remains independently animated and painted above it while they overlap.
  5. Ownership transfers to ordinary maze actor rendering without a jump, duplicate, missing frame, or changed route.

Scope

In: nest-local phase interpolation, active/dormant painter order, compact-to-persistent renderer handoff, live/demo parity, both framebuffer owners, capture evidence, timing, and capacity. Out: release eligibility/cadence, enemy path selection or speed, maze geometry, dormant animation design, and palette selection owned by BUG-018.

Edge cases and risks

  • The released and dormant actors may use the same pixels during several phases; draw order is part of acceptance.
  • The compact and persistent renderers must not both expose the actor or omit it at their ownership boundary.
  • Multiple released enemies, death reset, part restart, vegetable overlay, and reversed framebuffer owners must retain current state.
  • Extra overlap work can increase the existing missed-commit count or overflow the 4096-byte enemy region.

Recommendation

Use the movement service's two-scanline phase unit in the compact compositor and make one renderer own each released-actor phase while preserving dormant-last painter order inside the overlap zone. Do not add a presentation-only animation.

Acceptance criteria

  • The first eligible release remains after 92 timer advances at nine committed frames per advance and activates exactly one enemy.
  • Committed release frames show uniform northward positions at 0, 2, 4, and 6 scanlines within each cell.
  • The dormant actor visibly overpaints the released actor wherever their opaque pixels overlap.
  • The compact-to-persistent handoff has zero discontinuity, duplication, or missing actor frames.
  • Natural live/demo, multiple-release, death/restart, both-owner, timing, capacity, BUG-014, BUG-012 loop, build, and GMC checks pass with no new missed commits or FRONT writes.

Discriminating test

Capture every committed release phase with actor records and physical framebuffer crops. Require two-scanline deltas and compute overlap pixels against an independent dormant-last composition oracle. Mutating the compact displacement to one scanline or reversing overlap order must fail.

Assignment contract

Not prepared. Ready preparation must fix owned artifacts, renderer ownership boundary, exact commands, capture format, capacity limits, worktree, commit boundary, and completion report.

Verification plan

Static phase oracle; natural first release; live/demo comparison; physical crop sequence; compact/persistent boundary; multiple actors; death/restart; both owners; timing and packing; BUG-012, BUG-014, build, and GMC regressions.

Decision log
