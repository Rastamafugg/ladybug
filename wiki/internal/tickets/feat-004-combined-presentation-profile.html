FEAT-004 — Combine instructions and demo runtime Verification

Add a non-default complete build profile that includes the authored instructions screen and the deterministic demo runtime in one GMC image.

Objective and motivation

Provide LADYBUG_PROFILE=complete as a testable build profile whose natural presentation path can execute the authored instructions choreography and subsequently enter the deterministic demo loop without changing the existing release or development profile contracts.

Scope

In: profile selection, presentation conditional assembly, separate instruction/demo runtime assembly, page-$23 staging of both runtimes, phase-specific copying into the existing $0300-$06A9 overlay, manifest and sparse-loader verification, build documentation, and regenerated outputs. Out: making complete the default, restoring release game-over/name-entry behavior, changing gameplay rules, changing the framebuffer protocol, changing the runtime destination, or adding a second simultaneously resident low-RAM module.

Scenarios, edge cases, and failure modes

  • Cold complete boot reaches attract, then authored instructions, then level-start, then demo mode.
  • Instruction runtime is installed before its first tick; demo runtime is installed before its first demo tick.
  • Both auxiliary payloads reconstruct from the sparse loader and remain inside page $23; neither overwrites actor surfaces or the page boundary.
  • Development still installs only instructions, release still installs only demo, and both existing profiles retain their current map selection and module boundaries.
  • Warm/reset entry does not execute the previous phase’s overlay after a profile transition.
  • Any module, cold payload, resident, loader, GMC, or low-RAM boundary failure fails the profile build.

Baseline and targets

Current release source assembles a 1,276-byte presentation module and a 143-byte demo auxiliary. Current development source assembles a 1,114-byte presentation module and a 931-byte instruction auxiliary padded to the 938-byte reservation. The complete profile target is a presentation module at or below the existing $1900-$1DFF 1,280-byte boundary, instruction auxiliary at or below 938 bytes, demo auxiliary at or below 938 bytes, combined page-$23 staging below 8,192 bytes, and a 65,536-byte GMC image.

Design and capacity

The existing $0300-$06A9 allocation remains an overlay. Page $23 stores actor underlays and records followed by the padded instruction runtime and demo runtime. The presentation module uses one common copy loop with phase-specific source addresses and lengths: start_screen selects instructions, and the level-start-to-demo transition selects demo. The complete profile reuses development map selection, so game-over and name-entry remain explicit black placeholders and are not part of this ticket’s release restoration.

Rejected alternatives are simultaneous placement in low RAM, which exceeds the documented slot; a new runtime destination, which changes the ABI and memory map; and making release compile the instructions map, which changes the default release contract and does not solve the overlay ownership problem.
