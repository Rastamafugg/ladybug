BUG-020 — Death animation is one pixel left of the player Proposed

Give live and death frames the same authored horizontal origin.

Identity and ordering

  • Status: Proposed; explicit approval required.
  • Created / updated: 2026-08-14 / 2026-08-14.
  • Priority / order: P1 / 12.74.
  • Owner: unassigned.
  • Parent: FEAT-002.
  • Dependencies: coordinate natural-death evidence with BUG-012 and perimeter reset evidence with BUG-017.

Approval brief

Objective and motivation

Anchor every death frame at the exact horizontal location occupied by the live ladybug at collision, without moving gameplay collision state or changing the artwork.

Reproduction and observed versus expected

Observed: the entire death animation is one source pixel left. Build generation prepends one transparent pixel and truncates the right edge for every normal player frame, while death frames are compiled without that alignment transform. Runtime draws both at the same PLAYER_FB address. Expected: live and death artwork use the same horizontal source alignment at that address.

Golden path

  1. Capture the final live player frame and collision origin.
  2. Enter either enemy- or skull-caused death without changing PLAYER_FB.
  3. Draw every death phase from the same visual origin as the live frame.
  4. Restore or return through the existing death flow with no maze damage.

Scope

In: generated death-frame horizontal alignment, all death phases, enemy/skull causes, live/demo parity, both framebuffer owners, source/artifact oracle, timing, and packing. Out: player movement/collision coordinates, death timing, artwork redesign, perimeter reset geometry, and respawn behavior.

Edge cases and risks

  • A runtime address offset would hide the generator mismatch but make clipping and collision-origin reasoning inconsistent.
  • The rightmost source column must be proven transparent or handled without losing opaque pixels.
  • Every orientation-independent death phase and both causes require capture; one frame is insufficient.

Recommendation

Apply the established normal-player alignment transform to death source rows during generation, guarded by an opaque-pixel and width oracle. Do not alter PLAYER_FB or collision coordinates.

Acceptance criteria

  • All generated live and death frames share one declared horizontal origin and width.
  • Every enemy- and skull-death phase is pixel-aligned with the final live player origin.
  • No opaque source pixel is truncated and no maze pixel outside the sprite footprint changes.
  • Natural demo, forced causes, both owners, timing, packing, BUG-012, BUG-017 interaction, build, and GMC verification pass with no new missed commits or FRONT writes.

Discriminating test

Decode generated live/death pixels to a common 16-column source grid and compare their declared origin to PLAYER_FB. Mutating death generation to omit the leading transparent column must fail before runtime capture comparison.

Assignment contract

Not prepared. Ready preparation must fix owned generator/artifact files, exact commands, capture evidence, packing limits, worktree, commit boundary, and completion report.

Verification plan

Generation mutation test; opaque-edge proof; every death phase; both collision causes; live/demo; both owners; framebuffer footprint; timing and packing; BUG-012/017, build, and GMC regressions.

Decision log

  • 2026-08-14 — Proposed after user observation and confirmed generator asymmetry: normal frames receive a one-pixel right-alignment transform and death frames do not. No implementation performed.
