Approval brief

Objective and motivation

Restore one build of the historical highscore-test profile from current source so BUG-113 can compare the existing $FF50 image with its $FF40 candidate while retaining the approved high-score name-entry startup marker. FEAT-003 completed and complete is the production default, so this proposal does not establish the diagnostic profile as an ongoing production or routine verification target.

Evidence and baseline

At source revision 1893399155b2fb75a0f4ab437106ec82066d37a1, the checked-in LADYBUG_PROFILE=highscore-test bash scripts/build.sh build first fails before assembly. scripts/build_presentation.py rejects tile ID 256 while compiling coco-credits-screen.tmx cell (21,8), with 257 unique tiles; the instrumented attribution is retained in this receipt. A first menu-placeholder candidate then remained at 257 after timer tile registration; its result is retained separately.

The six-map placeholder candidate passes presentation and BUG-016 proofs: 9 maps, 210 tiles, 4,589 cold bytes, and the four-page bound. Assembly then exits at src/main.s:870 with undefined symbol life_marker_position. Its manifest, capacity checks, source hashes, and failure attribution are retained in this receipt. No HST ROM was produced; the pre-existing ROM file remains the complete-profile baseline, not an HST candidate.

After the user-directed HST omission of live marker-entry code, the next authorized build passed presentation, resident, asset, audio, page-$3D, and presentation-module guards, but stopped at the demo-runtime guard: 940/938 bytes, ending at $06AC against fixed limit $06AA. No HST ROM was produced. The generated listing places the first HST-only lbeq highscore_name_tick at $0304 with bytes 10 27 00 42; the target is $034A. A short beq would branch forward 68 bytes and save exactly 2 bytes, projecting a 938-byte runtime. This is static analysis of the failed-build listing, not a passing build; see the retained receipt.

On the same source revision, the complete profile builds a 65,536-byte ROM with SHA-256 7a676d149bf2e46771b1341fe90b03479b5d79c5d7ceecef75fda37269d6edce; measured limits are resident 8149/8192 bytes, assets 7671/7680, and presentation module 1262/1280. These are single-build baseline observations, not headroom projections for a repaired profile. The receipt is BUG-113 pre-approval diagnostics.

Runtime-profile history records highscore-test as the FEAT-003 diagnostic harness. FEAT-003 began after its visible renderer exceeded the locked presentation module by 203 bytes, then used profile isolation to build and test high-score/name-entry behavior. FEAT-003 is now Done; complete is the current production profile. The build scripts still accept highscore-test, but that does not make its current failing build a supported launch target.

Reproduction and observed versus expected

  1. Run LADYBUG_PROFILE=highscore-test bash scripts/build.sh build at the pinned source revision.
  2. Observed on checked-in source: presentation generation exits because the atlas reaches 257 tiles. The six-map candidate clears the atlas guard but fails assembly because life_marker_position is undefined for this profile.   3. Expected: the command emits a valid 65,536-byte GMC image, preserves the high-score name-entry initial map, and passes existing layout and capacity guards.

Confirmed cause and unresolved detail

Confirmed causes: the shared atlas first overflows on credits-map compilation and remains one tile over after name-entry timer variants are registered. The six-map placeholder candidate validates all authored maps independently, emits placeholders for instructions, level-start, game-over, options, credits, and keybind-options, retains attract/high-score/enter-high-score, and passes the 256-ID guard. It then exposes an assembly dependency: the nonadaptive HST mainline compiles a live-entry branch and its initial_entry_tick/marker_entry_begin routines, which reference life_marker_position; that helper is defined in src/shared_text_runtime.inc, included only under COMPLETE_PROFILE. HST's required cold-start route is name-entry/high-score; FEAT-003 live gameplay is out of scope. The user directed omission of the HST-only live-entry branch, routines, and death-path hook. This resolves the unused helper reference without adding asset bytes or changing the complete-profile runtime. Temporary diagnostic instrumentation was reverted.

Newly confirmed boundary: with those omissions, all measured checks before the demo-runtime guard pass, but the highscore-test demo runtime is 2 bytes larger than its fixed allowance. The generated map/listing confirms the HST-only branch at $0304 was encoded as a four-byte long conditional branch to the highscore_name_tick symbol. Replacing it with the two-byte short form preserves the condition and symbol target within the signed 8-bit relative range and was projected to recover exactly the 2-byte deficit. At proposal time, no code change had yet been made in src/demo_runtime.s.

The user approved the single short-branch change. The HST build now exits successfully with demo runtime 938/938, emits a 65,536-byte ROM with SHA-256 0d2884132597aa26f235ad37eb3be5055e5db9268fc58a03145b7f7d901ea02d, and retains enter-high-score as an authored map. The baseline ROM is preserved at this evidence artifact; detailed build/capacity evidence is in the success receipt and build-log excerpt. The same-revision complete build exits successfully and reproduces baseline ROM SHA-256 7a676d149bf2e46771b1341fe90b03479b5d79c5d7ceecef75fda37269d6edce. BUG-113 still owns the MAME marker comparison.

Scope

Previously approved work retained: use the existing isolated-authored-map validation and placeholder path for instructions, level-start, game-over, options, credits, and keybind-options in the historical highscore-test profile; preserve authored attract, high-score, and enter-high-score; omit the HST-only live-entry dispatch branch, its initial_entry_tick/marker_entry_begin routines, and the death-path call from src/main.s.

Proposed addition, pending approval: in src/demo_runtime.s, change only the first HST-only lbeq highscore_name_tick at the name-mode dispatch to beq highscore_name_tick. The current listing shows a forward displacement of 68 bytes, within the short-branch range; the projected runtime decreases from 940 to 938 bytes, meeting the existing $06AA end limit exactly. Then produce one current-source HST baseline ROM for BUG-113; retain build identity, map, capacity, and profile-isolation evidence; and mark the profile historical after its one-time use.

Out: any second code-size optimization or further HST runtime reduction without renewed approval; changing FEAT-003 gameplay or its Done status; changing the complete production image or other profile behavior; adding a substitute helper or gameplay implementation to HST; widening map IDs or changing runtime decoding; changing loader/MMU ownership; expanding any cartridge, atlas, module, RAM, or payload boundary; retesting all FEAT-003 gameplay scenarios; adding ongoing CI or future maintenance guarantees; changing BUG-113's bank-select code or MAME result criteria.
