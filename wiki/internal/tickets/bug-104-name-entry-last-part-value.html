BUG-104 — Name-entry last-part value Proposed

2026-10-01 · P2 · High-risk · Proposed

Approval brief

Objective and source cause

Show the part number for the level just completed on the enter-high-score screen after game over. At baseline fe160ae389145d24083218ded05ba9cdca781474, the user TMX contains the PART 01 field, but render_name_screen does not draw a part value. The stage-panel writer is guarded to the level-start map. The active stage byte at $24 STAGE advances in next_stage; the last completed part must be read from that state before another stage is initialized, not from the starting-level option or reused temporary state. Runtime handoff identity remains an acceptance gate.

Scope and proposed design

In: the authored part-number cells only, populated from the final active stage at game over. Out: the vegetable sprite (BUG-106), vegetable point value (BUG-105), score fields, and stage progression. Derive the destination from the authored PART label, preserve its fixed-width format, and call a small name-screen field writer using the current stage identity.

Scenarios and acceptance

  • Game over during the first part displays part 01.
  • Game over after a later part displays that final part and does not use configured starting level.
  • Commit/owner replay preserves the displayed value and does not advance the stage.

Acceptance requires correct value on both owner surfaces after the natural game-over-to-name transition, with no change to live stage progression.

Assignment, dependencies and verification

Class: High-risk because it consumes stage identity across the gameplay → game-over → name-entry handoff and the high-score helper has only 39 bytes free in the C3 preparation build. Exact production files: scripts/build_presentation.py for an authored destination constant and src/shared_text_stage.inc for the current-stage read and draw. Coordinate the shared identity source with BUG-106. After approval, run the complete adaptive build, python3 scripts/verify_shared_text.py --build-dir build, and force first/later-stage game-over entry in ≤60-second marked phases after confirming the exact ROM bytes. Preserve current capacities; no new state snapshot or hard-limit increase.

Decision log
