Approval brief

Objective and motivation

Determine whether the complete-profile verify-gmc audio guard correctly rejects a real overlap or falsely treats boot-only descriptors and foreground audio state as simultaneous. The static review established phase-disjoint ownership and supplied the evidence for the complete-profile verifier correction integrated under BUG-113.

Observed baseline

The first candidate image built to 65,536 bytes and passed source, presentation, sparse reconstruction, and GMC boundary checks, then exited 1 with audio proof: completion guard overlaps boot table or audio state before XRoar. The map places GMC_LZSS_TABLE_RAM at $0287 with size $0063 (99 bytes), so the occupied interval is $0287-$02E9 inclusive and ends at $02EA exclusive. The old verifier incorrectly required $0287+99 to be at or below $02C0. The descriptor cap remains 99 bytes and the complete verifier now checks the unchanged $02F0 boot-state boundary. The 20-byte audio guard fits its 28-byte $02C0-$02DB slot.

Source references are confined to src/gmc_bootstrap.s. decompress_gmc_streams consumes the first six descriptors before resident/assets staging; decompress_staged_audio consumes the final audio descriptor and returns directly to boot_streams_retired. The subsequent attract-surface expansion, optional historical HST atlas expansion, boot-flag write and jmp $C002 do not access the descriptor table. Audio initialization and key_init occur in the runtime after handoff. Foreground keybindings reuse $0287-$029A; the audio guard owns $02C0-$02D3, audio state $02DC-$02DD, and gateway $02DE-$02EF. These are later-phase owners, not concurrent boot consumers. The memory map records the exact intervals and lifetime.

Retained evidence: original failure receipt, complete-profile build/audio proof and later verifier stops, current source src/gmc_bootstrap.s, map build/ladybug-gmc-boot.map, and verifier scripts/verify_audio_runtime.py.

Scope

In: read-only source/control-flow audit of every descriptor reader and writer, confirmation of the last consumer and audio/keybinding initialization order, reconciliation of source audit metadata, build maps, verifier limits, and memory-map documentation, and a recommendation with the smallest safe verification change.

Out: changing production assembly, descriptor format or size, audio guard/state, the verifier, memory placement, bank-select behavior, gameplay, build limits, or emulator/hardware configuration. Any implementation remedy requires its own approved assignment.

Questions and discriminating checks

  • Enumerate all accesses to $0287-$02E9 by phase and prove whether any descriptor access can occur after boot_streams_retired. Risk covered: the descriptor table may still be live when runtime state writes begin.
  • Compare exact map symbols and source-reference lifetimes for the boot descriptor range, the keybinding state, the audio guard, and the audio mode/gateway. Risk covered: the verifier may enforce spatial disjointness where the documented ownership is temporal.
  • Reconcile the observed $02EA table end with the memory-map page's historical $02C0 end claim and the current audit width of 99 bytes. Risk covered: stale documentation or a wrong generated boundary.

Acceptance criteria

  1. Provide a byte-accurate interval map with inclusive/exclusive boundaries and named owners for each boot and runtime phase.
  2. List every source-level descriptor consumer and prove whether each is before or after the retirement boundary. State evidence and any unresolved aliasing assumption.
  3. Identify the immediate verifier condition and decide, with source/map evidence, whether it is a false positive or detects an actual invalid lifetime overlap.
  4. Recommend the smallest verifier correction and retain separate runtime qualification as an explicit remaining risk.
  5. Retain a concise diagnosis receipt, update BUG-113 and the memory-map page, ticket index, and project log. Do not claim XRoar or physical-hardware acceptance from static ownership evidence.

Risks and alternatives

The source control flow and the explicit boot_streams_retired boundary confirm that no descriptor consumer remains when foreground owners install into the overlapping range. The safe correction retains the 99-byte descriptor cap, the $02F0 boot-state boundary, the 28-byte audio slot, and the four-pass mixer counter. No assembly, table-size, audio runtime, or memory-placement change was made. The remaining runtime limitation is recorded in BUG-113: current verifier preflights stop before XRoar, and XRoar's parity-based SCS model cannot distinguish $FF40 from $FF50.
