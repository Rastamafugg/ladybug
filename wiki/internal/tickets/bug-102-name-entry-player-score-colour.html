BUG-102 — Name-entry player score colour Proposed

2026-10-01 · P2 · High-risk · Proposed

Approval brief

Objective and confirmed source cause

Draw the pending player's score at the enter-high-score field x33–38,y2 in the same light green as the authored 1ST heading. At baseline fe160ae389145d24083218ded05ba9cdca781474, render_name_screen sends PRES_SCORE_H through draw_entry_scores and the shared generic score_glyphs/PRESENTATION_GLYPH_0..9 path. That runtime digit path has no light-green role; the static heading resolves to pen8. The configured score colour does not reach these dynamic digits.

Scope and design

In: six pending-player score digits and their owner refresh. Out: other scores, score calculation, BUG-069 level-start static score, name-entry top-record fields, and left HUD. Add a generated light-green digit role and select it only for the player-score destination; keep the numeric source and generic score path intact elsewhere.

Scenarios and acceptance

  • Render scores containing every digit, including leading and interior zeroes; every foreground score pixel uses pen8.
  • Update the field after owner alternation and verify unchanged 1ST heading, top-record score and neighboring cells.
  • Use the current source-generated asset path and reject any capacity overflow or hard-limit change.

Acceptance requires actual pending score data at the authored destination, light-green pixels matching 1ST, and no unrelated palette or field changes.

Assignment, dependencies and verification

Class: High-risk because a new dynamic glyph role crosses the generated presentation data and high-score runtime, while the fitted assets, resident and presentation modules have only 58, 55 and 16 bytes free respectively in the C3 preparation build. Exact production files: scripts/shared_text.py, scripts/build_presentation.py, src/shared_text_stage.inc. The shared glyph-role work must be coordinated with BUG-103, BUG-108 and BUG-110; do not run concurrent writers on these files. After approval, run LADYBUG_PROFILE=complete LADYBUG_INPUT=keyboard LADYBUG_CPU=6809 LADYBUG_ADAPTIVE=1 bash scripts/build.sh build, python3 scripts/verify_shared_text.py --build-dir build, and the existing high-score/name-entry runtime verifier with a ≤60-second entry marker. Compare score digits and both buffer publications; retain artifact hashes and capacity deltas.
