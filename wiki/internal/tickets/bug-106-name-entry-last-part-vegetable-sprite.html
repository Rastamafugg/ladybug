BUG-106 — Name-entry last-part vegetable sprite Proposed

2026-10-01 · P2 · High-risk · Proposed

Approval brief

Objective and confirmed source cause

Display the vegetable sprite associated with the last completed part on the enter-high-score screen. At baseline fe160ae389145d24083218ded05ba9cdca781474, the user map has a Sprite Locations marker at x32,y13 (GID633). The parser validates the marker but does not publish it as a name-screen draw destination. stage_panel_finish selects and draws vegetable sprites only on the level-start map; render_name_screen has no vegetable draw call. This is source absence, not current-ROM proof.

Scope and design

In: draw the sprite at the authored name-screen marker using the sprite for the final active $24 STAGE. Out: value field (BUG-105), part number (BUG-104), stage progression, or any TMX change. Publish the marker destination through generated presentation symbols and reuse the existing stage-to-vegetable selection and native graphic path; do not translate heart/text glyphs into this sprite path.

Scenarios and acceptance

  • First-part game over selects the first applicable vegetable.
  • Later-part game over selects the corresponding final-part sprite.
  • Both owner surfaces show the exact expected pixels after natural transition and replay.

Acceptance includes correct identity, palette/mask, no background corruption, and unchanged live game state.

Assignment, dependency and verification

Class: High-risk because it adds native graphic publication across a phase handoff and approaches hard module/resource limits. Exact production files: scripts/build_presentation.py to expose the authored marker destination and src/shared_text_stage.inc to select/draw the stage sprite. Depends on BUG-104's confirmed stage identity and on the BUG-059/060 Sprite Locations layer-contract integration owned by the compiler workstream. Apply those dependencies before this ticket; one owner controls the generator path. After approval, run the complete adaptive build, python3 scripts/verify_shared_text.py --build-dir build, existing presentation sprite/pixel guards, and marked first/later-stage name-entry probes ≤60 seconds each with exact ROM bytes. Do not raise limits.
