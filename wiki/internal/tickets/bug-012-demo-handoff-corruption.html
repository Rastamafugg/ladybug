Decision and outcome

On 2026-08-13 the user selected a replacement deployed flow: attract title → part-one level start → normal-engine demo → death presentation → attract title. The automatic instructions state is removed. This replaces the prior attract → instructions → level-start owner path in presentation_flow_tick.

Arcade evidence and revised route model

The installed arcade Z80 program proves that the demo uses a fixed direction stream, not algorithmic intersection choice. Demo initialization sets bit 4 at $605F and stores ROM pointer $0EF8 at $61D8. Player-control routine $35FF-$3642 advances the pointer whenever X/Y low nibbles are $8/$6, independently of movement legality, and holds the last byte before $FF. A hazard-disabled MAME trace consumed the 186 post-neutral bytes at 112 distinct nodes; turns can consume two bytes at one node. Mapping those nodes to the adapted maze visits only 104 of its 117 collectible cells. The raw table therefore remains authoritative reference evidence but cannot be the deployed walk list if the user-required target is 117/117.

2026-08-14 renewed approval recommendation

Recommended outcome: replace byte-for-byte playback with a deterministic CoCo-aligned walk derived from the arcade node order, then add the minimum detours needed to consume every adapted collectible. Preserve the clockwise quadrant shape: conceptual order upper-left → upper-right → lower-right → lower-left, with the entrance joining the upper-right sweep and continuing through lower-right, lower-left, then upper-left. The left half mirrors the right half in reverse sweep order where maze and gate topology permit. Normal gameplay still ends the demo on the first ladybug death; a hazard-disabled diagnostic continues to route completion.

  2. The title runs to its deadline while global credit/start edges remain active.
  3. The flow loads and publishes the part-one level-start map directly, with no instruction map or intervening blank frame.

  • The route ends before a natural collision, loops without progress, or advances more than once at one boundary.

  • No enemy reaches the route before the hard deadline. This fails natural acceptance; forced death is diagnostic only.
  • Credit/start arrives during map load, level-start hold, a pending framebuffer commit, or death presentation.
  • The removed instruction payload remains reachable, copied, emitted, or counted in the shipping manifest.
  • Framebuffer-owner starting order changes pixels, commits, or route state.
