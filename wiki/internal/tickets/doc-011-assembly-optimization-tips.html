Approval brief

Objective and recommendation

Expand the public 6809 assembly tips with four concise, source-backed articles: register allocation and routine contracts; indexed addressing and table traversal; shared routines and compact lookup data; and hot-loop timing versus code size. Update the existing direct-page page to distinguish Ladybug runtime DP=$00 from the bootstrap loader's temporary DP=$02. Update the folder index to link the articles and remove the future-expansion placeholder.

Motivation and baseline

The folder currently contains only index.html and dp-conventions.html; its index already lists register allocation, addressing patterns, and timing-critical code as planned expansion. Source baseline is 6c26a7e651256e4fe206b73ecfaf88ecec38c4a3 (2026-10-04). The main runtime sets DP to $00 in src/main.s; src/gmc_bootstrap.s uses $02 for bootstrap work. src/shared_text_runtime.inc provides verified examples of typed descriptor dispatch, a shared one-bit mask renderer with a colour lookup table, and a fixed eight-row blitter. src/enemy_runtime.s and src/main.s contain indexed stream and record patterns. These are example anchors, not measured performance claims.

Scope

In: the four new release pages; a project-specific DP note in the existing DP page; links and descriptions in wiki/release/reference/asm-tips/index.html; source-grounded worked examples and tradeoffs; references to relevant 6809 instruction pages.

Out: assembly/runtime changes, code-generation or build-tool changes, cycle benchmarks, claims that an idiom is universally faster, changes to the ROM or hardware reference, and internal mirrors of the release articles.

Reader scenarios and edge cases

  1. A reader learning routine-level register use can identify the 6809's paired D register, explicit clobbers, and when to save/restore registers without assuming a universal calling convention.
  2. A reader traversing fixed-size records or packed streams can follow index bounds, stride, pointer updates, and the distinction between PC-relative immutable data and mapped addresses.
  3. A reader comparing shared drawing code and specialized loops can see the code/data reuse benefit and the indirection, cycle, and ROM-size tradeoffs without treating source appearance as timing evidence.
  4. A reader opens any article directly and can understand it without access to internal-only wiki pages; all local navigation targets resolve.
  5. The DP note does not conflate the loader's DP=$02 with the gameplay runtime's DP=$00 or imply DP changes during normal runtime.

Options and tradeoffs

One long tutorial would minimize page count but make direct lookup harder. Four narrow articles match the promised index categories, make cross-linking clearer, and require modest maintenance as source patterns change. Examples will describe project patterns as examples rather than as a portable ABI.

Dependencies and order

No code or ticket dependency. Implementation order: register contracts, indexed traversal, shared routines/data, then hot-loop tradeoffs; update the DP note and index alongside those articles. No source changes or new pattern are authorized.

Acceptance criteria

  1. Four new, self-contained HTML articles cover the named topics and each contains a small 6809 example, a source-verified Ladybug pattern, explicit constraints/tradeoffs, and relevant links.
  2. The DP article accurately states the separate loader and runtime values and limits the runtime stability claim to normal game execution.
  3. The index links every article, removes the scheduled-for-future wording, and all new page/index links resolve.
  4. Instruction sizes/cycles and source claims are checked against the current source and release reference. Unmeasured performance statements are explicitly framed as tradeoffs or hypotheses.
  5. HTML parsing, unique in-page IDs, local-link resolution, and direct-page standalone reading pass. No code, generated runtime artifact, or ROM changes are present.

Verification plan and risks

  • Technical accuracy risk: review examples and statements against current source and the relevant 6809 instruction pages; reject unsupported cycle claims.
  • Navigation risk: parse changed HTML, check unique IDs, and resolve local links across the edited pages and their targets.
  • Audience risk: read each article from its own URL to confirm it stands alone and does not require internal-only context.

There is no runtime, memory-capacity, loader-change, or performance acceptance risk because this ticket changes documentation only. If source review uncovers a proposed code change or a broader architectural claim, stop and return that work for a separate ticket.

$checkScript = @'
from collections import Counter
from html.parser import HTMLParser
from pathlib import Path
from urllib.parse import unquote, urlsplit
class Page(HTMLParser):
    def __init__(self):
        super().__init__(convert_charrefs=True)
        self.ids, self.links = [], []
    def handle_starttag(self, tag, attrs):
        attrs = dict(attrs)
        if 'id' in attrs: self.ids.append(attrs['id'])
        if tag in ('a', 'link') and 'href' in attrs: self.links.append(attrs['href'])
root = Path.cwd()
tips = root / 'wiki/release/reference/asm-tips'
sources = sorted(tips.glob('*.html')) + [root / 'wiki/internal/tickets/doc-011-assembly-optimization-tips.html']
cache = {}
def load(path):
    path = path.resolve()
    if path not in cache:
        page = Page()
        page.feed(path.read_text(encoding='utf-8'))
        page.close()
        duplicates = [name for name, count in Counter(page.ids).items() if count > 1]
        assert not duplicates, f'{path}: duplicate IDs {duplicates}'
        cache[path] = page
    return cache[path]
for source in sources:
    for href in load(source).links:
        parts = urlsplit(href)
        if parts.scheme or parts.netloc: continue
        target = source if not parts.path else (source.parent / unquote(parts.path)).resolve()
        assert target.is_file(), f'{source}: missing target {href}'
        if parts.fragment and target.suffix.lower() == '.html':
            assert unquote(parts.fragment) in load(target).ids, f'{source}: missing fragment {href}'
print(f'Parsed {len(sources)} pages; local links and unique IDs pass.')
'@
try {
