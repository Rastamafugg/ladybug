Canonical approval, ordering, delegation, and completion queue.

How to read the queue

Ticket IDs use a work-type prefix and a three-digit sequence. Status is the current lifecycle state, not a completion percentage. Priority describes urgency: P0 is an immediate project stop, P1 blocks the active milestone, P2 is normal planned work, and P3 is deferred improvement. Order is the recommended execution position among currently listed work; lower numbers run first. A dependency names work that must be integrated before the ticket can become Ready.

Selection rule

Select the lowest-order Ready ticket compatible with the active roadmap phase. Proposed tickets require explicit user approval. Parallel delegation is allowed only when dependencies are resolved and writable artifacts do not overlap, or when an integration owner and conflict plan are defined before assignment.

Relationship to roadmap and backlog

The roadmap describes product phases and milestone outcomes. Tickets are executable units. The backlog retains investigations and deferred context; actionable work should be promoted into a ticket and link back to its source rather than being implemented directly from a backlog note.
