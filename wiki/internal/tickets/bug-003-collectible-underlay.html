BUG-003 — Collectible underlay on stage load Done

Remove authored dot/flower pixels beneath randomized collectibles before the first colour-cycle redraw.

  • Status: Done
  • Created / updated: 2026-08-06 / 2026-08-06

Objective and evidence

Stage-load rendering must show an empty background beneath every heart, letter, and skull collectible. Current fri_stage_background calls draw_screen, draw_all_gates, and draw_entities; unlike the incremental entity path, it does not call erase_entity_footprints. The authored screen therefore remains visible under each object until the first colour-cycle entity redraw restores the footprint.

Expected: no flower/dot pixels under any collectible on the first committed stage frame, with maze-state restoration preserved for later pickup and movement.

Scope and acceptance

In: initial and next-stage persistent background ordering, focused stage-load capture, and regression evidence. Out: collectible art, colour values, maze generation, and player collection rules. Acceptance requires every placed object type to have a clean underlay before the first colour change and no dot-count or pickup regression.

Assignment contract

  • Owned artifacts: src/enemy_runtime.s, focused BUG-003 verifier, this ticket, ticket index, project log, and lessons learned.
  • Implementation: restore entity footprints from MAZE_STATE before gate overlays and entity drawing in the full stage-background path.
  • Required commands: full build, BUG-003 verifier, GMC proof, enemy-runtime proof, arcade-fidelity, BUG-001/BUG-002 regressions, and HTML-link check.
  • Evidence: retain build/bug-003-collectible-underlay.json; temporary captures remain untracked.
  • Commit: one bounded commit; parent owns integration and QA closure.

Implementation

Inserted erase_entity_footprints into fri_stage_background immediately after draw_screen and before draw_all_gates/draw_entities. This preserves gate overlays while replacing consumed object cells with their clean maze tiles.

Acceptance and current-revision verification

verify_bug003_collectible_underlay.py confirms the stage order, placement dot-bit clearing, and consumed-dot-to-clean-tile restoration. The full build passed with resident 8,190/8,192 bytes, assets 7,144/7,680 bytes, and bank 3 4,096/4,096 bytes. build.sh verify-gmc passed, including the enemy-runtime proof. BUG-001 and BUG-002 focused regressions remain passing. The remaining bank-3 margin is zero bytes; future bank-3 changes require size reduction elsewhere.
