FEAT-009 — Package SPECIAL, EXTRA, and dinosaur art in the ROM internal

Done · Approved High-risk ROM packing and capacity · 2026-10-09

Approval brief

Objective and motivation

Place the converted SPECIAL event art, EXTRA event art, and dinosaur sprite set in the 64 KiB GMC ROM, ready for later screen implementation. This is asset packaging only. No screen entry, rendering, animation, decompression at runtime, or gameplay behavior is added.

The SPECIAL and EXTRA CoCo Tiled maps and representative arcade maps already exist in the working tree. Packaging these assets makes their converted art available to a later implementation ticket while keeping that future screen behavior separately reviewable.

Evidence and baseline

Baseline build artifact: build/ladybug.rom, 65,536 bytes, SHA-256 3794d6feac156514f1dcf97ca0f83f5b0dfeba6561cfb93be38a586f2938d161. Build layout: build/ladybug-sparse-layout.json, SHA-256 8333529204ef5eaf4d910096ea491f8ff62a0a4a55b6cdc56b972a38156db90c, built from source revision 8f951e8c64aece600734c64e299c1829493f24ca. The candidate Tiled event files are working-tree inputs and are not yet included in this ROM.

The current complete build uses 29,583 of 41,438 CPU-readable GMC source bytes, leaving 11,855. It has seven boot LZSS streams and the full 99-byte descriptor allocation. The current cold presentation payload is 14,377 of 16,384 bytes, leaving 2,007; page $39 has 2,442 bytes free. The SPECIAL and EXTRA CoCo Event Scene layers reference 187 and 83 source tiles respectively; the shared compiler atlas contains 258 distinct native tiles (8,256 pixel bytes). The dinosaur sprite-tile payload and index total 5,112 raw bytes in the compiler bundle. These payloads do not fit as additional boot-expanded data in the current cold or page-$39 allocations.

The original projection is superseded by the current compiler output. The CoCo event layers reference 187 SPECIAL and 83 EXTRA source tiles; conversion yields 258 distinct native 4bpp tiles. The self-describing event bundle is 9,547 raw bytes, including 8,256 atlas bytes, two 640-byte 16-bit lookup tables, and an 11-byte header. The dinosaur bundle is 5,112 raw bytes, including 37 source-code entries and sparse streams. Exact current LZSS output is 3,834 event bytes plus 1,855 dinosaur bytes, 5,689 total. Against the baseline 11,855 free source bytes, projected remaining capacity is 6,166 bytes; final bank placement and integrated capacity remain build gates. The event raw SHA-256 is 51a1ca12f3b833ad28c6c20b0728f854774ad1cb5e0a4c311a3bf0ea84037e63; dinosaur raw SHA-256 is 3b66568b9274811d6c83750a2d8739eabdeb61119e9b7c709bacecfb1e568fbd.

Scope

In: Compile the SPECIAL and EXTRA CoCo Tiled event art into a shared native 4bpp tile atlas with source-TileID-to-atlas-ID mappings for each event map; compile the 37 selected dinosaur sprite tiles in the existing sparse sprite format while preserving source tile IDs; compress and embed these payloads in available GMC ROM source intervals; emit generated bank, source offset, length, and hash metadata so a later screen task can locate them. Preserve the current ROM size and all existing runtime and boot data.

Out: SPECIAL/EXTRA full-map compilation or presentation, runtime reads or decompression, framebuffers, screen transitions, event animation/path playback, dinosaur game logic, new loader/MMU/boot descriptors, palette redesign, and changes to the source Tiled files. Screen behavior will require a separate ticket.

Palette assumption: use the current canonical CoCo GIME palette mapping. The current nearest-palette conversion merges two arcade green shades into one CoCo slot; preserving the arcade distinction would require a separate palette decision and is outside this scope.

Scenarios and edge cases

  • Both CoCo event maps compile against the authored 320-tile arcade event tileset, with shared native tile pixels deduplicated and each map's source-tile-to-atlas mapping retained; full 40×24 placement layers are excluded.
  • The dinosaur selection includes sprite codes 89–125 only. Code 88 is the existing death angel frame; codes 126–127 are uniform pen-3 tiles and are excluded.
  • Builds fail on an asset source mismatch, duplicate or missing tile reference, source interval overlap, protected GMC region overlap, output beyond the 64 KiB image, or total source-capacity overflow.
  • The existing seven boot descriptors, runtime bank, nine deployed presentation maps, and their outputs remain valid. The new compressed assets are present in the ROM but remain unused at runtime.

Possible SPECIAL mini-game follow-up

These are design sketches, not approved behavior. The 16×16 sheet entries show varied dinosaur forms, but their intended combinations and animation order are not yet confirmed against a measured arcade sequence.

  • Pose parade: assemble several source tiles into larger dinosaur poses, then cycle through the pose changes while Lady Bug crosses the scene to collect a coin or egg trail. Completing the route awards points and an extra life.
  • Telegraphed stomp: use distinct head, limb, and tail poses to signal a stomp, sweep, or lunge. Lady Bug navigates a short maze route, avoids the indicated area, and collects bonus items. Score scales with collected items; surviving the sequence earns an extra life.
  • Silhouette match: briefly show a target pose, then let the player collect or select the appendage tiles that complete it. Correct combinations earn points; a full set earns the extra life. This emphasizes the modular art but needs the most new interaction rules.

Recommendation for the later screen ticket: first reconstruct the actual source-tile grouping and arcade timing from MAME captures, then evaluate the telegraphed-stomp sequence if the forms represent distinct action poses. Keep any added player control and reward thresholds behind an explicit gameplay approval; asset packaging alone does not select a mini-game.

Options and recommendation

Recommended: keep the new assets as two independently compressed, unexpanded GMC ROM payloads and emit generated source-location metadata. This fits the measured source budget without consuming a boot descriptor or claiming unavailable RAM capacity. The tradeoff is that a later screen ticket must design and verify how to retrieve/decompress the payload at the screen boundary.

Rejected for this scope: add boot expansion descriptors and RAM destinations. The descriptor allocation is full, and the 12,965 expanded bytes exceed current cold and page-$39 headroom. That alternative changes boot/runtime memory ownership and would expand this ticket into a loader design.

Rejected: store the converted art uncompressed. Its 14,659-byte current compiler footprint exceeds the 11,855-byte baseline free GMC source capacity before any location metadata.

Acceptance criteria

  • The complete 65,536-byte ROM contains both the deduplicated event-art payload and the dinosaur payload, with reproducible generated source locations, lengths, and SHA-256 values.
  • Decompressing each embedded payload reproduces its compiler output byte-for-byte; SPECIAL and EXTRA source tile IDs resolve to the intended shared-atlas tiles, and all 37 selected dinosaur sprite tiles match their converted source pixels and preserve their source IDs.
  • The complete build succeeds with no GMC source interval overlaps, protected-region writes, source-capacity overflow, ROM-length change, or added boot descriptor. Remaining GMC source capacity is nonnegative and is reported exactly.
  • Existing nine-screen pixel proofs, runtime/boot payload identity, and current complete-profile capacity guards remain passing.
  • No runtime behavior or visual output changes are claimed or required by this ticket.

Dependencies and ordering

Inputs are the current tiled/coco-special-screen.tmx, tiled/coco-extra-screen.tmx, tiled/arcade-special-screen.tmx, tiled/arcade-extra-screen.tmx, tiled/arcade-event-tiles.tsx and PNG, and the existing arcade sprite JSON/raw tileset. No runtime feature ticket is a prerequisite. A later SPECIAL/EXTRA screen implementation will depend on this bundle and must separately approve its data-access/lifetime design.

Constraints and risks

High-risk technical classification: this feature consumes tight cartridge source capacity and changes the build-time cartridge packing contract. The hard current ceiling for new source payload plus metadata/alignment is 11,855 bytes. The build-time package must not be counted as an available decompressed RAM destination. Seven of seven boot descriptor slots are already used; any design that changes this or adds runtime access must return for renewed approval.

If the emitted compressor output and metadata exceed available source capacity, stop and return this ticket to Proposed with actual sizes and a revised design. Do not remove existing assets, alter GMC limits, or modify boot/runtime behavior to force a fit.

Verification plan

  • Payload/source identity risk: run the complete build and exact per-payload decompression/byte comparison; require the expected event atlas references and 37 dinosaur sprite tiles.
  • Cartridge packing risk: inspect generated GMC locations against all current source intervals and protected regions; require a 65,536-byte ROM and nonnegative remaining capacity.
  • Regression risk: run the existing nine-screen pixel proof and complete-profile source/capacity guards; compare runtime bank and boot descriptor content against the pre-change build wherever the approved package is not meant to alter them.

No MAME/XRoar runtime probe is required because this ticket adds no runtime consumer. Emulator validation of SPECIAL/EXTRA presentation belongs to the later screen implementation ticket.
