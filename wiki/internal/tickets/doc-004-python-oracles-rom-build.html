DOC-004 — Python oracles and ROM build internal

Define the Python build roles, oracle contract, generated artifacts, and ROM assembly path.

Approval brief

Objective and motivation

Document how Ladybug's Python programs transform authored Tiled, JSON, and captured arcade data into generated assembly/binary artifacts, how those artifacts are assembled into the four-bank ROM, and what “oracle” means in this project. This is needed before the Tiled MCP work uses Ladybug as a template.

Evidence and baseline

Current revision 2026-08-15 contains Python generators and verifiers called by scripts/build.sh, including derive_maze.py, build_screen.py, build_presentation.py, build_sparse_sprites.py, and independent verification scripts. Existing pages describe commands and outputs but do not define the shared oracle terminology or the complete Python-to-ROM ownership boundary.

Scope

In: one internal HTML page, links from tooling/build indexes, definition and taxonomy of oracle roles, Python input/output ownership, generated-file rules, ROM/bank composition narrative, command references, and a dated project-log entry. Out: Python refactors, new build behavior, MCP implementation, runtime changes, and replacing existing verification scripts.

Scenarios and edge cases

Cover a normal scripts/build.sh build; a Tiled map change; a captured-asset change; a generated include or binary mismatch; a source-bank capacity failure; a successful bank-0 overflow composition; a failed one-byte-over-capacity proof; release versus development profile; and a runtime verifier that is not equivalent to a build-time oracle.

Options and recommendation

Use one canonical “Python build and oracle” page linked from the existing runbook. Do not duplicate the full build runbook or create a second terminology page. Define an oracle by its expected-result authority and independent checkability, not by the implementation language or by whether it emits bytes.

Acceptance criteria

The page defines oracle, generator, verifier, reference capture, staged artifact, and delivered artifact; identifies the current scripts and their inputs/outputs; explains raw lwasm output, padding, bank composition, and hard guards; links from tooling navigation and the build runbook; passes local-link validation; and records the revision and decision in wiki/internal/log.html.

Assignment contract

  • Owned artifacts: wiki/internal/tooling/python-build-oracles.html, wiki/internal/tooling/index.html, wiki/internal/tooling/build-workflow.html, this ticket, ticket index, and wiki/internal/log.html.
  • Constraints: hand-authored HTML; no Markdown wiki page; preserve existing commands and claims unless corrected by current source; no runtime or build-script changes.
  • Required commands: local HTML target scan, Python syntax compilation for cited scripts, and scripts/build.sh build if available in the current environment.
  • Evidence: changed-file list, local-link result, syntax result, build result, and current source revision.
  • Commit: one bounded documentation commit; integration remains parent-owned.
  • Completion report: commit, pages changed, commands/results, build outcome, and residual documentation gaps.
