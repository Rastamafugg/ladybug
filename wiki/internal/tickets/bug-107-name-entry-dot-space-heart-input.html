BUG-107 — Name-entry dot, space and heart actions Proposed

2026-10-01 · P2 · High-risk · Proposed

Approval brief

Objective and confirmed source cause

Make the bottom-row dot, space and heart choices append their exact selected symbol and trigger the existing name-entry cue when Ladybug traverses each node. At baseline fe160ae389145d24083218ded05ba9cdca781474, parse_enter_high_score_contract emits node IDs FE/FF/FF/FF/FD and filters FF from action_records; name_cell_arrival only appends and cues a matching record. Thus the three choices have no action records. Raw asset evidence identifies dot code45, blank-space code36, and heart code41; code41 is a native 8×8 graphic and the text-glyph translation deliberately blanks codes36–42.

Scope and proposed design

In: virtual semantic mappings for the three existing bottom-row nodes, exact append data, traversal cue and correct visible representation. Out: TMX edits, other glyph actions, sound redesign and BUG-057's already supported action/cue paths. Have the generator emit action records for dot45, space36 and heart41 while retaining CL=$FE and END=$FD. Space must consume name length while remaining visually blank; heart must render from the native graphic descriptor, never from the normal text translation.

Scenarios and acceptance

  • Traverse each node independently: exactly the chosen byte is appended and the existing cue occurs once.
  • Space advances length and remains invisible; dot shows a period; heart shows the heart graphic.
  • Existing delete/clear and END behavior remain distinct; name length and owner replay stay correct.

Acceptance requires generated descriptors and exact runtime pixels, name bytes, length and cue evidence for all three symbols.

Assignment, dependencies and verification

Class: High-risk because the action-table omission feeds persistent text/audio ownership, the heart uses native graphics, and current helper/presentation margins are tight. Exact production files: scripts/build_presentation.py, scripts/shared_text.py, src/shared_text_stage.inc. Link BUG-057 Done only as the existing cue mechanism; do not reopen its completed scope. After approval, run the complete adaptive build, python3 scripts/verify_shared_text.py --build-dir build, the existing audio verifier and a ≤60-second forced traversal for each symbol; prove current ROM bytes before reading runtime state. Capacity failure rejects the proposed design; no limits or TMX data may change.
