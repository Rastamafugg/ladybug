TOOL-006 — Align audio verifier with current topology

Draft · Standard · 2026-09-30

Objective and observed baseline

Make the shared audio verifier accept the current audited boot/foreground lifetime and adaptive counter implementation while retaining negative ownership/bounds checks. On integrated keybinding ROM b452413b9e2d0e4d6e57e87a63d22b44ffed2a4cbb87c3c9c9e07a5d81992b55, python3 scripts/verify_audio_runtime.py --rom build/ladybug.rom fails because it requires boot descriptor end≤$02C0, although seven descriptors retire at$02EA before guard installation. A repro-only corrected bound then fails the legacy lexical audio_mix_all_next counter check because of an existing adaptive branch. Normalized src/audio_runtime.s is unchanged from6fc1eee. These are host verifier incompatibilities, not observed sound failures. Motivation: restore one reliable current-topology oracle rather than accumulating adapters.

Scope, criteria and assignment

In scope: scripts/verify_audio_runtime.py ownership/lifetime and profile-sensitive static checks plus small shared negative fixtures and evidence. Out of scope: audio/runtime/loader changes, keybinding semantics, memory limit changes or gameplay performance. Standard because two independent verifier assumptions require profile/lifetime handling; no runtime mutation or hard-boundary change. Scenarios: current adaptive build passes; nonadaptive bounded-counter build still passes; actual guard/state overlap and nonretired reuse fail; unbounded/clobbered counter mutation fails. Acceptance: zero false rejection on both valid profiles and every malformed fixture fails. No missing fixture counts as pass.

Dependencies/order: approval, measured design/fixtures, Ready assignment, parent implementation, QA; current source provenance and ownership are prerequisite inputs. Exact assignment before Ready must identify fixture artifacts, owner, commands, retained negative evidence and separate commit. Verification will reuse python3 scripts/verify_audio_runtime.py --rom build/ladybug.rom and existing source/ownership audit, with minimal targeted fixtures. Constraints/risks: avoid accepting phase overlap without retirement proof or weakening the four-slot mixer invariant. Retain concise hashes and failures. No implementation is approved.
