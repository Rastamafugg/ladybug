Attract actor-animation source review — 2026-11-08

Finding: the actor stutter may share the menu repaint defect's broad pattern: one owner's pixels can be stale while shared state makes work appear current. It is not the same flag or exact failure. In the menu defect, the other owner's MENU_DIRTY bit remained set; the lost work was because dispatch waited for a fresh input event after the scanner had cleared it. The correction keeps the per-owner bit until that BACK is painted, then retries outstanding work on idle ticks (src/shared_text_stage.inc:1062-1064, 1198-1201, 1240-1278; src/presentation_runtime.s:686-703). The menu dirty bit was not cleared prematurely.

Actor mechanism: Attract derives one desired phase and compares it with a single global PRES_ACTOR_PHASE at src/perimeter_reset_helper.s:195-201. On a phase change it stores that global phase before preparing and drawing only the selected BACK at lines 201-241. If the phase is unchanged, it returns before selecting/preparing the other owner. The existing framebuffer prepare hydrates owner-local metadata but does not copy FRONT pixels (src/enemy_runtime.s:1356-1413); project memory-map and framebuffer lessons describe separate persistent A/B pixel histories. By contrast, the logo tracks separate owner phases (src/shared_text_stage.inc:934-955) and can publish a logo update through BACK (src/shared_text_stage.inc:998-1015). The normal source-supported path does not require a failed draw: a successful actor update advances one BACK, while the other retains its previous actor pixels; a later logo or menu publication could expose that older image. I infer that this could produce the reported replay. The early global phase store is an additional potential lost-retry hazard if preparation or drawing fails, but no such failure is established as the normal cause.

Rejected simple explanation: current menu input does not reset the actor phase. It reanchors PRES_TIMER with 6 + ((PRES_TIMER - 6) & 31) at src/shared_text_stage.inc:1113-1122, preserving the bits used by presentation_attract_phase. The older full timer-reset explanation therefore does not apply to this source revision.
