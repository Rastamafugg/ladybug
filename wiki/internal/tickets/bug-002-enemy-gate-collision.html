Test authoritative enemy navigation only after gate visuals and replay state are corrected.

Approval brief

Objective and motivation

Determine whether enemies violate authoritative GATE_STATE, then correct only confirmed navigation defects. Current visual corruption can make legal movement appear illegal, so implementation scope is not yet fixed.

Evidence and baseline

User observation: enemies appear to walk through gates. Exact gate, direction, state, enemy cell, revision sequence, and frequency are not yet captured. Static inspection confirms enemy_direction_legal has a dynamic slow path for gate-owned target cells. It also identifies a candidate coverage gap: one rotation-cross cell per gate lacks NAV_GATE in maze_nav, allowing the current-cell fast path there. Speculation: this may permit a stale static exit after rotation; it is not a confirmed cause.

Scope

In: controlled enemy-entry, exit, occupancy-during-turn, and post-turn tests against all gates and states; correction of a confirmed legality defect. Out: gate rendering, pursuit policy, enemy speed, sprite overlap, and unrelated AI redesign.

Scenarios and edge cases

Force every gate, state, approach direction, current/target gate-owned cell, natural junction choice, enemy already inside the rotation cross when the player turns it, and repeated movement through both framebuffer owners. Compare semantic enemy cells and directions, not rendered pixels alone.

Options and recommendation

After BUG-001, build a table-driven semantic oracle and a live forced-path capture. Do not patch the fast path or maze metadata from static suspicion alone. If the semantic record is legal while pixels appear to cross a wall, route back to renderer ownership; if the record is illegal, isolate current-cell versus target-cell legality before selecting a fix.

Acceptance criteria

Complete after reproduction: every required path must be forced; enemy semantic movement must agree with authoritative gate state; no missing scenario counts as passing; navigation, den entrance, non-reversal policy, and renderer ownership regressions must pass.

Bug reproduction and discriminating test

Observed: apparent enemy passage through gates, without a stable reproduction. Expected: enemies use only passages open in the current gate state. Discriminating test: after BUG-001 convergence, freeze one enemy at each gate-relative cell, force each candidate direction and gate state, invoke the live legality/movement interval, and compare record changes against an independent gate-geometry oracle. Retain natural sequences where a gate rotates while an enemy occupies the cross.

Assignment contract

  • Approved objective and non-goals: incomplete until reproduction fixes the contract.
  • Owned artifacts: expected enemy navigation code and focused diagnostic scripts; exact files assigned only when Ready.
  • Implementation constraints: no hypothesis-driven change without approval; preserve arcade gate rules and den exception.
  • Required commands and scenarios: build, runtime verifier, semantic oracle mutation, all-gate/state forced paths, natural occupancy-during-turn, and renderer cross-check.
  • Evidence: retain compact semantic path results and any failing snapshot.
  • Commit: one bounded commit only after Proposed, Approved, and Ready.
  • Completion report: reproduction, cause, semantic result, tests, capacity, residual risks, and status.

Verification and completion

BUG-001 must first remove visual ambiguity. No enemy implementation is authorized.
