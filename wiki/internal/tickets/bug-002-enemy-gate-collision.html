BUG-002 — Enemy gate collision Done

Make enemy movement honor the authoritative gate-owned target cell and current gate state.

Identity and ordering

  • Status: Done
  • Created / updated: 2026-08-06 / 2026-08-06
  • Priority / order: P1 / 4
  • Owner: parent agent

  • Approval: user explicitly approved implementation and verification on 2026-08-06

Approved objective and scope

Enemies must never enter or leave a gate-owned cell through a passage closed by the current GATE_STATE. In scope: enemy_direction_legal, its focused oracle, and required ticket/wiki evidence. Out of scope: gate rendering, pursuit policy, enemy speed, player gate rules, and AI redesign.

Observed facts and confirmed cause

Observed: enemies can appear to walk through gates after the gate visual/replay fix. Expected: enemy movement agrees with the player-side target-cell gate oracle, except for the intentional den re-entry exclusion. Cause: the enemy fast path checked only the current cell's static navigation bits. An ordinary cell adjacent to a gate could enter a gate-owned target without reaching the dynamic gate-state test. The fast path also did not force all five rotation-cross cells through the slow path.

Discriminating test

scripts/verify_bug002_enemy_gate_collision.py enumerates every walkable/current rotation-cross cell, direction, gate, and state, and compares the legacy fast/slow behavior with an independent target-cell oracle. The pre-fix model reproduces 3,200 mismatches across 128,640 cases; the fixed model must produce zero.

Assignment contract

  • Owned artifacts: src/enemy_runtime.s, focused BUG-002 verifier, this ticket, ticket index, project log, and relevant lessons learned.
  • Implementation: force current rotation-cross cells and gate-owned targets through the authoritative slow path before accepting static navigation.
  • Required commands: full build, BUG-002 oracle, enemy runtime verifier, GMC proof, and integrated regression suite.
  • Evidence: retain build/bug-002-enemy-gate-collision.json; temporary captures remain untracked.
  • Commit: one bounded commit; parent owns integration and QA closure.

Implementation

Updated enemy_direction_legal so the optimized static exit path checks the target's maze_gate_owner entry before accepting movement. Gate-owned targets continue through the existing dynamic GATE_STATE logic; ordinary targets retain the fast path.

Acceptance and current-revision verification

Pass: scripts/verify_bug002_enemy_gate_collision.py forced 128,640 cases, reproduced 3,200 legacy mismatches, and found zero fixed mismatches. Full build passed with resident 8,190/8,192 bytes, assets 7,144/7,680 bytes, and bank 3 4,093/4,096 bytes. build.sh verify-gmc, verify_enemy_runtime.py, BUG-001 replay, gate cache, arcade-fidelity, and forced no-overlap checks passed. An eight-second randomized XRoar soak reached timeout without crash markers. The transition-profile verifier remained unable to locate its expected entry in the regenerated trace and is retained as a separate tooling limitation, not a BUG-002 acceptance criterion.
