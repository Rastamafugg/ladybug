Design, Reuse, and Boundaries

The BUG-009 path already establishes the authored Attract image as the first normal presentation frame and verifies GMC startup and natural Attract progression. FEAT-018 inserts the approved Loading frame before that existing path and retains its Attract handoff. The presentation-flow gate must continue checking the natural Attract sequence after Loading; it must not treat Attract as the first raw cartridge frame. FEAT-018 does not redesign Attract or create a second normal presentation owner.

The memory map documents $FE00-$FEFF as forced to physical page $3F, independent of PAR7, and identifies the IRQ jump slot at $FEF7. The GIME reference identifies Vbord as the 60 Hz source enabled at $FF92 bit 3 and records the SAM cartridge/all-RAM transitions. The approved handler range does not overlap the IRQ jump slot. Before source edits, confirm the current bootstrap IRQ owner and preserve the existing IRQ enable state and handoff contract; do not introduce a general IRQ framework.

Keep handler code in the forced-RAM window. Any accessed state must use an explicitly assigned RAM location that remains valid across both SAM modes; do not fetch code or animation data from a banked source while all-RAM is selected. The 144-byte range is a hard handler-code limit, not a measured current fit. The build must prove the handler fit and retain existing bank, resident, asset, and payload limits. Any new or changed assembly routine, generated/exported symbol, or call boundary must follow DOC-002, including its source-reference record, primary-source contract mirror, routine-catalog entry where applicable, and post-generation audit.

Out of scope: Attract artwork or choreography changes, gameplay/runtime IRQ redesign, unrelated boot payload changes, other screens, NitrOS-9 support, the deferred web app, and the patched XRoar monitor stack.
