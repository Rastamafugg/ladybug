Project-management classification

Objective: move the menu from High Score to Attract, allow a selected Start Game at zero credits, wake the automatic attract loop on fresh keyboard or already-supported joystick direction input, and display the approved ranking layout.

Approved boundaries: keep both authored Attract and High Score TMXs byte-for-byte unchanged; preserve Options, Credits/About, keybinding capture, gameplay, name entry, ordinary HUD credit labels and SPECIAL stores; keep the existing 558 presentation-counter idle interval and restart it after recognized title-menu input. Ranking is display-only: TOP is row 4, nine ranked records are rows 5–13, record zero appears both at TOP and 1ST, and only the existing nine records are stored. Preserve existing framebuffer, loader, audio, input and MMU owners. No new module, allocator, MMU protocol, renderer rewrite, hardware support, or larger capacity limit.

Cost class: High-risk. The change crosses cold-load and title publication, title/local/automatic/postgame input ownership, copied auxiliary-runtime handoffs, persistent A/B pixels, generated menu and ranking destinations, and hard resident/module limits. These risks determine the fit, static and natural-runtime gates below.

Affected existing artifacts: src/presentation_runtime.s, src/keybinding_runtime.s, src/shared_text_stage.inc, scripts/build_presentation.py, scripts/shared_text.py, scripts/build.sh's existing resident-symbol export dictionary, and the existing verifier allowlist below. The preferred joystick route reuses src/main.s:joy_read_axis and does not edit its source body; conditionally export its existing label for INPUT_JOYSTICK=1. Update scripts/source_reference.json only if the new cross-module call changes its export contract. Do not change scripts/source_reference_adaptive.json unless emitted adaptive symbols or delivery contracts actually change. src/shared_text_ranking.inc is not an assumed target; edit it only if the emitted complete-profile listing proves a changed ranking destination is consumed there. Existing architecture and ownership proof

Cold title and local menu. Complete-profile presentation_flow_tick scans input before checking PRES_MAGIC. Its cold branch then starts PRESENTATION_MAP_ATTRACT. start_screen installs the instruction runtime when the target is Attract or Instructions, copies it to the existing $0300 region, clears menu state only when the screen changes, and starts the existing bounded BACK loader. A cold Attract target can equal the zero-initialized screen byte, so the cold branch must explicitly seed MENU_SELECT=$00 and dirty both owners before load; it must also clear the cold scan's stale local event after scanning. The initial Attract load must not run menu_tick before the first complete FRONT is published. A held Return during cold loading is consumed by input history and must not launch gameplay at first FRONT.

The existing menu implementation is in shared_text_stage.inc. Its page-$23 entry addresses are PRES_STAGE_SLICE=$B083, MENU_SCAN=$B086 and MENU_TICK=$B089. load_tick maps PAR5 to page $23, calls the helper, then restores PAR5 to $34. menu_scan calls the existing resident key-service gateway, which temporarily maps page $3D and restores its caller mapping. menu_tick owns the current high-score and local Options/Credits menu behavior. The frozen source disproves the earlier assumption that its repaint is independent of copied callbacks: menu_tick reaches PRES_HIGHSCORE_FB_PREPARE/FINISH at $0300 through PRES_NAME_PTR. On the title, $0300 contains the instruction runtime, so invoking those high-score callbacks is invalid. The candidate routes repaint through the existing resident PRES_MAIN_FB_PREPARE/FINISH callbacks, PRES_GAME_PAGE_RETURN, and stacked PRES_MAIN_PAGE23_RESUME continuation; it leaves the instruction runtime and actor callbacks installed. Add the Attract menu to this page-$23 owner and dispatch Start to the existing Level Start handoff without testing, decrementing or rewriting the legacy credit balance. Options and Credits/About remain local; their Back path returns to Attract with Start selected.

Attract animation and copied-runtime handoff. start_screen(Attract/Instructions) installs the instruction runtime into $0300-$06A9, not the copied high-score/name runtime. attract_tick calls the page-$23 highscore_logo_tick at $AC40 through PRES_NAME_PTR and the resident PRES_MAIN_PAGE23_RESUME return gateway; this callback uses the existing prepare/finish framebuffer path. Its source comment says the attract-owned instruction overlay makes high-score low-RAM callback addresses invalid. Keep this page-$23 animation callback and the instruction runtime installed on title. Do not install the copied high-score runtime for a title menu. Postgame normal_tick installs the copied high-score/name runtime for game-over and name-entry work; after the approved ranking return, start_screen(Attract) replaces it with the instruction runtime before the new title load. No callback address, copy slot, handoff, bank mapping, or page-$23 return protocol needs to change.

Menu selection and state. shared_text_stage.inc declares MENU_SELECT=$E0, MENU_PREV=$DF, MENU_EVENT=$D0 and MENU_DIRTY=$E1. The existing key scanner writes D0 only for the old high-score and local menu owners; it must recognize the new Attract owner while preserving the existing local screen gates. D0 is also phase-owned by the Instructions colour clock and name entry, so do not clear or update it globally. $DF/$E0/$E1 overlap name-entry state by phase; only the existing screen-owned menu path may use them. After cold setup and after Back from a local page, Start is selection zero and the authored highlight is painted onto both BACK owners before their fronts are exposed.

Attract idle and title-event order. attract_tick advances PRES_TIMER=$B0 once per presentation call and enters the existing Instructions path at 558. On a fresh recognized title menu edge, run menu selection/activation and reset both timer bytes before the next idle interval. Do not reset on an unmapped title key: the approved title contract allows only recognized menu controls to act. While title has no menu event, preserve the exact natural 558-counter path. Call the existing page-$23 MENU_TICK only after title FRONT publication and release of any existing hold/pending transaction; while MODE_LOAD targets Attract, consume/update physical edge history without local dispatch.

Automatic-loop wake and ranking return. The global wake check belongs in presentation_flow_tick after the single scan and before coin/start handling or phase dispatch. Use a currently unused high bit of the existing PRES_EVENT=$A9 byte as a one-call wake token; preserve the existing start and coin bits. Consume the token before start_screen(Attract) so it cannot become title input. Gate it to Instructions/demo automatic ownership and the ranking-only High Score owner, excluding Options/About, keybinding capture, live gameplay and MODE_NAME. For a fresh event during an automatic Instructions/demo-targeted load, cancel the old load/owner and request Attract through the same start_screen/PRESENTATION_HOLD path; publish the new fully loaded Attract before any local action. For an Attract-targeted cold or return load, do not call the menu tick until actual publication; scanner state must suppress a held event after the title appears. High Score ranking receives a fresh-edge return to Attract with Start selected, consumed. Keep the existing credits storage and HUD render flags; remove only coin-driven presentation preemption and high-score coin presentation.

Preserve the current prepare-once and RNG lifecycle across demo → returned Attract → free Start. The title/wake path must not call startup init_joystick/read_joystick, reseed RNG_STATE, reinitialize a demo/player route, or consume the next-stage preparation a second time. Free Start should rejoin the existing Level Start/prepare-once handoff and run gameplay initialization once at its existing owner boundary. Candidate evidence must compare the relevant prepare/context and RNG state before wake, after title publication, and at Level Start, and prove one normal initialization; this is an acceptance obligation, not a new fixture or source-derived passing result.

Keyboard any-key edge without extra matrix storage. keybinding_runtime.s scans eight active-high, seven-bit physical column samples into KB_ROWS=$028E–$0295, then uses those newly stored rows in key_down for mapped gameplay, fixed menu edges and capture. Source reference and raw-source search show keybinding_runtime.s is the only post-boot reader/writer of KB_ROWS: menu navigation reads rows+3..6, key_down resolves mapped physical switches from the rows, and key_capture OR-reduces all eight rows to wait for release before accepting a replacement key. The module audit makes keybinding_runtime the sole post-boot writer of $0287–$029A; main consumes mapped actions at $0296 and later, not the raw rows. During each ks_column, compare the just-read sample with its old KB_ROWS byte before replacing it, accumulating an any-new-pressed-bit result in an existing clobbered register. This reuses the existing eight-byte history and requires no second matrix. key_init currently clears mapped edge/capture state but does not initialize KB_ROWS; its established startup call precedes the first scan. Seed all eight old-row bytes to $FF; the scanner masks samples with #$7F, so the sentinel is impossible and the first scan seeds history without manufacturing a cold-start edge. Publish the wake token only in eligible automatic/ranking phases and only when key capture is inactive. Preserve MENU_PREV updates on non-menu phases so held Return cannot become a second menu edge after owner change. Do not reuse reserved $028D or repurpose name-entry D0/DF/E0/E1.

Joystick scope and preferred existing callback. Prefer exporting that existing raw callback rather than adding resident sampling code. The keyboard assembly must not reference the absent joy symbol.

Within keybinding_runtime, invoke the raw-axis export only for the already-supported joystick profile and only while the global owner is Instructions/demo automatic loop or ranking. Capacity and packing limits

The source/ticket baseline at commit 3cba1bf measures resident free space of 110 bytes for complete adaptive keyboard, 74 bytes for complete adaptive joystick and 42 bytes for complete nonadaptive keyboard. The required floor is 32 bytes, so the remaining permitted net resident growth over that baseline is 78, 42 and 10 bytes respectively. These are measured historical observations, not feature projections; new growth and savings are unmeasured. The limiting profile has only 10 bytes above the required floor.

Measured source baseline also records the complete presentation module at 1259/1280 bytes (21 free), copied name/high-score runtime at 917/920 (3 free), and the page-$23 auxiliary staging boundary at $B880. The source guard rejects auxiliary staging past $B880. Separate fixed limits remain: instruction copy at $0300 with limit $06AA (938 bytes); high-score/name copy at $0300–$0697 (920 bytes); page-$23 phase helper entry $AC40 and resume $AD00; presentation module $1900–$1DFF (1280 bytes); keybinding transport at $BA00 with a 0x600-byte maximum; audio prefix maximum 0x1A00; and resident 8192-byte maximum. The page-$23 shared helper, copied runtime, resident, compressed title, audio and presentation module are non-fungible owners. A removed coin path in one owner is not headroom in another.

The candidate must report assembled size/end and remaining bytes for every affected owner from its listing/map and pass all existing build guards unchanged. Preserve the $AC40–$AD00 callback slot, $B880 staging boundary, all copied-runtime limits, the keybinding 0x600 limit, module limits and resident floor. The removed draw_coin_slots code, Coin Positions sparse records and ADD CREDITS generated string are possible savings only in their own compiled/payload owners; no byte recovery is projected or accepted until measured. If any one hard owner overflows or resident free drops below 32 in any profile, fit fails; no limit increase or relocation is authorized.
