Budget to beat

The matched baseline has 91 bytes from name_late_turn at $DF37 through resident_end at $DF92. The failed candidate has 217 bytes from $DF37 through $E010, exactly +126. Its post-snap continuation is 42 bytes and its nlt_deltas table is 8 bytes. The nonadaptive keyboard baseline has 42 free resident bytes; preserving the required 32 leaves a maximum net BUG-120 resident growth of 10 bytes. Therefore the equivalent body may be at most 101 bytes and, if the 42-byte continuation and 8-byte table stay, pre-snap code may be at most 59 bytes. The current pre-snap code occupies 175 bytes. Required recovery is at least 116 bytes from that region. Adaptive keyboard and joystick could tolerate +78 and +42 bytes, respectively; the nonadaptive profile is controlling.

Optimistic same-ABI instruction floor

The accounting below uses 6809 machine-code bytes, not source bytes. It is a source-only lower-bound screen for a caller-only rewrite that leaves the callback ABI and placement unchanged: name_late_turn receives the callback target in X, the callback returns passability in A and the full graph byte in B, and name_late_turn must preserve X for its caller. It grants zero bytes for pair classification, selecting which hazard applies, all branch routing to shared return labels, and several register reloads. A positive gap means the floor already exceeds the 59-byte pre-snap allowance.

| Required block | Minimum bytes | Required operations included |
|---|---:|---|
| Continue partial snap or skip decision | 4 | TST TURN_SNAP; short BNE to the fixed continuation |
| Skip when no movement step is pending | 4 | TST $DE; short BEQ to the unchanged no-turn return |
| Preserve X and test the requested current-cell exit | 9 | PSHS X; LDA PLAYER_WANT; JSR ,X; TSTA; BEQ fallback |
| Commit an admitted direct turn | 16 | Store old direction; compute/store remaining snap; set step to 4; store requested direction |
| Test the old-axis edge | 7 | With old direction already in A for free: INCA; LSRB/DECA/BNE loop; BCC hold |
| Probe the projected center and its requested exit | 18 | Seed TEST_DIR with old direction; LBSR cm_step_test; seed requested TEST_DIR/A; LDX ,S; JSR ,X; TSTA; BEQ result |
| Restore saved X on return | 2 | At least one shared PULS X, even granting common return layout |
| Test the selected unsafe-corner bit | 8 | Four possible immediate BITB masks, 2 bytes each; pair-to-mask dispatch is granted free |
| **Optimistic floor before omitted routing** | **68** | **Sum of the required blocks above** |

The 68-byte practical floor exceeds the 59-byte allowance by 9 bytes. It is deliberately favorable: it assumes direction registers are already available for the state commit and old-axis test, grants pair validity and hazard dispatch for free, and excludes branches to nlt_yes/nlt_no, label-distance expansion, extra reloads, and parity/edge-path routing. If the 8-byte hazard-test row is also granted for free, the remaining required-operation subtotal is still 60 bytes, one byte above target before result routing. The 68-byte figure therefore is not a formal proof of every possible 6809 encoding; it is a discriminating floor for a practical same-ABI caller-only rewrite. A destructive variable shift would have to preserve/restore B or fetch the current graph again before checking the old-axis edge, and the omitted dispatch/routing work has positive cost. No source-only implementation meeting 59 bytes is evidenced. Any callback offload is a separate copied-runtime size problem, not a solution to this caller-only bound.

Same-scope offload check

Speculation: The existing name callback could make A mean “requested edge is open and this adjacent turn is hazard-safe,” while still returning the full graph byte in B. That would move pair/hazard work out of resident code but into the copied-name runtime. The pinned assignment records a historical copied-name size of 917/920 bytes and projects the current approved callback/call-site changes at +7, or 924/920. That projection is four bytes over before any added hazard code. The failed build did not assemble ladybug-highscore-runtime.bin/.lst/.map, so there is no receipt-bound callback size or saved-byte evidence. This offload is not a source-only size plan: it has no demonstrated copied-runtime capacity and cannot be counted as a fit.

The 576-byte geometry graph itself is unchanged in length. Cursor/node destinations move by +160 framebuffer bytes with the same record count and width. Neither generated-data change can supply the missing resident bytes. The helper remains at its historical $B880 end limit; the failed build did not reach a candidate helper map. Future FEAT-010 savings remain excluded.

Conclusion and lowest-cost recommendation

A body-only, same-ABI rewrite cannot meet the 59-byte pre-snap target under the optimistic operation floor. Moving the hazard computation into the copied callback has no proven 920-byte fit and worsens the existing +7 projection. Do not start another code rewrite or compile under this report. The lowest-cost same-scope action, if the parent wants to keep that scope open, is a source-only design that accounts for every operation and shows a complete pre-snap budget of at most 59 bytes while also showing a copied-name budget at or below 920. Current evidence does not supply such a design.
