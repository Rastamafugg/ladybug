Tail-accounting correction

The matched baseline name_late_turn span is 91 bytes: 49 bytes pre-snap plus a 42-byte tail. The tail is 34 bytes of snap/return/delta code plus the eight-byte nlt_deltas table. The failed candidate span is 217 bytes: 175 pre-snap plus that same 42-byte tail. Thus baseline routine code is 83 bytes plus eight data bytes. The earlier phrase “42-byte continuation and 8-byte table” double-counted the table. No target arithmetic changes: at a maximum 101-byte whole routine (baseline 91 plus the nonadaptive profile's 10-byte growth allowance), retaining the 42-byte tail leaves 59 bytes for pre-snap code. The existing 68-byte caller-only practical floor still exceeds that by nine bytes before omitted routing.

The existing stage callback's direction/result block can be replaced by the already-present ranking callback's mask-loop shape. This change is within the assigned callback portion and preserves the callback ABI: input A still holds the requested direction; TEST_X/Y and the graph lookup are unchanged; PAR5 has already been restored to $34; B is saved and restored; A is zero for a blocked edge and nonzero for an open edge; stack depth returns to its entry value; and X remains caller-clobbered for the resident caller to save.
