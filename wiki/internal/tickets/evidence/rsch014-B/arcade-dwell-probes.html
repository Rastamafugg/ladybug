scripts/capture_mame_gameplay.py writes one 192×240 BGRA32 image per rendered frame from --video-from, plus the complete 0x6000–0x6fff work-RAM sample on every frame. All live diagnostic phases were at or below 3,600 frames (60 simulated seconds) and completed in less than 60 seconds wall time. A marker timeout means only that the expected visible screen marker was not confirmed inside that phase. It does not establish that a page is absent, unreachable, or slow.

Reassessment and next discrimination

Last proven screen boundary: gameplay pixels. The high-score screen is documented as an existing attract-sequence state, but has not been visibly identified in these current invocations. The TMX frame-3310 property remains a historical source pointer; reclassify it as “does not locate the page in this run,” not globally wrong.

Current evidence changes the next step: source docs identify $605F bit 4 as demo-route mode. In the idle run, this bit is active at both historical candidate frames; in the credited run it is clear. The harness frame counter starts in the first MAME frame callback and JSON uses that counter. The harness does not explicitly select an INI/config directory. Before any new capture, inspect the original high-score asset provenance and ROM screen/state handler, compare their frame origin and mode transitions with the current captures, and design a per-frame pixel/state marker. This lower-cost source/state review should determine whether a bounded natural-attract continuation or a deliberate game-over route has greater expected benefit. The latter would distinguish a true post-death table flow only if the ROM handler supports it; route/hazard outcome remains unconfirmed.

Class and verification: BUG-081 remains High-risk and Draft because two screen contexts and persistent framebuffer owners are involved. No subsystem expansion or class change is supported by these misses. Do not lengthen a phase or launch another route until that reassessment produces a discriminating plan with an authored/staged/ROM identity, visible marker, and deadline no longer than 60 seconds.
