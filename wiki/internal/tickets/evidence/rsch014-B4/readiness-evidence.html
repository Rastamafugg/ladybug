Decision boundary

The proposed BUG-081 acceptance target is 31 CoCo Vbord ticks per logo phase in both attract and high-score contexts. The arcade attract logo has a measured 31-frame dwell in the current MAME 0.220 capture. The high-score arcade dwell is not measured: the user explicitly assumes it matches the attract logo. That assumption is the high-score target and removes high-score reachability and measurement as gates. It must remain labelled as an assumption in the ticket and any future report.

Clock and conversion evidence

  1. src/enemy_runtime.s::framebuffer_irq_impl increments the 16-bit FRAMES counter in the Vbord IRQ. This establishes the hardware frame-count unit.
  2. src/adaptive_runtime.s::adaptive_clock atomically snapshots FRAMES. The adaptive src/main.s::mainloop calls the presentation entry $1900 once when the sampled count differs from its prior sample. If foreground work misses multiple Vbords, this path does not replay each missed count; the current timer writers increment once for that dispatch. A 31-call target would therefore not prove 31 elapsed Vbords.
  3. Attract attract_tick calls the common presentation timer once per presentation dispatch. presentation_attract_phase derives its existing phase from (PRES_TIMER - 6) >> 3. High-score highscore_logo_tick increments PRES_TIMER once per dispatch and derives its two-state phase from the same six-tick alignment and eight-call interval.
  4. assets/arcade/attract_actor_reference.json documents the established arcade-to-CoCo calibration: one captured 60-Hz MAME callback frame maps to one 60-Hz CoCo Vbord tick. This conversion is project reference evidence; the B4 source review did not collect a new CoCo runtime trace.

The retained BUG-052 current-ROM receipt independently records high-score phase publications eight presentation-timer calls apart, the correct phases on both owners, and unchanged non-logo pixels. This supports the current writer-path description. It does not measure an arcade high-score dwell and does not establish that the proposed 31-Vbord target is already implemented.

Acceptance still required after approval

The source and retained receipts are sufficient to set a coherent proposed clock contract; they are not implementation acceptance. Before Ready, the design must count elapsed Vbord samples across dispatch gaps, leave the decorative-actor writer unchanged, compare its cadence with a same-Vbord-condition baseline, and leave the shared presentation timer intact. Actor dwell changes remain BUG-080. A future approved repair must then measure 31 elapsed CoCo Vbord intervals between published logo phases on both contexts, prove current ROM/helper identity before interpreting live state, verify both persistent framebuffer owners, and show logo-only changes with actors and non-logo pixels unchanged. The high-score 31-frame comparison is an assumed target, not measured arcade evidence.
