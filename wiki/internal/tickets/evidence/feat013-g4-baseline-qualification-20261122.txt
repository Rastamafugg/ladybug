Offline capture-failure review
The first checkpoint selected by capture_performance_baseline.py is frame_render_impl at $09D4, inside copied low RAM $0800-$17FF. The XRoar wiki warns that trap snapshots taken inside this copied module can serialize that page incorrectly and directs saved renderer captures to resident main_render. This makes $09D4 unsuitable as a retained snapshot point, but does not explain why the file was absent.

The script's run_xroar uses subprocess.run without a host-side timeout or child-process cleanup. The first outer 60-second cap wrapped bash/python; its exit status was not retained and build/perf-baseline.log is empty. This explains the weak failure record, not the missing snapshot. The second direct $C175 attempt did not include -ram-init 0, which the script uses for cold capture, so it was not a controlled comparison.
