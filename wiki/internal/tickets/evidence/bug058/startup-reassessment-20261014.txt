Cause assessment
The active source artifact is 622 bytes, SHA256 a938542f728044875ecb413725f11aa73e4b53fd7a9cc71f334a89915dde220a. The failure payload confirms staged bytes match that artifact. At the failing comparison, physical destination and CPU destination are identical to each other (SHA256 d0496185759f9c4027f1ee3648a7c573cc5f350db509b205e50875ed5d1376be), but differ from the expected image at byte 0; 618 of 622 bytes differ. This is not a matching copied prefix. The physical destination is page $38, as specified by the frozen map, and the PFT module on that page separately passes its full live-byte proof.

Source control flow explains the phase ordering. Startup sets DP=0 and clears PRES_MAGIC. The mainloop calls $1900; the pinned runtime artifact has JSR $1900 at $C129, so its expected return PC on entry is $C12C. The PFT source checks PRES_MAGIC, then initializes it to $A5 and calls start_screen; start_screen enters MODE_LOAD while the selected screen is being prepared. A nonzero PFT return takes the presentation/reset branch and stores PRES_MODE in AD_MODE_BYTE without invoking the active-driver installer. Therefore AD_MODE_BYTE equality or non-$FF value is not independent proof that the active image owns $038F.

After a PFT returns zero, the mainloop compares PRES_MODE with AD_MODE_BYTE; only if they differ does it call adaptive_install_active. That routine maps stage page $3D and copies exactly 622 bytes from $B792 to $038F on destination page $38, then the mainloop resets/caches the mode and calls AD_WORK_EXEC at $038F. A PFT stop is before this decision, and the source does not guarantee a copy at every PFT. The retained receipt has no $038F entry proving that the copy branch ran. At a source-qualified $038F execution entry, require the whole image to match source, stage, physical destination, and live CPU bytes. Do not accept a prefix or weaken strict identity; no observer stop is available inside the copy loop.

The leading cause is observer ordering: read_snapshot calls qualify_active_driver_safe before applying the lifecycle/gameplay availability gate, and the safe wrapper only treats AD_MODE_BYTE=$FF as not installed. The observed nonmatching image and CPU/physical equality fit the pre-install page-$38 owner. A loader/mapping defect is not supported by the retained facts: active stage bytes match and CPU/physical destination bytes agree; the PFT code and PAR0 proof also pass. No observation-tool or hardware cause is indicated. The exact PRES_MODE/PRES_MAGIC at stop #4 was not serialized, so the specific loader substate there remains unproven.

C116 handling remains conservative. C116 is the source-qualified resident mainloop SYNC, but it closes a timing interval only when a current source-qualified $038F worklist entry is open and its validated outer return is reached. A startup/menu C116 with no open worklist is raw bootstrap traffic and must not produce a sample, residual, or slowdown claim.
