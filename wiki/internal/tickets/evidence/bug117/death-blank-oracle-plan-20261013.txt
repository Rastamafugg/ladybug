Source findings

- src/main.s death_tick moves PLAYER_FB during state 2 in the swing/rise path, stores the moving address, and starts state 3 with DEATH_TIMER=37. State 3 does not advance PLAYER_FB during the blank countdown. Its renderer suppresses death-art drawing at state 3. The blank boundary is a real rendered background restoration opportunity, but the timer value alone is not a pixel oracle.
- src/enemy_runtime.s framebuffer_prepare_back (around line 1356) hydrates the chosen owner’s old-valid flag, saved row count, and old framebuffer address into PLAYER_BG_VALID, PLAYER_VISIBLE_ROWS, and PLAYER_OLD_FB. It sets PLAYER_BG_PTR to that owner’s save-under buffer: A=$A300 or B=$AB00. PLAYER_BG_PTR ($00A2) is a buffer address, not the framebuffer position. actor_closure_restore (around line 1148) temporarily puts PLAYER_OLD_FB into PLAYER_FB and restores the old rectangle from that buffer. framebuffer_capture_back (around line 1432) later clears metadata validity after restoration and writes the current logical PLAYER_FB into FBM_PLAYER_FB. The capture therefore replaces the retired rectangle address with the logical address. FB_META_A=$A900 and FB_META_B=$AA00 keep player-valid at offset 2, saved row count at offset 3, and framebuffer address at offsets 4-5; each owner save-under is 128 bytes. The observer already reads the 512-byte metadata area from physical page $34 at offset $0900, and its low-RAM snapshot includes PLAYER_OLD_FB ($0067), PLAYER_BG_VALID ($006A), and PLAYER_BG_PTR ($00A2).
- The observer’s only owner_history assignment is in _front_pose. Its live caller in _irq_done is guarded by DEATH_STATE==0 and a current entry. Death-rise frames never enter that history writer. At timer37, _irq_done looks up (FRONT owner, current logical PLAYER_FB); if absent it silently skips the oracle. The retained trace proves the matching history key is absent for this run, so the pixel comparison did not run.
- scripts/build_screen.py compile_death_sprites reuses compile_sprite_codes with DEATH_CODES. Owner-retirement interpretation

The renderer restores the previously published address for the selected BACK owner, not necessarily the current logical PLAYER_FB. After that restoration, capture records the current logical address and invalidates the old saved-under metadata. The address needed for the just-restored rectangle remains in PLAYER_OLD_FB for the stopped render transaction; after IRQ publication, identify the owner and retired address from that field, then bind it to the last committed state-2 death-pose record for that same owner and generation. Do not key the blank oracle on current PLAYER_FB, and do not require the two owners’ pointers, frame indices, ordinals, or saved-under bytes to match.

The A/B owners need separate latest-visible-state-2 records because their commits alternate. dt_wings increments through timer 143, publishing the final state-2/angel pose, and on the next callback with timer 144 it changes to state 3/timer 37. Which owner is BACK at that transition determines which buffer is restored first; the other owner can still hold its own earlier committed state-2 pose until its next state-3 render. Retain each owner’s own last visible state-2 art, actual rendered pointer, owner-local saved-under, visible rows, source frame, and commit sequence. A timer37 proof uses the currently committed FRONT owner’s record and retired pointer. The existing acceptance predicate is singular, so do not require a second owner commit unless the canonical ticket is revised; retain the second owner record to prevent borrowing the wrong buffer’s evidence and to make any later owner commit independently checkable.

At the timer37 commit, independently retain current logical PLAYER_FB and verify captured FBM_PLAYER_FB names that logical value with player-valid/rows cleared. This is bookkeeping evidence, not the rectangle to compare as if it had been drawn. Compare actual FRONT pixels at PLAYER_OLD_FB to that same owner’s saved-under snapshot, after confirming PLAYER_OLD_FB equals the owner’s last committed state-2 rendered pointer and the owner save-under bytes still match the captured snapshot. A mismatch is a hard pixel failure. For the observed pointer $62A4 with virtual framebuffer base $2000, the rectangle begins at row 106, byte-column 100; its full 8-byte width and 16 rows end at column 107 and row 121, within the 160x192 framebuffer. Thus this observed rectangle is not clipped. Apply the normal visible-row/width bounds to each newly observed pose rather than assuming all future pointers share this geometry.
