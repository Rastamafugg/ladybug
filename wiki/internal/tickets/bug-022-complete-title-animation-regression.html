Approval brief

Objective and motivation

Restore the moving actor surfaces on the LADYBUG_PROFILE=complete title screen while retaining the combined instructions and demo runtime profile. The previous title animation implementation is present and the current regression is caused by profile guards that exclude the complete profile.

Evidence and baseline

The current complete ROM is build/ladybug.rom, SHA-256 98d3ae7347a2deff4d6b43ab6f8feb2a79e279271e95b612186c6bbfcd3c190a. Current source src/presentation_runtime.s suppresses PRESENTATION_ATTRACT_OVERLAY in both load_done and attract_tick through ifeq BUG011_DEVELOPMENT_PROFILE; complete defines that flag as 1. The prior working revision e468402 calls the same overlay from both locations, including the PRES_ACTOR_PHASE=$FF initialization during title hydration. Generated actor records and underlays remain present; the complete presentation module is 1227 of 1280 bytes.

Reproduction

  1. Build with LADYBUG_PROFILE=complete bash scripts/build.sh build.
  2. Run the combined image and wait for the attract title.
  3. Observe the static title instead of the actor animation retained by the prior demo-screen branch.

Observed versus expected

Observed: complete-profile title animation calls are conditionally omitted even though their generated data and fixed helper remain available.

Expected: the complete title renders the authored actor set and advances its animation on each natural attract tick, with both framebuffer owners receiving the same completed surface.

Scope

In: profile-guard correction in src/presentation_runtime.s, complete-profile title hydration and natural animation verification, regenerated artifacts, and synchronized ticket/wiki evidence. Out: actor artwork, animation timing, instructions choreography, demo movement, game rules, loader/MMU layout, and release/development semantics.

Scenarios and edge cases

  • Complete profile first title hydration initializes and draws the actor overlay.
  • Complete profile advances the overlay during natural attract ticks before instructions transition.
  • Complete profile retains the BUG-021 instructions transition and demo-runtime installation.
  • Release and development builds retain their existing title behavior.
  • Both framebuffer owners publish identical title pixels after hydration and after an animation tick.

Options and recommendation

Recommended: include COMPLETE_PROFILE in the two existing overlay guards. This reuses the proven actor path and changes no authored data, runtime ABI, or map selection.

Rejected: copying or redesigning actor data, because the generated surfaces already exist and the prior implementation supplies the required behavior.

Discriminating test

Compare complete-profile title captures before and after one natural overlay tick. Require the expected actor-phase/state change, authored actor ownership, and equal FRONT/BACK visible hashes without altering the instructions or demo markers.

Acceptance criteria

  • Complete title hydration calls the existing actor overlay path.
  • Natural complete attract ticks animate the authored actor set before the instructions transition.
  • Both framebuffer owners contain the expected title output at the required checkpoints.
  • BUG-021 instruction transition and FEAT-004 demo transition remain passing.
  • Development and release builds and existing focused checks pass unchanged.
  • Capacity remains within the current presentation, resident, and GMC limits.
