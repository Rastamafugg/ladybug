Scope

In: the root README.md; a roms/<tag>.rom naming convention with an image for every existing version tag; currently one image, roms/1.0.0-alpha.rom; a dated project status; clone/build/run prerequisites and instructions; a README link to the prebuilt alpha image; a fresh standard complete-profile build and exact artifact comparison; a local retarget of 1.0.0-alpha; and a forced update of the matching published tag on origin so both point at the final commit containing the README and ROM.

Out: changes to game source, build scripts, CI, or gameplay; building historical tags beyond those present when work starts; creating a GitHub Release object; automatic future tag builds; unverified runtime/gameplay claims; and physical hardware validation.

Scenarios and edge cases

  • Fresh clone path: a Linux or WSL reader follows repository-root clone, build, and XRoar launch steps. Risk covered: setup instructions omit a required step or use the wrong working directory.
  • ROM-only build: a reader builds the image without XRoar installed. Risk covered: emulator-only prerequisites are incorrectly presented as build requirements.
  • Tag archive coverage: each tag in the initial local and published tag inventories has one matching roms/<tag>.rom; currently the only tag is 1.0.0-alpha. Risk covered: a tagged version is missing its binary or the image is mislabeled.
  • Tag destination: local and published 1.0.0-alpha resolve to the final commit containing both requested deliverables. Risk covered: the source tag remains stale or points to an incomplete commit.
  • Status accuracy: the dated wording separates implemented scope from active polish and unfinished hardware qualification. Risk covered: the README implies release readiness or physical hardware acceptance.
  • Link and command accuracy: repository links resolve and shell commands match the current default profile and script interface. Risk covered: dead project guidance or stale build instructions.

Options and recommendation

Recommend storing one binary per tag as roms/<tag>.rom and listing the available prebuilt image in the root README. The current image is exactly 65,536 bytes (64 KiB); this adds repository storage only and does not change the four-bank GMC image layout or runtime memory use. A separate manifest/release system is unnecessary for the one existing tag, and leaving the image only in ignored build/ would not preserve it with the version. Build from the current main tree only after confirming that all ROM-producing inputs remain identical to the source tagged 1.0.0-alpha. The local and published tag will be moved to the final commit; updating the published tag requires a force push and changes the commit GitHub associates with that version. No other tags are present in the current local or published inventories.
