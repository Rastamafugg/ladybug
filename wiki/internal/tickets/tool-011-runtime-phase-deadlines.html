Approval brief

Recommendation / work / reason: replace renewed per-stop waits with one elapsed deadline per named observer phase, including nested RPC reads/steps. This prevents executor time being consumed by continued irrelevant markers. It changes host test boundedness only.

Observed baseline: source 96ccc0e8df646acffccb06aafee6b5eb18384eb0; pinned files. BUG-018 capture_draw and BUG-010 phase-cycle loops have no cumulative time limit; BUG-014/019 finite loops reuse the full timeout on every iteration. BUG-019 has 92 timer stops and up to 96 framebuffer stops. Those are source iteration bounds, not measured wall duration. Defaults are 30 seconds per wait for BUG-010 and 60 for the other three; they currently do not guarantee a whole-phase bound. No new live timeout is needed to establish the host-loop defect.

Confirmed cause / reproduction / discriminator: present repeated valid-but-unwanted draw/phase markers to the actual loop under fake time. The existing function resets each wait budget and keeps running; the desired marker never appears. For finite release loops, make each stop consume part of the phase budget: total time must expire instead of granting another full wait. The shared MonitorClient._read currently clamps an expired budget to 0.1 seconds, allowing a continuing message stream to outlive its deadline; correct that expiration boundary as part of the same host repair.

Class and material risks: Standard: four observer entry points plus their existing shared client are affected; preserving all nested paths/cleanup exceeds Compact scope. No game-side ownership/protocol/loader/MMU/framebuffer algorithm or hard memory/timing target changes. Risks: accidental per-callback deadline reset, nested RPC overrun, stale success after expiry, excessive cleanup delay, and shared-client acknowledgment/event regressions. Existing gameplay timing targets remain independent.

In scope: scripts/verify_bug010_phase_cycles.py, verify_bug014_initial_enemy_release.py, verify_bug018_runtime.py, verify_bug019_enemy_nest_exit.py, verify_bug009_monitor_input.py and one focused standard-library module scripts/test_runtime_phase_deadlines.py. Thread remaining time through each named phase and its existing call/read/step/breakpoint helpers; preserve prior state-write/scenario permissions. Reuse the monotonic remaining-time idiom in verify_bug012_full_coverage.py without importing its executable main path. Use the existing MonitorClient instance to enforce the shared budget; no general framework or protocol extension.

Out: broad migration of every historical script, server/native monitor changes, web work, new test-side routing, seed sweeps, longer runtime bounds, different guest writes, production code/ROM repairs, changed pixel or performance oracles and full historical live scenario matrices. Shared client tests cover adjacent consumers without rewriting them.

Target / outcome / measurement: every named phase ends by its configured elapsed deadline (valid 0<timeout≤60 seconds; BUG-010 default stays 30). A success marker observed at or after expiration cannot pass. All blocking call budgets are positive and no larger than the remaining phase time; reject expired budgets before I/O. Fixed callback caps bound fast marker streams independently of time. Cleanup has a separately recorded maximum 2-second process wait and no fresh diagnostic reads. Real OS scheduling can delay host return; report any overrun instead of inventing a timing tolerance or game-speed conclusion. Offline fake-time tests verify exact deadline behavior without real sleeping.
