TOOL-002 — Tiled MCP starter internal

Create a bounded design and package scaffold for a future Tiled resource MCP server.

Approval brief

Objective and motivation

Start D:\retro\tiled-mcp as a repository that a later agent can use to design and build an MCP plugin for Tiled project resources, image assets, and translation to target assembly data. The repository must use Ladybug's existing Tiled/JSON/assembly pipeline as a concrete template while remaining reusable for other targets.

Evidence and baseline

The target repository currently contains only its MIT license. Ladybug already contains hand-authored TMX/TSX resources, JSON asset contracts, Python generators, generated assembly includes, binary payloads, and capacity guards. Official Tiled documentation for JSON maps, layers, objects, custom properties, templates, custom export formats, and scripting is the public reference baseline.

Scope

In: repository README, Python package scaffold, resource inventory model, translation interface boundaries, agent handoff/design documentation, installation/configuration/use notes, capability roadmap, Ladybug template mapping, tests for the starter model, and links to public Tiled references. Out: a working MCP transport, Tiled UI plugin, write-back mutation commands, image conversion implementation, target assembly compiler, authentication, remote resource fetching, and exposure of every Tiled feature.

Scenarios and edge cases

Inventory a project containing TMX, TSX, JSON maps, external tilesets, templates, images, and project files; distinguish unsupported or unknown files; preserve relative paths; handle malformed JSON; recognize global tile IDs versus local tile IDs; represent custom properties/classes without losing raw values; keep source and generated artifacts separate; and allow a later target adapter to reject unsupported transformations explicitly.

Options and recommendation

Use a dependency-light Python core with a neutral intermediate resource model and adapter interfaces. Keep MCP transport and Tiled-in-process scripting outside the core. This follows Tiled's documented JSON/TMX model and avoids making Python export-plugin compatibility the foundation of the system.

Acceptance criteria

The repository can be installed locally, inventories a fixture or supplied directory deterministically, exposes typed resource and translation boundaries, documents how a future MCP agent should proceed, links the public Tiled references, includes Ladybug's source/derived/delivered artifact mapping, and passes package tests and syntax checks. No claim of MCP compatibility is made until an actual MCP server is implemented and tested.

Architecture and ownership

Core model: resource discovery and normalized metadata. Format adapters: TMX/TSX/JSON/project/template readers. Target adapters: translation from normalized resources to target-specific assembly or binary plans. Protocol adapter: future MCP tools/resources/prompts. CLI: local inspection and deterministic diagnostics. The core owns no Tiled UI state and no target-specific memory assumptions.

Assignment contract

  • Owned artifacts: all new files under D:\retro\tiled-mcp; Ladybug changes are limited to this ticket, ticket index, and project log unless separately approved.
  • Constraints: no dependency on a running Tiled process; no network access at runtime; preserve raw resource paths and values; fail closed on malformed input; do not claim unsupported Tiled features.
  • Required commands: python -m compileall for package sources, package tests, CLI inventory against a fixture, and repository status/diff inspection.
  • Evidence: test output, deterministic inventory output, source tree, public-reference links, and an explicit non-goal list.
  • Commit: one bounded starter commit; no push or merge authority.
  • Completion report: commit, files, tests/results, supported starter behaviors, excluded features, and next-agent handoff.

Verification and completion

Pending implementation and QA. MCP protocol behavior is intentionally unverified and out of scope for this starter.
