TOOL-003 — Read-only MCP surface internal

Define the first MCP resources and model-controlled tools for Tiled project inspection.

Approval brief

Objective and motivation

Define a small, read-only MCP contract for D:\retro\tiled-mcp that exposes Tiled project files, normalized metadata, references, validation, and dry-run translation planning. The contract must let a later implementation agent build the server without mixing MCP transport, filesystem security, Tiled parsing, or Ladybug target policy.

Evidence and baseline

The current target repository contains a deterministic local inventory core, GID decoding, and target-neutral translation interfaces, but no MCP transport or resource URI namespace. The design baseline is MCP specification revision 2026-07-28, with legacy 2025-11-25 compatibility treated as an implementation decision. Ladybug's existing Tiled maps, TSX assets, Python generators, oracle vocabulary, and target-capacity rules are the first target-profile reference.

Scope

In: URI namespace, resource templates, project manifest, raw and normalized resource representations, five read-only tools, JSON Schemas, provenance, caching, pagination, diagnostics, security rules, and implementation order. Out: MCP transport code, Tiled UI control, source mutation, image editing, network fetching, authentication implementation, assembly emission, and target runtime changes.

Scenarios and edge cases

Open a configured project alias; list resources deterministically; read text and binary files; inspect JSON maps and tilesets; resolve external TSX, template, and image references; handle malformed JSON, missing references, unsupported formats, infinite maps, GID transform flags, symlink escapes, path traversal, oversized files, duplicate aliases, stale cache data, and a dry-run translation that reports unsupported target features without writing files.

Options and recommendation

Use standard MCP resources for raw and normalized context, and tools only for queries or computations that need arguments. Do not create a raw-read tool that duplicates resources/read. Use a custom tiled:// URI scheme with project aliases and query-encoded relative paths; never expose host absolute paths as the public identifier.

Acceptance criteria

The design names exact resource URIs and templates, defines the five tool inputs and outputs, specifies read-only annotations, deterministic ordering and pagination, error and diagnostic semantics, path and symlink containment, provenance and cache rules, protocol-version handling, and the first implementation sequence. The design is reviewable without claiming that MCP behavior is implemented.

Selected design

Resources are application-controlled context. Tools are model-controlled functions and must be marked read-only, idempotent, non-destructive, and closed-world. The first server advertises resources and tools capabilities without change notifications until a filesystem watcher is deliberately implemented. The core remains deterministic and local.

Project aliases map to an allowlisted root configured outside the protocol payload. The server canonicalizes every requested path, rejects traversal and symlink escapes, and returns private, provenance-bearing content. A resource read returns text for text formats and base64 binary content for images or other binary files.

Approval and first implementation assignment

Approval: On 2026-08-17 the user approved the read-only MCP design, including the tiled:// namespace, configured project aliases, raw and normalized resource separation, five read-only tools, deterministic ordering, provenance, diagnostics, cache rules, and explicit scope exclusions. This approval does not authorize write operations, live Tiled control, remote fetching, assembly emission, or runtime changes.

Assignment objective: Implement the first design step: a dependency-free project registry and URI/path security boundary that later MCP resources and tools can call. The implementation must not add MCP transport or parse Tiled formats.

Owned artifacts and boundary

  • Repository: D:\retro\tiled-mcp; isolated worktree D:\retro\tiled-mcp-worktrees\tool-003-project-boundary; branch codex/tool-003-project-boundary; base target revision 12bba94.
  • Implementation files: add src/tiled_mcp/project.py for validated project aliases and root containment, add src/tiled_mcp/uri.py for tiled:// project/file URI parsing, and add tests/test_project_boundary.py.
  • Permitted synchronization: update README.md only if required to document the accepted project configuration shape and local test command. Do not modify Tiled resources, Ladybug source, generated assembly, or ROM artifacts.
  • Core integration: reuse ResourceRecord and existing deterministic inventory behavior where useful. Do not change resources.py discovery semantics in this assignment.

Required behavior

  • Accept a JSON-serializable configuration shaped as {"projects": {"alias": "root"}}; validate aliases against ^[A-Za-z0-9._-]+$, resolve roots, and reject missing or non-directory roots.
  • Parse only the approved project URI forms needed by this step, preserving project alias and query-decoded relative POSIX path without exposing host paths.
  • Reject absolute paths, drive-letter paths, UNC paths, URL schemes, empty paths, traversal segments, encoded traversal, and backslash traversal before filesystem access.
  • Resolve the candidate path and prove it remains under the configured root. Reject symlink or junction escapes with stable diagnostics such as PROJECT_UNKNOWN, PATH_ABSOLUTE, PATH_TRAVERSAL, SYMLINK_ESCAPE, and RESOURCE_NOT_FOUND.
  • Keep the parser and registry transport-independent. No MCP SDK, server loop, resources/list, resources/read, tool handler, Tiled parser, or target adapter is part of this assignment.

Verification contract

  • Run python -m unittest discover -s tests -v; all existing and new tests must pass.
  • Run python -m compileall -q src tests.
  • Run python -m tiled_mcp inventory tests/fixtures and confirm unchanged deterministic output.
  • Force tests for valid in-root resolution, unknown aliases, malformed aliases, POSIX and Windows absolute paths, UNC paths, URL schemes, literal and percent-encoded traversal, missing resources, and an outside-root symlink or junction. Symlink support must not be silently skipped; an environment that cannot execute that security test remains incomplete.
  • Inspect the final diff for read-only behavior, no generated artifacts, no network dependency, and no changes outside the assigned files.

Evidence and handoff

Retain test output, compile output, deterministic inventory output, the security-case list, and the final diff. Produce one bounded commit with no push or merge authority. The completion report must state the commit, exact files, results versus each verification requirement, rejected experiments, residual risks, and whether the parent can integrate the commit. Parent integration must rerun the combined tests and inspect the target branch before changing the ticket to Verification.
