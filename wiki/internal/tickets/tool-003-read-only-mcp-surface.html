TOOL-003 — Read-only MCP surface internal

Define the first MCP resources and model-controlled tools for Tiled project inspection.

Approval brief

Objective and motivation

Define a small, read-only MCP contract for D:\retro\tiled-mcp that exposes Tiled project files, normalized metadata, references, validation, and dry-run translation planning. The contract must let a later implementation agent build the server without mixing MCP transport, filesystem security, Tiled parsing, or Ladybug target policy.

Evidence and baseline

The current target repository contains a deterministic local inventory core, GID decoding, and target-neutral translation interfaces, but no MCP transport or resource URI namespace. The design baseline is MCP specification revision 2026-07-28, with legacy 2025-11-25 compatibility treated as an implementation decision. Ladybug's existing Tiled maps, TSX assets, Python generators, oracle vocabulary, and target-capacity rules are the first target-profile reference.

Scope

In: URI namespace, resource templates, project manifest, raw and normalized resource representations, five read-only tools, JSON Schemas, provenance, caching, pagination, diagnostics, security rules, and implementation order. Out: MCP transport code, Tiled UI control, source mutation, image editing, network fetching, authentication implementation, assembly emission, and target runtime changes.

Scenarios and edge cases

Open a configured project alias; list resources deterministically; read text and binary files; inspect JSON maps and tilesets; resolve external TSX, template, and image references; handle malformed JSON, missing references, unsupported formats, infinite maps, GID transform flags, symlink escapes, path traversal, oversized files, duplicate aliases, stale cache data, and a dry-run translation that reports unsupported target features without writing files.

Options and recommendation

Use standard MCP resources for raw and normalized context, and tools only for queries or computations that need arguments. Do not create a raw-read tool that duplicates resources/read. Use a custom tiled:// URI scheme with project aliases and query-encoded relative paths; never expose host absolute paths as the public identifier.

Acceptance criteria

The design names exact resource URIs and templates, defines the five tool inputs and outputs, specifies read-only annotations, deterministic ordering and pagination, error and diagnostic semantics, path and symlink containment, provenance and cache rules, protocol-version handling, and the first implementation sequence. The design is reviewable without claiming that MCP behavior is implemented.

Selected design

Resources are application-controlled context. Tools are model-controlled functions and must be marked read-only, idempotent, non-destructive, and closed-world. The first server advertises resources and tools capabilities without change notifications until a filesystem watcher is deliberately implemented. The core remains deterministic and local.

Project aliases map to an allowlisted root configured outside the protocol payload. The server canonicalizes every requested path, rejects traversal and symlink escapes, and returns private, provenance-bearing content. A resource read returns text for text formats and base64 binary content for images or other binary files.

Assignment contract

  • Owned artifacts: D:\retro\tiled-mcp\docs\mcp-read-only-surface.md, target README/architecture links, and this ticket plus the Ladybug tooling summary and log.
  • Constraints: design only; no MCP transport or parser implementation; follow the current MCP specification without coupling the core to a specific SDK; preserve raw Tiled values and explicit target diagnostics.
  • Required review: schema review, path-containment review, deterministic-order review, and comparison against the official MCP resources/tools specification.
  • Evidence: design document, official MCP/Tiled reference links, rejected alternatives, and local-link validation.
  • Commit: one bounded documentation commit; implementation requires renewed approval and a separate Ready assignment.

Verification and completion

Pending user approval of the design before implementation. No MCP code is authorized by this ticket.
