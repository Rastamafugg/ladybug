Research brief

Objective and motivation

Design a repeatable, source-legal setup that reaches a live gameplay score above the current first-ranked high-score record while leaving the table itself unchanged. The check should show TOP still comes from that first record. The user reports that naturally scoring past the current leader would require roughly 100,000 points and is too time-consuming for the current stage. This missing test setup must not block the FEAT-012 baseline.

Evidence and baseline

BUG-044 is Done and states that TOP remains the highest-ranked committed table record until an eligible name-entry result is committed. Scenarios and edge cases

  • Live score below and above table row one: TOP name and score remain the values in row one while current score changes independently.
  • Table state changes only through the existing accepted record/name-entry path; this task does not redefine the separate row-one, lower-ranked, and no-commit outcomes in FEAT-013.
  • If no safe, repeatable setup exists without changing production behavior or writing guest state, document that result and leave the test deferred.

Options and recommendation

Ordinary play preserves a natural route but is too costly for the current manual stage. The recommended research is to inspect existing source-legal fixtures or initialization seams and propose one bounded setup with a clear row-one oracle. Do not use arbitrary memory writes or random play to force the rare score.

Acceptance criteria

  • Identify a controlled setup tied to a named source revision, profile, and artifact or fixture.
  • State how expected TOP is independently read from committed table row one, and give a negative control where the live score is below or equal to TOP.
  • Keep the shipped scoring and ranking behavior unchanged; if no compliant setup is found, report that and leave the scenario deferred.
