Approval brief

Objective: bring the existing six instruction presentation timing windows below the unchanged maximum of 27,000 CPU cycles, preserving screen pixels, choreography, input pre-emption and all gameplay clocks. This is a bounded optimization of an existing lookup. FEAT-005's delivered C3 menu contract remains Done; its older parent timing gate remains open until integrated acceptance passes.

Class: High-risk. The shortcut depends on PAR5 page mapping and operates near a hard module boundary. Incorrect mapping can decode unrelated bytes as pixel destinations and overwrite runtime code. This determines mapping-integrity, dynamic-pixel and capacity verification; it does not justify an unrelated renderer or audio rewrite.

Baseline: complete adaptive keyboard ROM at source revision 163d0be13daeeea4f6ec2a1e6b027ef54e13447c, ROM SHA-256 7caa58c1ff1ef84b0b107b4b5cc46850244de1f2729dbc60f3af1f46abfac32e. The retained six-window measurement has maximum 27,450 cycles at timer 128, exceeding the target by 450. These are maximum sampled inclusive presentation call costs, not averages or a whole-game maximum. Baseline receipt.

Recommendation: in the shared-text branch of src/instruction_runtime.s, use the already mapped event-page window for the colour-pointer table instead of calling the generic cold-pointer mapper for every table lookup. Retain the generic mapper for the selected colour stream. At the X multiplier path, explicitly call the existing event_ptr_a before the direct lookup, because that path has no preceding event lookup to establish the page. No new state, loader, helper, asset format or scheduling policy is introduced.

In scope: only production file src/instruction_runtime.s, its generated build products and focused reuse of existing verifiers. Out of scope: audio, gameplay rendering, input bindings, B2 debt policy, authored TMX content, choreography timings, legacy non-shared instruction branch, new memory reservations, and changing the 27,000-cycle target. Any additional production target or mapping contract change requires renewed approval.

Observed prototype: isolated ROM a4c6de907b5dfeda76e6040f174ee93ecf468cf5243b4554f2c584510be726ad based on the same revision; 36 samples across timer windows 31, 127, 1503, 1534, 1599 and 1630 have maximum 26,574 cycles, leaving 426 cycles. The maximum is 876 cycles below the baseline maximum, a 3.19% reduction. This is observed diagnostic evidence, not integrated acceptance. The X mapping trace completed 999 read/surface pairs with zero mismatches and no observed write to the watched enemy-code byte. Nine static screen guards pass. Dynamic whole-sequence pixel verification remains required.

Capacity: retained keyboard prototype authored instruction code ends at $06A8 from origin $0300: 936/938 bytes, leaving two. The packaged binary occupies the complete 938-byte padded slot. Resident 8149/8192, assets 7671/7680, presentation 1262/1280, mapped adaptive 198/220 and banked adaptive 696/698. Each fraction is observed used bytes / fixed capacity, not a projection. Joystick qualification and current combined BUG-110 fit must pass before Ready. Later headroom changes must be measured rather than inferred from these isolated figures.

Static page proof: the retained build maps event records at cold offset $2000, twelve bytes each, and the sixteen colour-pointer words at $20C0-$20DF. Both occupy cold page $3B, with pointer-table CPU address $A0C0. Ordinary callers immediately invoke event_ptr_a before the lookup; the corrected X caller now does the same. Acceptance must recheck these generated bounds after integration rather than assuming the layout remains fixed. Reviewable one-file prototype patch.
