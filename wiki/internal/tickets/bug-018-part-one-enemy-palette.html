Approval brief

Objective and motivation

Render the part-one gameplay enemy with the matching attract actor's pen colours while preserving shape, animation, direction, and behavior.

Reproduction and observed versus expected

On integrated ROM f412729c1ef09989666c360e81eba0c570556fe0c9e089cc0ecc059dec6c518d, gameplay and attract actor cell (27,5) share source codes 9, 10, and 11. Observed: gameplay maps raw pens 1/2/3 to palette slots 12/5/2 (dark red/green/yellow). Expected: the accepted attract actor maps them to 9/5/6 (purple/green/white).

Golden path

  1. Attract publishes the accepted actor colours.
  2. Part one selects the same source family.
  3. Every direction and phase maps raw pens 1/2/3 to 9/5/6.
  4. Transparency and maze pixels remain unchanged.
  5. Later types retain independently defined palettes.

Scope

In: per-family sparse palette generation, part-one live/demo frames, all directions/phases, pixel/RGB verification, packing. Out: shapes, attract rendering, AI, release timing, unverified later palettes, and global GIME palette values.

Edge cases and risks

  • The current global pen map affects every gameplay enemy.
  • Raw pen order is dark/light/white while authored tuples are white/light/dark.
  • Rotation must preserve pen identity.
  • Per-family data must fit existing sparse pages.

Recommendation

Generate palettes per enemy family and use BUG-010 metadata as the part-one oracle. Do not alter shared GIME slots or add a demo-only recolour.

Acceptance criteria

  • Every part-one phase/direction matches raw-pen mapping (0,9,5,6).
  • Transparency and shapes are unchanged.
  • Later families have explicit retained mappings and no unintended changes.
  • Natural live/demo RGB captures, mutation-rejecting proof, packing, build, and GMC verification pass.

Discriminating test

Decode every part-one sparse frame against source pens. Mutating one phase to (0,12,5,2) must fail; comparing only colour sets is insufficient.

Selected architecture and viability

Keep the existing type-major, direction-major, phase-major 130-frame sparse index and runtime frame-number ABI. Replace the generator's single global pen map with eight explicit gameplay-family maps passed into frame expansion: family one uses (0,9,5,6); families two through eight each retain (0,12,5,2). The two appended BUG-010 horizontal-flip shapes retain their existing explicit map and index positions. No runtime palette state, new renderer path, GIME palette change, or src/enemy_runtime.s change is permitted.

A no-write design projection against baseline c42f863 changes only frames 0–15 and produces projected enemy payload SHA-256 688af5ca9c98802096aa50cf47ef65b78077205f7d77a4d70415bbfb4d51029d. Because all substituted colours remain nonzero, sparse transparency, command boundaries, stream lengths, index addresses, page crossings, and copy layout are unchanged: enemy payload remains 23,005/24,576 bytes with 290 padding bytes and 1,571 spare bytes. The current build also remains projected at 3,965 CPU-readable GMC bytes spare and a 4,090/4,096-byte enemy runtime module. This establishes viability without changing the approved scope or targets.
