Observed mechanism and alternatives

src/main.s:read_joystick disables the audio master using PIA2 CRB $34, selects right X/Y, sweeps the DAC through joy_read_axis, and leaves restoration to src/audio_runtime.s:audio_select_gmc. The shared selector necessarily interrupts cartridge audio during right-axis sampling. This confirms the source mechanism, not a new acoustic measurement of the reported buzz. See the input reference and sound reference.

Joystick-preserving candidates are a shorter conversion (successive approximation or direction-threshold tests), immediate audio restoration, or reduced sampling cadence. These may reduce audible interruption, but cannot guarantee elimination through the documented shared selector. Lower cadence risks input latency and a different audible modulation. An independent digital direction interface or independent audio output changes the hardware contract and is excluded. Existing muting means simply adding mute-around-poll is not a new remedy.

Discriminating test: compare the same build profile, cues, audio settings, and gameplay segment with analog sampling enabled versus direct keyboard input with zero axis conversions. A quiet keyboard run and buzzing joystick control support polling as the cause. Buzz in both leaves an additional cause unresolved. Missing audio comparison is incomplete verification.

  • Natural sequence: boot, add credit with 5 or 6, start with 1, enter live gameplay, use each arrow, release, turn at a wall, and resume. Opposite arrows cancel their axis; perpendicular ties use a documented deterministic priority matching the existing horizontal tie preference.
  • Input isolation: instrument or inspect the keyboard build to prove zero analog conversions during live gameplay and name input, with cartridge audio selection preserved. This covers accidental joystick fallback and shared PIA side effects. Merely mapping host arrows to an emulated joystick does not satisfy this criterion.
  • Audio comparison: retain matched short recordings or user listening results for normal polling versus keyboard-only gameplay, including a cue and a quiet interval. Target: no reported polling-related buzz in the keyboard build and intact intended cues. Physical hardware confirmation is required for a hardware silence claim; emulator results must be labeled accordingly.
  • Adjacent regression: natural demo input remains director-owned; qualifying name entry moves and stops with arrows. The opt-in joystick build retains centered and cardinal behavior. These cover separate input consumers without a rendering-owner matrix.
  • Build and capacity: run the standard complete-profile build and existing relevant guards. Record deltas versus the local pre-change build. Known BUG-031 non-complete capacity failures are baseline issues, not new passes; do not enlarge or repair those profiles within this ticket.
