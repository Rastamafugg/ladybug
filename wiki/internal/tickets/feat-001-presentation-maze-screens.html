Restore the full central maze on presentation maps and add the game-over map.

Approval brief

Objective and motivation

Update coco-enter-high-score-screen.tmx and coco-instructions-screen.tmx so the central 24×24 maze fills the playfield exactly as in the current gameplay map, while retaining the presentation text. Add coco-game-over-screen.tmx using the same 40×24 CoCo layout and a static GAME OVER presentation. This supplies the missing Tiled assets for the Phase 9 presentation flow and keeps screen layouts consistent with gameplay.

Evidence and baseline

The structural baseline is tiled/coco-screen.tmx, a 40×24 map whose authored maze occupies columns 8–31 and all 24 rows. The current enter-high-score and instructions maps are also 40×24 maps, but their presentation layers replace the central maze with a panel. The observations are from the current working-tree TMX files on 2026-08-06; they are structural map observations, not runtime measurements.

Scope

In: the two named TMX updates; a new 40×24 game-over TMX map; full central-maze coverage; static placement of the existing presentation text; map metadata and layer names needed to identify each screen; XML and grid validation; wiki ticket and log updates.

Out: runtime state-machine sequencing, game-over behavior in src/main.s, changes to scripts/build_screen.py, changes to the authoritative gameplay map, new glyph extraction, new sprites, palette changes, and emulator acceptance of a runtime screen that is not yet wired into the game.

Scenarios and edge cases

  • Enter high score: the full maze remains visible in the centre; the phrase YOU GET TOP HI SCORE is readable in the unused lower-left area and does not overwrite maze cells or the right HUD.
  • Instructions: the full maze remains visible in the centre and the existing instruction content remains readable without obscuring the maze's structural boundary or side HUD.
  • Game over: the new map is 40×24, uses the established CoCo side layout, shows the full centre maze, and contains a readable static GAME OVER message.
  • Map integrity: every visible cell is covered, all active tiles resolve through chars_raw2bpp.tsx, and no map contains malformed CSV or an out-of-bounds placement.
  • Regression: the existing gameplay map and its build output remain byte-for-byte unchanged when this asset work is compiled through the normal build.

Options and recommendation

  • Recommended: use the gameplay maze as the central background contract, then place presentation text in separate visible layers or non-maze cells where the requested layout permits. This preserves the visual and structural baseline and keeps the assets useful for later runtime sequencing.
  • Rejected: retain the panel-only central layouts. They are the current baseline that prompted the request and do not satisfy the full-maze presentation requirement.
  • Out of scope: composing the maze at runtime under a panel. That would create a new rendering path and is not required to author the requested Tiled assets.

Acceptance criteria

  1. Each affected map parses as a 40×24, 8×8 orthogonal Tiled map with valid CSV layers and the expected screen-role metadata.
  2. For both updated maps and the new game-over map, central columns 8–31 match the 24×24 authored maze region of tiled/coco-screen.tmx unless a documented presentation glyph is intentionally overlaid.
  3. YOU GET TOP HI SCORE, the instructions, and GAME OVER are readable in their intended locations, with no accidental clipping, overlap with the side HUD, or out-of-bounds cells.
  4. The new map is named tiled/coco-game-over-screen.tmx, uses the shared character tileset, and follows the established metadata and layer conventions of the existing presentation maps.
  5. Focused XML/grid validation passes for all three maps, and scripts/build.sh build plus the existing arcade-fidelity verification pass without changes to the gameplay screen output.
