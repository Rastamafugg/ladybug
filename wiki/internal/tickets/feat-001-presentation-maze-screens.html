Approval brief

Objective and motivation

Update coco-enter-high-score-screen.tmx and coco-instructions-screen.tmx so their visible maze is the arcade-faithful outer maze border only. Add coco-game-over-screen.tmx with the matching arcade presentation border and any unique arcade content that appears above or below that border relocated to the lower-left CoCo HUD. The inner maze walls, gates, gameplay dots, and other interior gameplay content are not part of these presentation maps because they do not appear on the matching arcade presentation screens.

Evidence and baseline

The current working-tree TMX files on 2026-08-06 show 40×24 presentation maps whose central presentation area is bordered but whose intended arcade presentation content is distinct from the gameplay map. tiled/coco-screen.tmx remains the authoritative gameplay map, but its interior walls and gates are explicitly excluded from this ticket. Existing arcade-reference properties and the measured presentation maps provide the source contract. The arcade game-over border and unique upper/lower text were previously verified against the Lady Bug arcade game-over screenshot (192×240, source page accessed 2026-08-06). A new MAME 0.277 run on 2026-08-06 captured the instructions state at frames 1000/1280 and the game-over state at frames 6920-7040; the emulator output is 240×192 and uses the same full-height presentation frame. No tracked arcade image capture for the qualifying-score name-entry state was present; the existing map property remains a MAME 0.220 forced-qualifying-score reference.

Scope

In: the two named TMX corrections; a new 40×24 game-over TMX map; arcade-faithful outer maze-border cells and presentation content; relocation of game-over content above or below the arcade border to the lower-left HUD; shared character tileset and screen-role metadata; XML, grid, and visual validation; ticket, decision, and log updates.

Out: inner maze walls, gates, gameplay dots, gameplay entities, runtime state-machine sequencing, changes to src/main.s, changes to scripts/build_screen.py, changes to the authoritative gameplay map, new glyph extraction, new sprites, palette changes, and emulator acceptance of a runtime screen not yet wired into the game.

Scenarios and edge cases

  • Enter high score: the arcade-faithful border is visible; YOU GET TOP HI SCORE is rendered in the empty lower-left area; the qualifying-score grid remains readable; no inner gameplay walls or gates are present.
  • Instructions: the arcade-faithful border and measured instruction content remain readable; no inner gameplay walls or gates are present.
  • Game over: the new map uses the verified arcade border/content arrangement; unique arcade content above or below the border is relocated only to the lower-left HUD; no invented interior gameplay structure is present.
  • Border fidelity: every border cell matches the selected arcade reference orientation, position, glyph, and colour treatment, subject only to the documented CoCo side-HUD adaptation. The CoCo frame occupies columns 8-31; cap rows are 0-1, side rows are 2-22, and the bottom row is 23, matching coco-level-start-screen.tmx and the MAME captures.
  • Map integrity: every visible cell is covered, all active tiles resolve through chars_raw2bpp.tsx, and no map contains malformed CSV or an out-of-bounds placement.
  • Regression: the authoritative gameplay map and its build output remain unchanged.

Options and recommendation

  • Recommended: preserve or reconstruct the measured arcade presentation border and content for each screen, then apply only the established CoCo relocation of above/below-border content to the lower-left HUD. Keep the presentation maps separate from the gameplay maze.
  • Rejected: using the full gameplay maze as a presentation background. The earlier implementation commit 1f4df6a did this and is rejected by the corrected requirement because its inner walls and gates do not match the arcade presentation screens.
  • Out of scope: runtime composition of an arcade presentation border or the game-over state machine.

Acceptance criteria

  1. Each affected map parses as a 40×24, 8×8 orthogonal Tiled map with valid CSV layers and the expected screen-role metadata.
  2. The enter-high-score and instructions maps contain only the arcade-faithful presentation border and their matching presentation content in the central area; no gameplay inner walls or gates are added.
  3. The new game-over map contains the verified arcade presentation border and matching unique content, with any content above or below that border relocated to the lower-left HUD as documented.
  4. YOU GET TOP HI SCORE, the instructions, and GAME OVER are readable in their intended locations without clipping, accidental HUD overlap, or out-of-bounds cells.
  5. Border and presentation-cell comparisons against the selected arcade reference pass for all three maps, with the source frame or capture revision retained in the ticket.
  6. Focused XML/grid validation, visual inspection, scripts/build.sh build, and python3 scripts/verify_arcade_fidelity.py pass without changing the gameplay screen output.
