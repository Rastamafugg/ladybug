Approval brief

Objective and motivation

Make the HUD Lady Bug walk straight right until fully beyond the playfield edge during life entry, without a downward turn, before the normal maze entry begins.

Reproduction and observed versus expected

Observe the initial life-entry marker path. Current source sets the marker south-facing and advances it down screen. The requested path is horizontal to the right edge and fully offscreen.

Confirmed source cause and baseline

initial_entry_tick in src/main.s starts from $8994, sets PLAYER_DIR and PLAYER_FACE to DIR_SOUTH, then adds $0140 for each of 12 scheduled steps. It hands off to the existing northward maze entrance afterward. This confirms the current trajectory differs from the requested direction. No current-snapshot runtime result exists because the RSCH-014 compiler prerequisite blocks the build.

Scope, scenarios, and acceptance

In: marker orientation and trajectory, right-edge clipping/cleanup, and handoff to the existing maze-entry phase. Out: life count, death art, enemy progression, animation dwell, and general travel-speed changes.

Acceptance requires an uninterrupted right-facing horizontal walk from the HUD origin to fully outside the 192-pixel playfield; zero downward-turn frames; no input, collection, or collision during transfer; complete removal of the marker footprint; then the existing maze entry. Test the actual right-edge crossing on the selected owner and one reversed starting-owner run only if the compositor has independent owner history. Pixel reads/writes must be clipped to the visible framebuffer. A source path or rendered frame beyond row/column bounds fails.

Class, risks, and pre-Ready gates

High-risk: the horizontal exit crosses persistent framebuffer edge/clipping boundaries and hands off into normal player state. Design target is Proposed, but implementation viability is not established: exact marker start position, offscreen boundary step, clipped save-under/restore ownership, code fit, and runtime artifact identity are unresolved. Keep existing player tick cadence; do not invent an arcade speed or fixed tick count.

Dependencies and recommendation

Depends on the RSCH-014 current-ROM build gate. BUG-085 reuses this departure and depends on its approved direction and edge-cleanup contract. First prove right-edge geometry and a bounded clipped compositor fit, then specify the natural and forced validation command.
