BUG-007 — Presentation startup stall Superseded

Bound presentation-map preparation and guarantee a fresh attract entry.

Identity and ordering

  • Status: Superseded by revised FEAT-002
  • Created / updated: 2026-08-08 / 2026-08-08
  • Priority / order: P1 / superseded
  • Owner: unassigned
  • Dependencies: retained as diagnostic evidence for FEAT-002; no independent implementation
  • Source revision: current working tree, 2026-08-08; no commit assigned

Approval brief

Objective and motivation

Cold launch must reach the attract presentation without a long apparent hang, and a warm emulator reset must not bypass attract mode because the presentation magic byte remains set.

Reproduction

  1. Build build/ladybug.rom with bash scripts/build.sh build.
  2. Launch the canonical GMC image with 512 KB RAM and -cart-autorun.
  3. Observe the first presentation entry and the visual output before the attract title.
  4. Repeat a reset or relaunch in the same emulator session and observe whether the runtime enters live level one immediately.

Observed versus expected

Observed: the first call at $1900 executes inflate_maps synchronously. A no-trace GDB snapshot at approximately four seconds found the CPU in $1AEB with PRES_REMAIN=$035C; a second snapshot after another four seconds reached the main loop. A separate snapshot found PRES_MODE=MODE_NAME after the accelerated demo sequence, where the current FEAT-003 name-entry implementation intentionally holds. On warm state, PRES_MAGIC=$A5 causes the initialization branch to be skipped.

Expected: startup publishes the attract title within a bounded preparation interval, and every reset/relaunch enters attract unless an explicit live start edge is accepted.

Scope

In: incremental or otherwise bounded map preparation, first-frame publication, presentation state initialization, and warm-reset/relaunch behavior. Out: visible high-score records, name traversal, sound, gameplay rules, and new presentation assets.

Competing causes and discriminating evidence

  • Confirmed: synchronous six-map inflation is the startup stall. The CPU is inside inflate_emit during the delay, not waiting in mainloop or missing the $1900 hook.
  • Confirmed: fresh randomized RAM does enter presentation_flow_tick at $1900 and changes PRES_MAGIC from a non-$A5 value.
  • Confirmed from source: a retained PRES_MAGIC=$A5 accepts the existing presentation state without reinitializing it, so warm reset can bypass attract.
  • Not yet accepted as cause: framebuffer pending or IRQ deadlock. The diagnostic snapshots reached the main loop after inflation, and the existing natural-plus-forced verifier passes its required paths.

Discriminating test: compare first-frame wall time and first presentation state for cold randomized RAM, warm reset with PRES_MAGIC=$A5, and a forced staged-inflation build. Require a title-frame publication before the bound and require PRES_MODE=MODE_ATTRACT after each reset.

Acceptance criteria

  • Cold launch reaches and publishes the attract title within a measured bound agreed before implementation.
  • Map preparation does not monopolize the presentation hook beyond the agreed per-frame budget.
  • Warm reset and relaunch cannot enter normal gameplay solely because stale presentation RAM contains $A5.
  • Existing attract, instruction, demo, credit, level-start, framebuffer ownership, GMC, capacity, and FEAT-003 boundary proofs remain passing.
  • The completion report retains cold/warm timing, state snapshots, capacity impact, and any rejected preparation strategy.

Assignment contract

  • Owned artifacts: src/presentation_runtime.s, any bounded verifier added for BUG-007, this ticket, ticket index, lessons learned, and log.
  • Constraints: preserve the locked 1280-byte module, 12939-byte cold payload bound, 512-byte future-sound margin, native hardware execution, and FEAT-003 ownership of visible high-score rendering.
  • Verification: clean build, cold and warm GDB/XRoar startup probes, canonical run profile, focused presentation flow, GMC proof, capacity checks, and arcade-fidelity regression.
  • Commit: one bounded implementation commit after explicit approval and Ready status.

Decision log

  • 2026-08-08 — User reported apparent launch hang and direct level-one startup.
  • 2026-08-08 — Debugger reproduced the delay in inflate_emit during synchronous six-map inflation; the $1900 hook itself is entered on fresh launch.
  • 2026-08-08 — Warm-reset stale-magic bypass recorded as a separate startup-state condition. No implementation started.
  • 2026-08-08 — Superseded by the revised FEAT-002 shared-engine/direct-streaming proposal. Startup, reset, input, and natural visible-flow correction modify the same presentation module and verification boundary, so a separate BUG-007 implementation would duplicate ownership.
