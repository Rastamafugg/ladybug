BUG-016 Tiled presentation build regression In Progress

Make the presentation compiler accept the current Tiled layer contract.

Approval brief

Objective and motivation

Restore a successful presentation build after the Tiled screen update while preserving the authored separation between static map art, sprite-location markers, and animation-frame layers. The failure blocks all cartridge builds at the active presentation asset stage.

Evidence and baseline

At revision 76d930bd55fc31a84c7959c4eb8f5b5dc852160d, with only generated listing/symbol files and ladybug.tiled-session dirty, bash scripts/build.sh build reaches maze and gameplay-screen generation, then fails at scripts/build_presentation.py:427 with ValueError: /mnt/d/retro/ladybug/tiled/coco-level-start-screen.tmx: unsupported tileset 'sprites_raw2bpp'. flatten_map() selects visible layers except Sprite Animations; the current level-start Sprite Locations layer is therefore flattened into the static map and contains raw sprite GID 633 at (16,7) and (32,13). The updated instruction Sprite Locations layer also contains raw sprite markers 593 and 633, but parse_instruction_contract() currently requires its exact record set to be character metadata. These are source-data and compiler-contract observations, not emulator observations.

Reproduction

  1. Use revision 76d930b with the current Tiled files.
  2. Run bash scripts/build.sh build.
  3. Observe the unsupported sprites_raw2bpp error from compile_map().

Observed versus expected

Observed: the build stops before presentation payload emission. The static-map compiler consumes a metadata layer containing raw sprite markers.

Expected: static presentation maps compile from their static character layers; sprite-location markers and unsupported animation layers are either consumed by an explicit compiler contract or excluded from static-map flattening without contaminating the atlas.

Scope

In: scripts/build_presentation.py, role-specific Tiled layer selection and validation, the current six presentation TMX maps, focused compiler tests or verifiers, generated presentation outputs, and this ticket's evidence. Out: new runtime rendering for vegetable markers, pickup markers, or logo-frame animation; gameplay behavior; new asset formats; memory-map changes; and high-score/name-entry behavior.

Scenarios and edge cases

  • All six current presentation maps compile in their existing order.
  • Level-start and instruction sprite-location markers do not enter the static character atlas.
  • Existing instruction character metadata remains exact and valid.
  • Unknown raw-sprite markers, misplaced character metadata, duplicate required layers, and unexpected visible layers fail with explicit diagnostics.
  • Attract and high-score logo-frame layers retain a declared non-runtime ownership decision and do not silently overwrite the static map.
  • Generated payload, manifest, include, capacity, and assembly outputs remain internally consistent.

Options and recommendation

Recommended: make presentation layer selection role-specific, explicitly classify marker/animation layers, and validate raw sprite markers separately from static character cells. This preserves the authored Tiled data and fixes the current build contract without inventing runtime behavior.

Rejected for this ticket: deleting the new sprite markers or logo-frame layers, because that discards the authored screen enhancements; implementing runtime logo and marker animation, because it expands the approved outcome into new presentation behavior and requires a separate ticket.

Discriminating test

Run the focused compiler against the current six maps and assert that the selected static layers contain no GID in the sprites_raw2bpp range. Separately parse the declared marker layers and assert the known marker coordinates/GIDs and the existing instruction character metadata. Then run the complete build. A passing build without these layer assertions is insufficient because it could silently discard or flatten the new authored data.

Acceptance criteria

  • bash scripts/build.sh build passes at the repaired revision.
  • All six current TMX maps compile and the generated manifest records the expected map count and payload bounds.
  • Static maps contain only supported character tiles; marker and animation layers are not silently merged into static output.
  • Instruction metadata and current raw sprite marker coordinates are validated by a focused current-revision test.
  • Existing presentation, sparse, GMC, capacity, Python syntax, and assembly checks pass.
  • The completion report records generated hashes, tests, capacity result, rejected experiments, and any residual runtime ownership gap.

Assignment contract

Owned artifacts: scripts/build_presentation.py, a focused scripts/verify_bug016_presentation_layers.py verifier, scripts/build.sh integration for that verifier, generated presentation outputs under build/, and this ticket, ticket index, implementation lesson, and wiki log. Existing dirty generated enemy listing/symbol files and ladybug.tiled-session are user-owned and must not be included in the bounded commit.

Implementation constraints: define one exact layer contract for each of the six current screen roles; select static character layers by semantic name rather than Tiled visibility; parse metadata and animation layers separately; validate the current instruction and level-start raw-sprite marker coordinates/GIDs plus existing instruction character metadata; reject duplicate, missing, unknown, misplaced, or unsupported layers with explicit diagnostics; record deferred logo-frame ownership without implementing it. Do not edit TMX assets or runtime rendering.

Verification: run python3 -m py_compile scripts/build_presentation.py scripts/verify_bug016_presentation_layers.py, the focused verifier against all six TMX maps including negative contract mutations, bash scripts/build.sh build, the existing presentation and sparse verifiers included by that build, and the wiki link/lint check. Retain focused-layer output, generated manifest hashes and bounds, full build capacity output, rejected experiments, and residual ownership gaps. Deliver one bounded commit and a completion report with tests, result versus target, changed capacity, and residual risk.

Design and packing resolution

The compiler now owns one exact semantic layer contract for each screen role. Static layers accept only chars_raw2bpp; metadata, compiler-consumed animation, and deferred logo-frame layers are separately named and validated. Instruction and level-start mixed metadata records are exact, including transformed GIDs, coordinates, tileset ownership, and the twenty-two current raw-sprite markers. The manifest records each role contract, authored-frame hash, emitted-map hash, marker record, and deferred owner.

Exact static selection exposed 248 map tiles plus twenty instruction-runtime tiles, exceeding the one-byte 256-tile protocol before the synthetic coin tile. Widening tile IDs, changing the runtime decoder, or changing memory ownership was rejected as outside scope. The already approved development-first policy permits name-entry flow to be omitted: the compiler still compiles and hashes the authored name-entry map in sixth position, but emits an explicit constant-black placeholder for that unreachable runtime slot and omits eight name-entry-only glyph constants. This yields 255 tiles and preserves the existing map and runtime protocol. Release-profile restoration remains owned by PERF-005.

Rejected experiment: using the high-score map as the unreachable name-entry placeholder retained a duplicate compressed stream and measured 11,261/10,874 cold bytes, failing the source guard by 387 bytes. The constant-black placeholder measured 10,653/10,874, leaving 221 cold bytes; no failed artifact was retained.
