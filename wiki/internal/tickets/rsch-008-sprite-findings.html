Authored art and generated destination

The enter-high-score TMX has one raw sprite marker: GID 545 at screen cell (19,22), in the Sprite Locations layer (TMX line 120). The generator requires exactly that marker at scripts/build_presentation.py:114, resolves it once at lines 1179–1185, and emits one sparse cursor stream. It computes one start destination from the same cell at lines 1271–1275; the current generated value is PRESENTATION_NAME_ENTRY_CURSOR_DST=$894C (include line 109). The Enter High Score Overlay is tile art and contains no second raw cursor marker. Static source therefore does not support duplicate authored Lady Bug artwork.

Confirmed dynamic defect

capture_initial seeds PLAYER_FB, PRES_NAME_PTR_A, and PRES_NAME_PTR_B to $894C and copies the initial underlay into both owner buffers (src/demo_runtime.s:1159–1175). On each update, update_name_frame records the selected BACK owner, prepares/maps it, restores that owner's saved rectangle, redraws fields, captures the current PLAYER_FB, draws the cursor, and finishes publication (:1178–1191). The defect is that restore_cursor uses the owner pointer saved in PRES_NAME_PTR_A/B (:1209–1234), while capture_owner updates that pointer to the current destination only after restoration (:1236–1251), and draw_cursor draws at current PLAYER_FB (:1253–1255). After a move, owner A can retain node N in its pointer; when owner B is selected, B restores its old marker underlay at its own old pointer while the global PLAYER_FB is already N, then captures/draws at N. On subsequent movement the selected owner can leave N visible and draw N+1, producing a chain or apparent jumping between two spots. This is a confirmed source-level owner-coordinate mismatch; it is not duplicate sprite art.

The 16×16 restore/capture geometry itself is internally consistent: four two-byte loads per row and a 152-byte row stride at :1193–1207, :1221–1233. The failure is the destination pairing, not the rectangle size.

Publication and alternate paths

The cursor update ends through PRES_MAIN_FB_FINISH, so the bad pixels are committed through the normal persistent A/B publication boundary rather than being an IRQ-only drawing artifact (src/demo_runtime.s:1183–1191). The regular cursor frame is supplied through the shared player draw entry at $0812 (:1253–1255); the gameplay implementation similarly saves then draws through draw_player (src/main.s:3899–3902). No second name-entry draw call or stationary runtime sprite source was found. src/main.s gameplay save/restore is a separate path and does not explain a name-entry-only duplicate without a cross-owner handoff failure.

  • Rejected: duplicate authored sprite: one GID 545 marker and one generated cursor stream are present in the current TMX/generator contract.

  • Rejected as primary cause: publication alone: publication exposes the already-composed BACK image; the source defect occurs before finish when restoration targets a stale owner destination.

Repair direction and smallest future check

Preserve one current cursor destination per framebuffer owner and pair each saved underlay with that owner's previous destination. During update, restore the selected owner's saved destination, then update only that owner's destination to the new PLAYER_FB, capture there, draw there, and finish. Do not use one global current pointer for restore. This matches the approved FEAT-003 owner contract and requires no authored-art change.

Smallest discriminating runtime check: on a revision-identified artifact, force marker → node 42 → node 43 across two publications, proving live module/source identity first. Capture both owner frames after each commit and assert that the old node is restored to its pre-cursor bytes, the new node contains exactly one 16×16 cursor, and no third location changes. A timeout means the probe boundary or observation path failed; it does not prove target slowness. Then repeat with starting owner reversed. Residual uncertainty includes any independent timer or map-overlay corruption.
