Baseline and confirmed source facts

Source baseline is fe160ae; the parent verified that the current core source files match the baseline build receipt. Arcade input identity and selected ROM bytes are recorded in the RSCH-014 Step D evidence, generated rate-policy model, and selected disassembly.

On local MAME 0.220, DSW0 bit 1 selects the Easy/Medium or Hard/Hardest rate table; MAME reports Easy as the default, with no local DIP override. The active part counter is incremented from zero to one before first play and again at each later transition. The arcade selector indexes the offset table with the active counter directly, so active Part N uses index N. The earlier counter-zero-as-Part-1 interpretation is rejected. Counter 51-255 uses offset 16; the arcade counter itself wraps 0xFF to 0x00. This is distinct from the CoCo's STAGE 255-to-1 progression.

Under the default Easy/Medium profile, stage-start codes are Parts 1-6: 0x10; 7-8: 0x12; 9: 0x10; 10-14: 0x12; 15-17: 0x15; 18-50: 0x18. Under Hard/Hardest they are Parts 1-2: 0x10; 3: 0x12; 4: 0x10; 5-6: 0x12; 7-8: 0x15; 9: 0x12; 10-11: 0x15; 12-13: 0x18; 14: 0x15; 15-17: 0x18; 18-50: 0x20. Codes mean average coordinate steps per enemy dispatcher: 0x10=1.0, 0x12=1.19921875, 0x15=1.5, 0x18=1.796875, and 0x20=2.0. Within each part, the index is min(15, part_offset + ($61B7 >> 4)). The model contains per-part offsets and every code-change threshold for both profiles.

The elapsed counter starts at zero. Timer $61B6 starts at 96 logical gameplay-loop calls, reloads at 60, and increments $61B7 at expiry until it saturates at 0xF0. The first elapsed bucket is reached after 996 loop calls; later buckets are 960 calls apart; bucket 15 begins after 14,436 calls. A credited natural Part-1 MAME capture now measures one source boundary: $61B7=0x0F spans callbacks 1589–1648 and 0x10 spans 1649–1708, 60 callbacks each. An exact enemy pixel/pose transition crosses the same boundary. This calibrates one Part-1 elapsed interval to raw MAME callbacks, not CoCo logical calls or later-part progression. No post-vegetable rate branch was found.

CoCo src/main.s::reload_box_timer already matches the arcade border thresholds: Part 1 uses 9 box ticks, Parts 2-4 use 6, and Part 5 onward uses 3. CoCo src/enemy_runtime.s::et_find_movement instead gates on LAST_FRAME & 1 and applies fixed framebuffer movement deltas, with no part or elapsed-rate selector. This is a confirmed source-policy mismatch. Current frame-indexed CoCo behavior across a natural level transition has not been measured, so causal attribution to the user's report remains open.
