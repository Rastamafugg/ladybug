Keep credited gameplay active until the game-over and optional high-score sequence completes.

Approval brief

Objective and motivation

After a credit and Player 1 start, the live game must own execution until all lives expire and the game-over plus applicable high-score flow finishes. Presentation timers must never terminate an active credited session.

Reproduction

  1. Launch the cartridge.
  2. Add one credit and press Player 1 start.
  3. Play without exhausting the final life.
  4. Observe the game return to the first attract screen when a timer expires.

Observed versus expected

Observed: an active one-player game exits to the first attract screen on a timer. This is one user observation; the exact timer, caller, and presentation state at the transition are not yet captured.

Expected: live gameplay has no attract timeout. Only final-life expiration enters game over; game over enters high-score entry when eligible or completes directly; only completion of that sequence returns to attract.

Scope

In: live-session state ownership, presentation timer reset/isolation, game-over transition, optional high-score handoff boundary, and credit/start lifecycle regression. Out: demo duration and autonomous movement, high-score name implementation, game-over visual redesign, and two-player mode.

Golden path and edge cases

  1. Credit/start transfers ownership from presentation to live gameplay.
  2. Gameplay continues across arbitrary elapsed time, ordinary deaths, and respawns while lives remain.
  3. Final-life expiration transfers to game over exactly once.
  4. Game over transfers to eligible high-score entry or directly completes.
  5. Only completion of that terminal path starts the attract title.

Credit presses during gameplay, held start, stage transitions, timer wrap, death animation, nonqualifying scores, and future qualifying-score entry must not create an early attract transition.

Options and recommendation

Recommended: trace the first unexpected start_screen(PRESENTATION_MAP_ATTRACT) call and separate live-session ownership from attract/demo timer state. Preserve the existing shared state machine rather than adding a second gameplay loop. Suppressing the symptom with a larger deadline is rejected.

Discriminating test

Run natural credited gameplay beyond the observed timeout while recording presentation mode/context/timer, death/lives state, and every caller that requests the attract map. A forced final-life path must then prove that attract is requested only after game-over and optional high-score completion.

Acceptance criteria

  • Natural one-player gameplay remains active beyond the former timeout with lives remaining.
  • No presentation, demo, or credit-screen timer requests attract during live gameplay.
  • Ordinary death and respawn preserve live-session ownership.
  • Final-life game over and both qualifying/nonqualifying high-score branches return to attract exactly once at completion.
  • Credit/start pre-emption, stage transitions, demo flow, framebuffer ownership, performance, and capacity checks pass.
