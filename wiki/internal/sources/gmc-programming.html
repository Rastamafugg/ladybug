Programming the Game Master Cartridge internal

External programming notes for GMC banking, SN76489 sound, MPI routing, emulators, and VGM playback.

Source identity

Programming the Game Master Cartridge is a publicly viewable Google document. It was accessed and ingested on 2026-08-30. The document exposes no revision identifier, author metadata, or publication date in the rendered view; claims below therefore use the access date as the source revision marker.

Extracted source facts

  • Non-ROM programs can reach GMC hardware through an MPI by routing SCS to the GMC with $FF7F; the document recommends a GMC in MPI slot 1 when a fixed slot policy is acceptable.
  • The GMC provides up to 64K of bank-switched ROM. Each bank exposes almost 16K because the CoCo cartridge exceptions occupy the $FFXX range and, on the CoCo 3, the $FEXX range.
  • The document identifies $FF40 as the write-only bank-select register and $FF41 as the write-only SN76489 register.
  • The SN76489 uses a recommended 4 MHz oscillator, has no readable status, and requires at least 32 on-board oscillator cycles between writes. Oscillator frequency changes require corresponding tone-period changes.
  • Cartridge audio must be routed through the CoCo analog mux. The example writes $34 to $FF01, $3F to $FF03, and $38 to $FF23.
  • The SN76489 tone generators power on enabled at high volume. The document recommends writing attenuation values $9F, $BF, $DF, and $FF before enabling cartridge audio, with sufficient spacing.
  • VGM data and raw converted streams are possible input formats. The document also points to conversion tools for clock-rate transposition, sampling-rate correction, and raw playback output.
  • Example emulator commands use an XRoar GMC cartridge and a MAME GMC extension. The document notes that MAME later renamed games_master to gmc.

Comparison with Ladybug

The comparison target is the approved FEAT-006 design, not a completed audio runtime. Current assembly has no shipped sound service or $FF51 write path.

Aligned decisions

  • Ladybug uses a four-bank, 64K GMC image and treats the cartridge-visible bank payload as almost 16K per bank.
  • The loader selects banks and copies executable or data payloads during boot, then runs the game from RAM. This is more conservative than bank switching during gameplay and protects the persistent framebuffer mapping.
  • FEAT-006 targets the GMC's 4 MHz single SN76489, uses register commands rather than samples, and reduces the arcade's two-chip audio to one chip.
  • FEAT-006 schedules semantic events in a bounded foreground service, emits only changed register bytes, forbids audio sequencing in the IRQ, and requires reset/startup muting.

Intentional differences

  • The document's MPI guidance is for programs that are not distributed on a GMC. Ladybug's shipped image already requires the GMC and does not add an MPI dependency.
  • The document emphasizes VGM/raw playback. Ladybug instead compiles MAME PSG traces into compact semantic command records so event ownership, interruption, channel arbitration, and memory usage remain explicit. VGM remains a possible offline import or comparison format, not the runtime ABI.
  • Ladybug uses redundant CoCo 3 SCS aliases $FF50 for banking and $FF51 for sound. Local XRoar dispatches GMC behavior by SCS parity, but the project's MAME 0.220 evidence accepts only the primary $FF40/$FF41 addresses. This is an emulator-compatibility and physical-hardware acceptance issue, not a resolved portability fact.

Required follow-up

  • FEAT-006 must encode and verify the 32-oscillator-cycle write-spacing rule without polling a nonexistent status bit.
  • The audio service must initialize the cartridge-SND mux and prove that legacy DAC/PB1 state cannot override or contaminate the selected output.
  • Cold boot, warm reset, replacement, explicit stop, and game-over paths must prove that all four channels are muted before any new cue is exposed.
  • A compatibility test must compare $FF40/$FF41 and $FF50/$FF51 on the selected emulator and, later, on physical GMC hardware. No address change is authorized by this source ingest.

Limits and provenance

The document is a programming guide, not a hardware schematic or a physical validation report. Its register addresses, timing advice, audio mux sequence, emulator commands, and format recommendations are retained as source claims. Project acceptance still depends on the current cartridge strategy, sound plan, XRoar evidence, and physical GMC proof.
