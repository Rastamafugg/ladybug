Web app — Docker container internal

Full-stack containerization of the retro-dev web app: lwtools + patched XRoar + FastAPI + a headless X stack, viewable over noVNC.

Status 2026-07-16: deferred. This reproducible environment is preserved for future monitor/web-app work. It is not part of the active Ladybug game-development workflow.

Goal

Run the retro-dev web app in one self-contained Docker image instead of a hand-set-up WSL host. Artifacts live under web/docker/ (Dockerfile, docker-compose.yml, supervisord.conf, entrypoint.sh, README.md); a repo-root .dockerignore keeps the build context lean.

Two findings that shaped the design

  • The backend speaks XRoar's -monitor JSON-RPC stub, not GDB. web/backend/instance.py launches xroar-monitor … -monitor … -monitor-halt-on-start. So the image needs no m6809-gdb — the README/backlog references to a GDB stub are stale. See xroar §monitor.
  • The monitor extension lives only on the project fork. docs/reference/xroar is just an upstream clone (origin = 6809.org.uk) with the monitor work committed on a local ladybug/monitor branch (M1→M6a). That branch was migrated into the personal fork github.com/Rastamafugg/monitor-xroar and is now the single source of truth. The Docker build fetches exact commit 7787ad937b15102bf8cb8eb81b92e29f5ba7169d (M6b), not the mutable branch head.

Decisions (with rationale)

DecisionWhy
Full stack in the image, headless via Xvfb, with the GUI exposed over noVNC. The app's purpose is to drive XRoar's GUI; a backend-only container could not show the emulator. Xvfb gives a virtual display the SDL2 XRoar build draws to; x11vnc + websockify/noVNC export it to the browser at :6080/vnc.html.
Build lwtools 4.24 and xroar-monitor from source in a builder stage. lwtools is downloaded over HTTPS and checked against SHA-256 b38a2baa…d7b3dd; XRoar is fetched from github.com/Rastamafugg/monitor-xroar at exact M6b commit 7787ad9…. Both inputs execute code during the image build. Version labels or branch names alone are mutable; authenticated transport, archive verification, and an immutable Git commit make the toolchain input explicit and reproducible.
XRoar configured --with-sdl2 --without-gtk* --without-alsa/pulse/oss/jack, plus SDL_AUDIODRIVER=dummy in the env. SDL2 UI renders under Xvfb; GTK is unnecessary weight. Disabling XRoar's own ALSA support is not enough — XRoar's audio still goes through SDL2's audio layer, which probes ALSA and spews cannot find card '0' errors. Forcing SDL's dummy audio driver via env (inherited by every XRoar child) silences it cleanly; no sound device is needed.
Build context = repo root; Docker files under web/docker/. The backend computes PROJECT_ROOT two levels above web/backend/ and operates on the whole tree (scripts/build.sh, src/, build/). The image must contain the full repo.
Zero backend code changes. Emulator selected via XROAR_BIN; ROMs found via $HOME/.xroar. The existing _resolve_xroar_bin() env hook and XRoar's default ROM search path let the container wire everything through environment + mounts alone.
Process model under supervisord: Xvfb → fluxbox → x11vnc → noVNC → uvicorn. XRoar instances are not supervised. The backend spawns each XRoar as its own child (inheriting DISPLAY=:99); supervising them separately would fight the instance manager's lifecycle.
Ports bound to 127.0.0.1 only (8765 app, 6080 noVNC). Matches the app's "localhost-only, no auth" non-goal in the backlog spec.

The crash that blocked instance creation — SIGPIPE (fixed: M6b)

First end-to-end run: every POST /api/instances went launching → attaching → crashed with "monitor: no hello within 10s". Root cause was a bug in the monitor extension itself, exposed by the backend:

  • instance.py:_wait_for_port() opens a throwaway TCP connection to check the listener is up, then closes it.
  • That connect-then-close races send_hello() / the event broadcast write() against a now-closed socket. With the default SIGPIPE disposition the write() raised SIGPIPE and killed the whole XRoar process (observed exit code 141 = 128 + SIGPIPE), so the real attach hit connection-refused.

Fix (monitor commit M6b on monitor-xroar:ladybug/monitor): signal(SIGPIPE, SIG_IGN) in monitor_interface_new(). The write() calls then return -1/EPIPE, which the send paths already treat as best-effort, and XRoar survives the disconnect as monitor_interface_free()'s own comment always intended. No backend change was needed. Verified: instance creation now reaches halted, and registers / memory / framebuffer.png all respond against the live emulator.

Build-recipe gotchas (xroar from a clean clone)

The fork does not commit generated autotools output (configure, Makefile.in), so a fresh clone needs a full bootstrap. Each of these was a real build failure:

SymptomCause / fix
./configure: No such file or directoryNot committed. Run autoreconf -fi first (needs autoconf, automake, libtool).
win2rc … Can't locate Text/Iconv.pm → windows32/resources.h Error 2The resource generator needs Perl Text::Iconv. Install libtext-iconv-perl.
xroar.info Error 127Top-level make builds docs (needs makeinfo/texinfo). Don't build docs — build only the binary.
No rule to make target '../portalib/libporta.a'make -C src alone doesn't build the sibling static lib. Build make -C portalib first, then make -C src.
(local Windows checkout only) autogen.sh: set: Illegal option -CRLF line endings. Irrelevant to the Docker build (GitHub serves LF); only bites when mounting a Windows working tree.

Runtime note: the binary links vo_opengl, so the runtime stage needs libgl1 (in addition to libsdl2-2.0-0).

The one hard constraint — system ROMs

-machine coco3 + -cart-autorun boots through Tandy BASIC, so XRoar requires coco3.rom (32 K) and extbas11.rom (8 K). These are copyrighted and are not in the repo or image. The user supplies their own into web/docker/roms/, mounted read-only at the container's /root/.xroar (XRoar's default search path). The entrypoint warns if they are absent; without them instances start but never dispatch into the cartridge.

Run

cd web/docker
# drop coco3.rom + extbas11.rom into ./roms/ first
docker compose up --build
# http://127.0.0.1:8765         the web app
# http://127.0.0.1:6080/vnc.html  live XRoar view (noVNC)
