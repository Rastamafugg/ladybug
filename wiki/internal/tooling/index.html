Internal · tooling

Tooling internal

Active build and gdb-mcp tools used for Ladybug, plus preserved documentation for deferred tooling.

All tools are installed in WSL Ubuntu under ~/coco-tools/. The host scripts/build.sh shells out to WSL so building is one command from either side.

Build workflow

build-workflow — the full runbook: source → ROM → emulator. Driven by scripts/build.sh.

python-build-oracles — Python ownership, oracle definitions, generated artifacts, and the Python-to-ROM pipeline.

Web app — deferred

The web app and patched XRoar monitor are preserved, but they are not part of the active game-development loop. Current work uses gdb-mcp.

web-app-architecture — v2 design for the locally-hosted retro-dev web UI (FastAPI + web-components frontend wrapping XRoar lifecycle, monitor session, opcode annotation, configs, snapshots).

web-app-docker — full-stack container (lwtools + patched XRoar + FastAPI + headless X / noVNC) for running the web app in one Docker image.

Deploy target

Cartridge ROM image (16 KB, mapped at $C000-$FEFF on a real CoCo 3, boots via the CART → FIRQ handshake — see platform/cartridge). No floppy, no NitrOS-9. 32 K (Init0=11) and software bank-switched (CoCoSDC / -cart-type gmc) are documented next-step expansion paths if 16 K turns out insufficient.

WSL access

The host (Windows) Claude session can drive WSL directly with wsl -d Ubuntu -- bash -lc "...". The build script uses this to keep a single source of truth for invocations.
