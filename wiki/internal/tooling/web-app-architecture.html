Internal · tooling · design

web/ retro-dev app architecture internal

Module split + data-layer conventions for the locally-hosted retro-dev web UI. Preserved design for deferred tooling — extends backlog/retro-dev-web-app (which captured the MVP).

Status 2026-07-16: deferred. Preserve the code and documentation, but do not extend this app during normal game work. The active verification loop is gdb-mcp. A real outward MCP server and end-to-end inject_text exposure were not implemented.

v2 design: instruction annotation, register/region/symbol wiki surfaces, persistent configs as web/configs/*.json per-file, snapshot save/load (with patched XRoar). Reverse-step / time-travel deferred entirely.

Two design principles

  1. Static data lives in flat JSON under web/data/. Opcode table, region map, register glossary, symbol→wiki map. Loaded once at backend startup; served verbatim to frontend on demand.
  2. Dynamic resolution lives in the backend. "Decode bytes at PC + tell me what this will do with these regs" is computed Python-side per halt and returned as a structured Instruction + annotation.

Schemas

Opcode JSON (web/data/6809-opcodes.json)

Keyed by primary opcode hex byte. Page-2/3 prefixes ($10, $11) marked with "page2": true / "page3": true; nested under 10xx / 11xx keys.

{
  "86": {
    "mnemonic": "LDA",
    "mode": "immediate",
    "length": 2,
    "cycles": 2,
    "operand_kind": "imm8",
    "cc": {"N": "bit7(result)", "Z": "result==0", "V": "0"},
    "summary": "Load A from immediate byte",
    "effect_template": "A ← #${imm8}",
    "wiki": "internal/platform/6809.html"
  }
}

operand_kind enum: imm8 | imm16 | direct | extended | indexed_postbyte | relative8 | relative16 | inherent | tfr_exg_postbyte | psh_pul_postbyte. The decoder dispatches on this.

length field. For most addressing modes a fixed integer. For indexed_postbyte opcodes the byte count depends on the postbyte, so length is the string "variable". Consumers must accept int | "variable".

cycles field. Integer for fixed-cycle opcodes. For path-dependent opcodes (notably RTI: FIRQ 6 cycles vs IRQ/SWI/NMI 15), the value is an object {"min": int, "max": int, "note": str}. Consumers must accept int | {min, max, note}.

Indexed-postbyte JSON (web/data/6809-indexed-postbyte.json)

~32 postbyte patterns covering ,X, n,X (5/8/16-bit), ,X+, ,X++, ,-X, ,--X, B,X, D,X, indirect […] variants, and PC-relative forms. Each entry: {mask, value, form, extra_bytes, description}.

Snapshot manifest (web/snapshots/<id>.json)

{"config_id": "...", "rom_sha256": "...", "capture_pc": 49340, "captured_at": "2026-05-15T13:42:00Z"}

ROM-hash check at load surfaces a warning on mismatch.

Wiki-content sourcing convention

Hybrid. Short summary field inline in JSON for fast tooltip rendering; wiki field is a deep link. The JSON's summary is the canonical UI surface text. No "always-fetch wiki on hover" pattern.

XRoar-patch dependency handling

Snapshot-load-with-debug needs the SO_REUSEADDR patch (backlog/xroar-load-gdb-patch). No version probe — design is attempt-and-detect:

  • On from_snapshot + gdb_enabled launch, the existing 4 s wait-then-attach path naturally exposes the bind failure. The XRoar log line [gdb] WARNING: bind ... failed is captured and parsed to set a specific error state.
  • from_snapshot + gdb_disabled always works.

Compliance with documented XRoar quirks

  • -trap segfaults after write → snapshot save is instance-terminating. UI surfaces this; endpoint returns success only after the file is on disk.
  • Cart-window writes are no-ops on XRoar 1.10 (memory-map §Important) → annotation engine flags this when the target ea lies in $C000-$FDFF.
  • Single-active-client / vMustReplyEmpty / no-TCP-probe / raw-stdin attach — historical gdb-stub quirks honored by the retired gdb_session.py. Obsolete since the 2026-05-17 Phase 4 pivot to -monitor; the new monitor_session.py speaks JSON-RPC 2.0 and supports multi-client (M6a). See xroar-monitor.

Decisions and rationale

  • 3-layer decode pipeline (opcode_table → decoder → annotation) rather than a single module. Each layer has independent testability; the opcode table evolves independently of decoder logic.
  • Flat snapshot directory + sidecar manifest rather than directory-per-config. Simpler listing and ROM-mismatch validation.
  • Indexed-postbyte table as a separate JSON rather than inlined per opcode. The ~32 postbyte forms are their own little universe.
  • Time-travel deferred — see log 2026-05-15. No record/replay infrastructure in v2.
  • Configs as per-file JSON rather than single instances.json. Git-friendlier.
