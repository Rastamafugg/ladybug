Two independent selectors

LADYBUG_PROFILE selects compile-time game behavior and generated auxiliary data. LADYBUG_CPU selects the processor XRoar emulates at runtime. CPU selection does not change the assembled bytes, ROM layout, loader, MMU mappings, or game profile.

The default command is equivalent to LADYBUG_PROFILE=complete LADYBUG_CPU=6809 scripts/build.sh run. The assembler remains locked to 6809 mode so the default ROM is portable to the project’s MC68B09E target and does not accidentally acquire 6309-only instructions.

Game profiles

highscore-test

An explicit diagnostic profile for the FEAT-003 high-score and name-entry harness. It boots the deterministic high-score path, supports focused ranking/name-entry verification, and holds updated rankings until reset.

development

Development presentation profile with instruction choreography and development-only presentation data. Use it for instruction-flow iteration and targeted presentation checks.

release

Arcade-oriented profile with the release presentation flow and no development or high-score test harness. Use it for the normal release-shaped run.

complete

Combined profile that stages both instruction and demo auxiliaries and exercises the complete presentation route. It is the broadest profile and the most sensitive to copied-module and cartridge-capacity limits.

CPU selection

LADYBUG_CPU accepts 6809 or 6309 and defaults to 6809. The normal and tester launch paths pass the selected value to XRoar as -machine-cpu.

# Reference run: 6809 emulation
LADYBUG_PROFILE=release LADYBUG_CPU=6809 scripts/build.sh run

# 6309 emulator run using the same ROM-producing build
LADYBUG_PROFILE=release LADYBUG_CPU=6309 scripts/build.sh run

# Tester ROM on the 6309 emulator
LADYBUG_CPU=6309 scripts/build.sh tester-run

An invalid value fails before the build starts. The 6309 run is an emulator compatibility check for the existing 6809-compatible ROM, not proof that every physical CoCo 3 contains an HD6309.

Runtime and diagnostic configuration

scripts/build.sh run uses the GMC cartridge, 512 KB RAM, random RAM initialization, RGB video input, and the right CoCo joystick mapping. Append additional XRoar flags through XROAR_EXTRA.

# Fast smoke run
LADYBUG_PROFILE=release LADYBUG_CPU=6309 \
  XROAR_EXTRA="-no-ratelimit -fskip 100" scripts/build.sh run

# GDB launch
LADYBUG_CPU=6309 XROAR_EXTRA="-gdb -gdb-ip 127.0.0.1 -gdb-port 65520" \
  scripts/build.sh run

# Instruction trace with timing
LADYBUG_CPU=6309 XROAR_EXTRA="-trace -trace-timing" \
  scripts/build.sh run

Use the XRoar runbook for GDB-MCP attachment, monitor limitations, and platform-specific launch details. Use the build workflow for WSL and generated-artifact handling.

6309 code policy

The current universal source contains no 6309-only instructions and continues to assemble with lwasm -9. A 6809-compatible ROM is the reference artifact for real hardware and for all current profile comparisons.

Potential 6309 instructions require measured research. TFM is the first candidate for contiguous copy loops; LDQ/STQ may reduce selected 32-bit state movement; and AIM/OIM/EIM/TIM may help isolated masked updates. Current framebuffer and save-under paths are strided and mapping-sensitive, so these instructions are not drop-in replacements.

See RSCH-003 for the proposed benchmark and test-harness work. Separate 6309 ROMs remain deferred until a 6309-only change produces a measured benefit and a separate compatibility policy is approved.
