Verdict and review boundary

The standalone source-audit unit suite has explicit, deterministic fixtures and useful regression purposes. Runtime acceptance includes path-search prerequisites with no guaranteed completion and legacy verifiers that reject valid source text. The existing testing system cannot receive a blanket reliability sign-off from this review.

Reviewed all top-level verifier module purposes and runtime-wait loops statically, all 24 unit methods, and selected enemy, collision, life-entry, phase-timing and historical acceptance evidence. The existing inventory supplies each verifier and unit method's purpose. The review receipt retains exact file hashes, inventory, repeated unit results and the current enemy-verifier failure. Pre-existing Tiled/wiki edits were preserved. No emulator, game build, native hardware session or complete runtime suite was executed. Evidence scripts and repro directories contain additional self-tests; the 24-method count describes the standalone top-level unit suite, not every test in the repository.

Enemy-path prerequisites that should not be routine gates

  1. BUG-087 paired displacement: bug087_ready_adapter.py, lines 1089–1134, advances two builds until a corresponding actor has a compatible legal direction. Matching stage/spawner state does not match all RNG/chooser inputs, and the changed movement schedule itself can change actor routes. Historical receipts record failure to find the same actor within the bounded phase. This establishes an unreliable setup requirement, not a movement defect. Replace path search with the same source-legal, pinned pre-measurement fixture on both sides, including relevant chooser state and coherent framebuffer history; retain a separate natural progression check.
  2. BUG-087 horizontal displacement: the same adapter, lines 1356–1400, searches up to 500 callbacks for a visible actor with 30 pixels of straight route at movement phase zero. Those are valid measurement conditions but are not guaranteed by the starting contract. A single successful search does not establish repeatability. The existing bug087_zero_addend_fixture.py illustrates explicit legal-corridor setup. Use a reviewed corresponding nonzero-rate fixture rather than increasing search bounds.
  3. BUG-087 reversal: historical natural route searches failed to produce the required arrival through (6,4)→(5,4)→(4,4) with another mover. Later bug087_reversal_fixture_setup.py explicitly installs the legal predecessor before measurement and proves gate legality and framebuffer coherence. Reuse this correction; do not restore the historical search as a gate. This review does not claim current integrated runtime acceptance for that fixture. Canonical history and acceptance.
  4. BUG-117 genuine contact and completion-order coverage: natural contact search does not guarantee a second death in 45 seconds; marker-column variation also does not guarantee both music/FRONT completion orders. The retained order proposal explicitly admits that even guarded timer writes are attempts subject to viability. On 2026-10-14 the user already removed the requirement to automate all deaths. Preserve the accepted first-death evidence and manual checklist; the second-contact timeout is no longer an automated acceptance gate. No new death-routing framework is recommended. Any remaining automated order case needs an explicit reachability contract or separately approved manual coverage.

These are runtime integration/acceptance scenarios, not Python unit tests. Source and retained failures prove route-dependent setup and missing guarantees. This review has not performed controlled seed crossover experiments and does not assign every historical timeout solely to RNG; input policy and observer mechanics also caused recorded failures.

Confirmed deadline defects

verify_bug018_runtime.py:capture_draw (lines 296–312) repeats a full run_to_breakpoint(timeout) until the desired stage surface appears, without a shared elapsed deadline or iteration cap. If other draw markers continue arriving, this function need not terminate. verify_bug010_phase_cycles.py (lines 97–125) similarly loops until a handoff with renewed per-stop timeouts.

verify_bug019_enemy_nest_exit.py:capture_natural_release (lines 275–318) caps timer advances and framebuffer samples but renews the full timeout for each one. verify_bug014_initial_enemy_release.py (lines 247–248) has the same pattern. A finite callback count is not a total wall deadline. Nest walkout follows a prescribed route: these findings concern boundedness, not demonstrated random movement failure.

Recommended correction: one monotonic deadline per named phase, remaining time passed through every read/stop operation, an independent finite callback limit, and retained last state on expiration. Unit-test the observer with fake time and repeated irrelevant markers so the missing target must stop. Do not run the entire historical emulator set to diagnose this source-confirmed defect. Prepare a Standard tooling ticket before fixes; no runtime ownership/protocol changes are required.

Authorized historical exceptions should permit their named failures without requiring those failures to persist; unexpected failures still fail. Any migration must preserve the recorded user waivers and the separate missed performance target. This is a consistency finding, not permission to erase failures or widen exceptions.

Tests to retain

All 24 source-audit methods use local controlled fixtures, fixed byte values, temporary directories with cleanup, and explicit expected diagnostics or values. They cover relocation length, operand widths/addresses, overlap and permitted sharing, annotation contracts, required producers/consumers, bounds, source links, and stale/interrupted/misconfigured build receipts. No enemy movement, live clock, network or probabilistic pass predicate is involved. Every method maps to a purpose in the existing inventory. Repeated local passes are supporting evidence, not proof of every platform combination.

verify_bug014_initial_enemy_release.py:160 uses random.Random(0xB014) to generate deterministic dirty-state contamination. This is useful controlled initialization coverage, not a chance-dependent pass condition. A seed alone does not stabilize unrelated guest RNG or input state.

verify_bug002_enemy_gate_collision.py enumerates finite authored gate/cell/direction cases and requires the old model to fail and the fixed model to match its oracle. verify_bug012_forced_collisions.py sets an explicit collision precondition before normal services execute. These are useful examples of discriminating models and controlled rare-path integration. They do not prove natural input routing or full cold lifecycle coverage.

scripts/build.sh:cmd_run intentionally uses random RAM initialization for ordinary gameplay. Do not remove that behavior to simplify tests. Test launches should declare their initial-state policy; an RNG sweep belongs in a separately approved robustness experiment with a fixed seed list and bounded work.

A difficult hardware safety limit or real performance target is not unreasonable merely because it fails. A prerequisite with no demonstrated reachable fixture, a stale lexical predicate, a hidden exception or unbounded observer is an unsuitable automatic gate. Missed product targets remain visible and require their own decision; agent effort should not silently expand to repair unrelated product debt.
